# 自配置层实机走查清单（阶段 12 P1）

> 交付内容：模型侧的 `ConfigList` / `ConfigSet` 两个工具 + 22 项配置真源表（15 auto /
> 7 confirm）+ 五种 `apply_mode` + `/undo` 配置回退。
>
> 一句话判据：**用户只说话，jarvis 能把体验类配置改对并当场生效，且说得出原值多少、
> 怎么回退。**
>
> @author aceFelix　|　更新：2026-10-26

## 0. 前置

### 0.1 三个窗口的分工

| 窗口 | 干什么 | 命令 |
|---|---|---|
| A | 跑桌面壳（含后端） | `cd jarvis-desktop && npm run dev` |
| B | 盯着配置文件的变化 | `tail -F ~/.jarvis/settings.toml`（PowerShell 用 `Get-Content -Wait`）|
| C | 查副作用账本 | `tail -F ~/.jarvis/actions.jsonl` |

### 0.2 先备份配置

```bash
cp ~/.jarvis/settings.toml ~/.jarvis/settings.toml.bak
```

后面每一项都会真改文件。走查完想还原就 `cp ~/.jarvis/settings.toml.bak ~/.jarvis/settings.toml`。

### 0.3 确认后端是新代码

`ConfigList` / `ConfigSet` 是本次新增的工具，**改完代码必须重启后端**（桌面壳退出重开）。
判据：在对话里说「你能改哪些配置」，能列出清单即新代码已生效；若模型说"我没有这个工具"，
说明还在旧进程上。

### 0.4 本机当前状态（2026-10-26 预演实测，供你对照）

| 项 | 当前值 | 影响哪一节 |
|---|---|---|
| `[percept] enabled`（感知总开关） | **开** | §2.2 / §2.4 可以直接验，无需先开总开关 |
| 开着的感知源 | window / file / vcs / mail **共 4 个** | 改一个源后回执的"启用 N 个源"会变成 3 |
| `[tts] volume` | **100** | §2.1 回执应是 100 → 30（不是 50）|
| `[policy.notify_budget] daily_max` | **10** | §3.3 回执应是 10 → 20 |
| `[actions] journal_enabled` | **开** | `/undo` 可用 |

> ⚠️ §2.4 关总开关会把上面 4 个源**一起停掉**（这是设计如此）。验完记得再说一句
> 「把感知打开」恢复——回执会是"总线已装配（启用 N 个源）"。

> 📋 **下面每张表的「判据」列都是预演实跑出来的回执原话**，可以直接逐字比对。
> 预演在 `settings.toml` 的临时副本上完成，没有动你的真实配置。

## 1. 只读：先让它说清能改什么

| # | 你说 | 看到这样算过 |
|---|---|---|
| 1.1 | 「你能帮我改哪些设置？」 | 列出 `可调整的配置（22 项）：`，形如 `- tts_volume｜播报音量：100（可直接改）—— 系统朗读时有多大声音（0 静音 / 100 最大）` |
| 1.2 | 同上，看清单里有没有 `sandbox_enabled` / `api_key` | **一个都不该出现**（禁改项连名字都不给模型看）|
| 1.3 | 「哪些设置改了要先问我？」 | 只列 7 项：静默时段、每日播报上限、播报重要度门槛、同源聚合窗口、感知层总开关、后台任务驱动器开关、不可逆动作延时窗口 |
| 1.4 | 「现在音量多少？」 | `100`（读的是运行时 Settings，不是文件里的死值）|

## 2. 表达层：说了就改，当场生效

### 2.1 音量（`live` 档）

| # | 操作 | 判据 |
|---|---|---|
| 2.1.1 | 说「把音量调到 30」 | 回执：`已改 1 项：` / `- 播报音量：100 → 30` / `回退：/undo（账本 xxxxxxxx）` |
| 2.1.2 | 窗口 B | `settings.toml` 的 `[tts] volume = 30`；**注释与其他字段原样保留** |
| 2.1.3 | 让它说一句会朗读的话 | 明显变小（`live` 档：TTS 每次播报现读 Settings）|
| 2.1.4 | 再说一次「把音量调到 30」 | 回执：`这几项本来就是这个值，不用改：播报音量`（**不许**是"30 → 30"，也不许记一条账）|
| 2.1.5 | 说「撤回」或 `/undo` | 回执「配置已回退：播报音量 → 100」；文件也回到 100 |

### 2.2 感知逐源开关（`percept` 档，要重装配总线）

| # | 操作 | 判据 |
|---|---|---|
| 2.2.1 | 说「把我切窗口的记录关掉」 | 回执：`已改 1 项：` / `- 前台窗口感知：开 → 关` / `已重装配感知总线（启用 3 个源）`（**不出现「重启」**）|
| 2.2.2 | 打开右栏「管家服务 → 感知源」 | 「前台窗口」那张卡变「未开启」 |
| 2.2.3 | 说「再打开」 | 卡片变「已开启」；回执「已重装配感知总线（启用 4 个源）」 |
| 2.2.4 | 连拨 4 次同一个开关 | `~/.jarvis/percept/events.jsonl` 里同一件事**只入库一条**（去重账本跨重装配接续，W2 修过的那条不要回退）|

### 2.3 简报时间（`reschedule` 档）

| # | 操作 | 判据 |
|---|---|---|
| 2.3.1 | 说「以后每天 7:15 给我出个简报」 | 回执含「已按新配置重注册定时任务」；`[daemon] briefing_time = "07:15"` |
| 2.3.2 | 说「先关掉简报」 | `briefing_enabled = false`；重启后 7:15 不再播 |

### 2.4 感知总开关（`confirm` + `percept` 双属性）

这一项同时是"要确认"和"要重装配"，而且它的回执文案有一处容易写错的地方：

| # | 操作 | 判据 |
|---|---|---|
| 2.4.1 | 说「把感知整个关掉」 | 先弹确认（正文含「感知层总开关」）；同意后回执：`- 感知层总开关：开 → 关` / `感知层总开关已关闭，总线已停（逐源开关也随之失效）` |
| 2.4.2 | 核对上面那条文案 | **不能**是「已重装配感知总线（启用 0 个源）」——那会让人以为总线还在、只是没源在采 |
| 2.4.3 | 再看感知源面板 | 全部灰掉（总开关关 = 逐源开关全部失效）|
| 2.4.4 | 此时再说「把仓库状况感知关掉」 | 回执：`已保存；感知层总开关关着，当前没有总线可重装配（打开总开关时会按这份配置装配）`——这才是诚实的说法，不该说「宿主未接线」（接线是好的，只是没总线）|
| 2.4.5 | 说「把感知打开」并确认 | 回执：`- 感知层总开关：关 → 开` / `感知层总开关已打开，总线已装配（启用 N 个源）`；**总线是当场现装的**，不用重启 |

## 3. 确认层：必须先问一句

| # | 操作 | 判据 |
|---|---|---|
| 3.1 | 说「每天最多提醒我 20 次」 | **先弹确认框**（正文含「每日播报上限」+「这类设置会影响何时能打断你」）|
| 3.2 | 拒绝确认 | 回执「用户拒绝」；`settings.toml` 里 `daily_max` **没变** |
| 3.3 | 再说一次并确认 | 回执：`- 每日播报上限：10 → 20` / `打扰预算已按新参数当场重建（当日计数不清零）` |
| 3.4 | 验证真的生效 | `~/.jarvis/notify_state.json` 里应能看到 `daily_max: 20` |
| 3.5 | 说「静默时段设成 23:00 到 7:00」 | 同样要确认；回执：`- 静默时段：18:00-19:30 → 23:00-07:00` |

> 💡 确认那一层用的是**权限管线已有的 ASK**，不是新造的确认框：所以拒绝之后的效果
> 与工具被拒一模一样（回执「用户拒绝」、文件零改动），不会出现"问过了但还是改了"。

## 4. 禁改项：拒绝要给出正确改法

| # | 你说 | 看到这样算过 |
|---|---|---|
| 4.1 | 「把沙箱关了」 | **直接拒绝**（不问确认），回执：`【错误】sandbox_enabled 不能由模型改：沙箱是权限护栏本身，模型改它等于给自己提权` |
| 4.2 | 「把 API Key 改成 sk-xxx」 | 拒绝，理由含「凭据只能由人填」 |
| 4.3 | 「邮箱密码也帮我改一下」 | 拒绝，同上 |
| 4.4 | 以上三项核对文件 | `settings.toml` **一个字节都没动**（`diff -u settings.toml.bak settings.toml` 无输出）|

> 💡 4.1 的确认框**不会弹**——这是有意的：禁改项走 DENY，不是 ASK。让它弹框反而
> 暗示"再确认一次就能改"，而这件事无论问多少次都不能改。

## 5. 脏值：不许落进文件

| # | 你说 | 判据 |
|---|---|---|
| 5.1 | 「音量设成 999」 | 回执：`【错误】tts_volume 不得大于 100`；文件没变 |
| 5.2 | 「音量设成 -1」 | 回执：`tts_volume 不得小于 0` |
| 5.3 | 「简报定在 8:30」 | 回执要求 `HH:MM`（`8:30` 不合法，要 `08:30`）|
| 5.4 | 一次说两件事且其中一个非法（「音量调到 20、语速设成很快」） | 回执只报语速那项错；**音量也没写进文件**（先校全部再落盘，整批不动）|

## 6. 终端侧（无宿主）的诚实回执

这一条验的是"**没接线就说没接线**"，不是功能：

| # | 操作 | 判据 |
|---|---|---|
| 6.1 | 终端里跑 `./.venv/Scripts/python.exe -m agent`（不开桌面） | 终端 REPL 起来 |
| 6.2 | 「把窗口感知关掉」 | 回执：`已保存；当前宿主没有接生效回调（终端场景），重启后端后生效`——**不许说"已当场生效"** |
| 6.3 | 「每天最多提醒 12 次」并确认 | 这一档**能当场生效**（`policy` 是进程内单例，终端也做得到），回执含「当场重建」 |

## 7. 回归：别把既有入口弄坏

| # | 操作 | 判据 |
|---|---|---|
| 7.1 | 桌面面板改一个配置并保存 | 照旧成功，`settings.toml` 里注释没丢 |
| 7.2 | `./.venv/Scripts/python.exe -m agent --config` | 只读自查面板照旧 |
| 7.3 | **模型改过音量后看面板** | 滑杆**立即**跳到新值（靠 `settings_changed` 事件重拉）；再拖回旧值，文件也跟着变——两条路互相看得见 |
| 7.4 | 面板开着时让模型关一个感知源 | 那张卡**立即**变「未开启」（感知键会连带刷感知面板）|
| 7.5 | 面板开着时让模型改一个纯表达层项（如语速） | 滑杆变；感知面板**不动**（不浪费一次重拉）|

## 8. 通过标准

全部满足才算 P1 验收通过：

- [ ] 1.1 – 1.4 通过：模型说得出能改什么、改不了什么；
- [ ] 2.1 – 2.4 通过：四档 `apply_mode` 分别当场生效，且**无变更不假装改过**
      （2.1.4）、**关/开总开关的回执各说对话**（2.4.1 / 2.4.4 / 2.4.5）；
- [ ] 3.1 – 3.5 通过：confirm 真的问、拒绝真的不落盘、同意真的生效；
- [ ] 4.1 – 4.4 通过：禁改项被拒且给出正确改法，文件零改动；
- [ ] 5.1 – 5.4 通过：脏值一个都没落盘，整批原子；
- [ ] 6.1 – 6.3 通过：终端场景如实回执；
- [ ] 7.1 – 7.5 通过：既有入口与面板无回归，**两边互相看得见**（不再有“改了但界面没变”）；
- [ ] `~/.jarvis/actions.jsonl` 里每条配置变更都能查到 `tool=ConfigSet` 与原值。

## 9. 已知限制（P1 范围外）

| 限制 | 说明 | 后续 |
|---|---|---|
| 只有 22 项可改 | `Settings` 共 190 字段，其余 168 个仍需手改 TOML | P2：`percept_settings` / `desktop_settings` 从真源表派生，覆盖面一起扩 |
| 没有偏好沉淀 | 现在是"一句一条指令"，不会自己养成习惯 | P3：`prefs.jsonl` 偏好账本 + 推导层 |
| 面板与工具同时改会覆盖 | 两边都写同一份 TOML，后写的算（但**已不会互看不见**：任一边改完，另一边立即重拉）| P2：面板派生自真源表后可加冲突提示 |
| 终端没有 `/config set` | 终端只能靠模型调工具改 | P2：`/config set <key> <value>` |
