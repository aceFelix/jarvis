## 0. 北极星

**让每个人拥有一位真正懂你、主动打理、随叫随到的电脑管家。**

不是聊天框，不是语音助手，是电影里贾维斯那样——你还没开口，它已经把事情办了。

---

## 1. 定位与边界

### 1.1 JARVIS 是什么

- **个人电脑的原生 AI 管家**：常驻操作系统，能看、能听、能说、能动手
- **多模态交互入口**：文字、语音、视觉，用户选最自然的方式
- **自主代理层**：不只是工具集合，而是能自己规划、执行、验证的 Agent
- **开放生态**：通过 MCP / Plugin / Skill 接入无限工具能力，做"调度一切能力的入口"

### 1.2 JARVIS 不是什么

- ❌ 不是云端 SaaS——数据和控制权在用户手里，跑在本地
- ❌ 不是聊天机器人——核心是"行动"不是"对话"，对话只是交互方式
- ❌ 不是编程工具——不只为写代码服务，为整个数字生活服务
- ❌ 不是万能的——它有边界，知道自己不能做什么，会说不

### 1.3 非目标（明确不做）

- ❌ **不做云端托管版**：JARVIS 是个人的，数据在本地，云端只用来调 LLM
- ❌ **不做手机 App**：JARVIS 扎根桌面操作系统，手机是协同端不是主端
- ❌ **不做企业版 / 多用户**：它是"一个人的管家"，不是 SaaS
- ❌ **不追求全自主**：永远保留人在回路，高风险操作必须确认
- ❌ **不替代专业工具**：不自己做编辑器/浏览器/邮件客户端，而是操控已有的
- ❌ **不自主造引擎**：清理/杀毒/健康监控等一律编排成熟引擎，不自研（见第 6 节）
- ❌ **不支持所有 OS**：先做好 Windows，再考虑 macOS，Linux 不是优先级

## 2. 现状自评（2026.10）

### 2.1 十维度成熟度

> 评级标准：⭐ 基础可用 / ⭐⭐ 功能完整但需打磨 / ⭐⭐⭐ 稳定可靠 / ⭐⭐⭐⭐ 生产可用 / ⭐⭐⭐⭐⭐ 体验优秀

| 维度 | 能力 | 成熟度 | 离管家还差 |
|---|---|---|---|
| **感知** | 截屏识图、摄像头、麦克风、视觉守望（mediapipe 手势/人脸） | ⭐⭐⭐⭐ | 缺疲劳检测；视觉守望未日常化；各感知源之间无统一总线 |
| **行动** | 100+ 内置工具 + MCP 实测注册 159 个，键鼠/Bash/文件/浏览器/GUI 操控 | ⭐⭐⭐⭐ | 缺应用语义理解（仍是盲操键鼠）；缺应用适配层 |
| **表达** | 双语音系统（`/voice` 半双工 + `/talk` 真全双工）+ 富文本终端 + 桌面壳 | ⭐⭐⭐⭐⭐ | —（无重大缺口） |
| **思考** | ReAct 循环 + 多 Agent 协作 + 深度思考统一档位（11 厂商适配） | ⭐⭐⭐⭐ | 基本够用 |
| **记忆** | 画像记忆（LLM 自动提炼 + 每日衰减）+ 长期记忆文件 + 知识图谱画像桥 | ⭐⭐⭐⭐ | 缺结构化可查询事实（时效/出处/冲突消解）、向量化情景记忆 |
| **主动性** | ProactiveHub：每日简报 / 定时提醒 / 截止日期分级追踪 / 待机 TTS 播报 | ⭐⭐⭐ | 提醒闭环已成，缺事件总线与"监控→自动处理"闭环 |
| **个性化** | 画像注入系统提示，越用越懂你（实测能答出作息/偏好/项目） | ⭐⭐⭐ | 缺主动适配工作模式、关系网络 |
| **系统维护** | 无 | ☆ | 完全空白（见第 6 节，这是现阶段主攻方向） |
| **跨端** | 桌面壳 / 手机 PWA / 微信 ClawBot 三端共享同一会话 | ⭐⭐⭐ | 只同步对话，不同步"东西"（剪贴板/文件/通知） |
| **安全权限** | 五层 fail-closed 管线 + 路径守护 + 四模式 + 沙箱 + shadow-git 回滚 + 操作审计 | ⭐⭐⭐⭐ | 高风险确认仍由 instructions 引导模型自判；缺授权租约与打扰预算 |

**一句话**：记忆这层最大短板已补上第一层——它开始认识你了；瓶颈转移到了
**主动处理闭环**（阶段 9–10）和**系统维护**（阶段 8 起逐步展开）：会提醒、会播报，但还不会"自己看着办"。

### 2.2 一句话定位

J.A.R.V.I.S 目前已经是一个**功能完整的 Windows 个人智能体**：100+ 内置工具 + MCP 生态，
双模语音（STT+TTS 循环 + 全双工实时 + WebRTC AEC3 回声消除 + Function Calling），
五层权限，桌面壳常驻。但距离"随叫随到、主动陪伴、包办一切"的贾维斯形态，
还需要**跨应用语义化操控、主动处理闭环、系统维护、可信自主执行、跨端设备协同、离线能力**等关键跃迁。

## 3. 愿景：一个普通工作日的 2027

### 3.1 愿景陈述

你坐到电脑前，按下热键唤醒 JARVIS。它开口说：

> "先生，早上好。昨晚您睡得晚，今天前两小时我先把不急的通知压着了。您关注的两个 GitHub 仓库发了新版，
> 我看了 release notes，有一个值得关注，摘要在我整理的早报里。9 点您有个会，相关文档我已经打开在第二个桌面。
> 另外，磁盘空间剩 15% 了，我清理了 3GB 缓存，没动您的项目文件。"

你不需要问它任何问题。它**记得你**（知道你昨晚熬夜）、**懂你的习惯**（开会前自动备料）、
**主动打理**（清了磁盘、压了通知）、**只在必要时打扰你**。

这是 JARVIS 要去的地方——**从"叫得动的执行者"变成"不用叫也懂你的管家"**。

### 3.2 最终形态速写

> **工作中**——你打开 IDE 写代码。JARVIS 注意到你在一个函数上反复修改了 15 分钟，轻声说：
> "先生，这个函数在第 42 行有个潜在的竞态条件，需要我说说吗？"
> 两小时后："先生，您已经连续工作两小时了，该起来喝杯水。"
>
> **下午**——你打开 Excel。JARVIS 看到你在手动合并两列："先生，需要我用公式帮你整列处理吗？3 秒搞定。"
> 写完周报，它说："第三段有个错别字——'顾'应该是'雇'。另外这周您完成了 12 个任务，比上周多 4 个。"
>
> **晚上**——你在刷网页放松，JARVIS 知道这是放松时间，保持安静。只在弹出低电量时说了句：
> "先生，电脑还剩 10%，我去把最近的工作保存一下吧。"
>
> **第 100 天**——"先生，今天是我们认识的第 100 天。这三个月我们一起写了 47,000 行代码、
> 处理了 312 个任务。您最爱深夜工作，最喜欢的模型是 qwen3.7-plus。您夫人李梅的生日在下周，
> 需要我提醒您准备礼物吗？感谢您的信任，先生。"

### 3.3 成功标准

不是 KPI，是"什么时候我觉得它真的成了我的管家"：

1. **一周没主动开过 JARVIS 窗口**——因为它该做的都做了，我只在被服务时感知到它
2. **换一台电脑装上 JARVIS，导入记忆，它立刻"认识"我**——记忆可迁移
3. **它能说"先生，这件事上次您是这么处理的，要照旧吗"**——有连续性
4. **朋友看到我用电脑的方式，问"你这管家怎么弄的"**——体感到差异

## 4. 能力模型

### 4.1 四层能力栈（自上而下）+ 两条贯穿轴

```
┌──────────────────────────────────────────────────────────────┐
│ ④ 人格层 │ 像人一样聊天、陪伴、有性格、会成长（长期关系演化） │
├──────────────────────────────────────────────────────────────┤
│ ③ 主动层 │ 随时观察、发现不对就提醒/处理、懂得时机           │
├──────────────────────────────────────────────────────────────┤
│ ② 操控层 │ 能操作电脑上的任何程序（语义优先，坐标为辅）       │
├──────────────────────────────────────────────────────────────┤
│ ① 感知层 │ 知道你在干什么、屏幕上有什么、系统发生了什么       │
└──────────────────────────────────────────────────────────────┘
      ▲ 贯穿轴 · 记忆（越用越懂你）      ▲ 边界轴 · 安全（值得托付）
```

**贯穿轴 · 记忆**：层的厚度由记忆决定。没有记忆，"主动"只是闹钟，"人格"只是静态提示词。
**边界轴 · 安全**：能动你电脑的 AI，必须是你最信任的——权限、审计、可撤销，缺一不可。

### 4.2 各层目标蓝图

**① 感知层——看到并理解屏幕上的一切**

现状能做的：全屏/区域截图、多模态描述、窗口列表、摄像头拍照、mediapipe 手势/人脸。
缺的：实时屏幕理解、UI 元素识别、OCR 常驻管道、应用状态感知、屏幕变化检测、系统通知拦截、音频环境感知。

技术方向（低频 + 高频双通道，核心是**注意力聚焦**——只在关键区域保持高频）：

```
低频通道（每 2~5 秒）：全屏截图 → VLM → "用户在写代码，IDE=VSCode，文件=main.py"
高频通道（每 0.5 秒）：屏幕变化检测 → 变化区域 OCR → 提取新出现的文字 → 匹配事件规则
```

**② 操控层——操作任何程序，不只是浏览器**

缺的：Accessibility 语义操控（UIA）、应用专精（Office / 文件管理器 / 终端）、多应用协作编排、
自适应等待与重试、快捷键知识库、剪贴板智能管理。

**三层操控体系（精度优先，逐级降级）**：

```
Layer 1 ▸ 语义操控（首选）  UIA/Accessibility: 找到 Button[name="确定"] → Invoke()   精度 100%
Layer 2 ▸ 坐标操控（降级）  截图 → VLM 定位坐标 → 鼠标点击                            精度 ~90%
Layer 3 ▸ 键盘操控（精确）  快捷键序列 Ctrl+S / Alt+Tab / Tab Tab Enter               100% 可靠
```

> Office 不走 GUI 模拟，直接操作文件格式：Excel `openpyxl`、Word `python-docx`、PPT `python-pptx`、
> PDF `pdfplumber`、Outlook `win32com`。

**③ 主动层——不叫就不动，不配叫助手**

```
输入侧：环境状态快照（屏幕变化 / 活跃窗口 / 键鼠活跃度 / 系统通知 / 音频环境 / 文件变更）
大脑侧：干预判断引擎（轻量规则 + 小模型，持续评估"用户有困难吗/有重要信息吗/现在是说话的时机吗"）
输出侧：分层递进干预  L1 托盘变色 → L2 Toast → L3 语音插入 → L4 强干预弹窗
```

干预规则示例：同一文件反复修改 >15min → "需要帮忙看看吗"；错误弹窗 → 截图分析；
危险终端命令 → 确认；连续工作 >2h → 提醒休息；低电量 <15% → 语音提醒；
检测到通话/全屏 → 自动静默。

**④ 人格层——像人，不像客服**

缺的：自动记忆提取、情绪感知（文本/语音/行为三通道）、风格适应、长期关系演化、
跨会话连续感、主动分享、犯错与道歉、有立场。

```
用户状态      →  助手模式
─────────────────────────────
专注工作      →  静默（除非紧急事件）
遇到困难      →  简洁建议，不多废话
闲聊时间      →  幽默放松，可主动延伸话题
赶 deadline   →  只回答，不闲聊，说完闭嘴
烦躁/焦虑     →  安抚语气，简短确认，不追问
```

### 4.3 六维度长期蓝图（横切视角）

| 维度 | 一句话 | 技术方向 |
|---|---|---|
| **记忆** | 管家越用越懂你 | 向量化 episodic store + 结构化 semantic store + 跨会话持久化 |
| **主动** | 不用叫也打理 | daemon 从"定时器"升级为"事件总线 + 规则引擎 + LLM 决策器" |
| **理解** | 从盲操到懂应用 | `tools/app_integrations/` 应用适配层，优先微信 / Outlook / Excel / 浏览器 |
| **维护** | 管家会打扫卫生 | 一组维护工具 + scheduler 定期巡检（见第 6 节） |
| **跨端** | 管家无处不在 | bridge 升级为"设备协同层"（剪贴板 / 文件 / 通知 / 会话漫游） |
| **安全** | 管家值得托付 | 权限分级 + 操作审计 + 敏感数据保护 + 行为边界 |

## 5. 核心设计原则

1. **本地优先，云端可选**——数据和控制在用户手里。LLM 调用走云，但记忆、文件、操作日志全在本地。
2. **对话是手段，行动是目的**——不追求"聊得自然"，追求"办得利落"。能静默做完的，不用问。
3. **主动但不越界**——默认"建议而非执行"高风险操作。用得越久信任等级越高，但永远保留"先问我"的红线。
4. **越用越懂，而非每次重头开始**——第 1 天和第 100 天的 JARVIS 应该是两个不同的存在。
5. **开放生态，不造孤岛**——通过 MCP / Plugin / Skill 接入一切；JARVIS 是调度入口，不是能力的全部。
6. **诚实地有限**——知道自己不能做什么。宁可说"这个我做不到"，也不瞎编。承认局限是信任的基础。
7. **不造引擎，只做编排**——清理、杀毒、健康监控、文件检索等，一律编排成熟引擎；自研只花在"编排与判断"上。

## 6. 下一程技术选型：电脑管家八件事

> 现阶段主攻方向。**共同原则：不自研引擎，只做编排层 + 判断层**——把成熟工具"对号入座"。
> 每件事标注成熟度：☆ 空白 / ⭐ 部分 / ⭐⭐ 可用 / ⭐⭐⭐ 完善。

### 6.1 监控电脑健康

| 项 | 内容 |
|---|---|
| 数据源 | WMI / ETW / Performance Counters（CPU/内存/磁盘/网络/温度/电池/启动项） |
| 磁盘健康 | SMART 数据，参考 `smartmontools`、`LibreHardwareMonitor`（开源、无需自研传感器层） |
| 现状 | 已有 `SystemMonitor` 阈值告警 + 600s 冷却 + 磁盘趋势预测 + 异常进程检测 |
| 缺口 | 电池/温度/启动项/网络连通性巡检；"体检报告"式汇总 |
| 落点 | `tools/system/maintenance.py` 一组工具 + scheduler 定期执行 |

### 6.2 清理垃圾

| 项 | 内容 |
|---|---|
| 成熟方案 | 规则表 + 预览 + 隔离区 + 白名单；参考 **BleachBit 的 CleanerML 规则格式**（声明式、可扩展、社区可维护） |
| 安全约束 | 只清白名单目录；删除先进隔离区（可恢复）；预览确认后执行；绝不碰项目文件 |
| 现状 | ☆ 空白（已有回收站纳入的文件工具，但无清理规则体系） |

### 6.3 整理文件

| 项 | 内容 |
|---|---|
| 检索 | **Everything HTTP API**（Windows 秒级全盘检索），比自研索引快一个量级 |
| 去重 | 参考 `dupeGuru` 的思路（内容指纹 + 模糊匹配），不自研算法 |
| 整理 | 按规则归档（类型/日期/项目）+ 保持可撤销（走副作用账本） |
| 现状 | ⭐ 已有原生文件工具（读写/移动/回收站）；缺规则化整理闭环 |
| 落点 | 落地文档：[plans/fileops-desktop-upgrade.md](plans/fileops-desktop-upgrade.md) |

### 6.4 杀毒

| 项 | 内容 |
|---|---|
| 首选 | Windows Defender：`MpCmdRun.exe` + `Get-MpThreatDetection`（系统自带、零依赖、免授权） |
| 兜底 | ClamAV（开源，可命令行调用）作为第二意见 |

### 9.2 阶段 8–11：管家形态（W1–W4，当前主线）

> 详细执行计划见 **[PLAN-butler-autonomy-upgrade.md](roadmap/PLAN-butler-autonomy-upgrade.md)**。此处只给纲领与依赖顺序。

**问题陈述**：横向能力已经不缺，但"真正的管家"体验卡在三处**接口**上——

| # | 现象 | 根因 |
|---|---|---|
| 1 | 「主动」实际上只是闹钟 | 感知源单一（`Scheduler` 只吃时钟、`VisionWatcher` 只吃摄像头），**没有工作现场的事件流** |
| 2 | 一扩感知就从"不够主动"掉进"太吵" | **缺"该不该打扰我"的决策层**（无重要度评分、聚合、静默时段、渠道选择） |
| 3 | 不敢让它无人值守 | 任务是**一次性"到点说一句话"**，活不过一次对话；行动只有文件可回滚，邮件/消息/系统设置无副作用账本 |

**三支柱与依赖顺序**：

```
   感知层 W2（事件）            判断层 W1（闸门）             兑现层 W3（行动）
 ┌─────────────────┐        ┌──────────────────┐        ┌──────────────────┐
 │ 时钟（已有）      │        │ 策略引擎          │        │ 任务脊柱          │
 │ 摄像头（已有）    │──事件──▶│ 授权租约          │──放行──▶│ （目标/步骤/条件） │
 │ 前台窗口  新增    │        │ 打扰预算/重要度    │        │ 副作用账本 + 撤销  │
 │ 文件·仓库  新增   │        │ 无人值守模式       │        │ /undo 与事后简报   │
 │ 邮件·日历  新增   │        └──────────────────┘        └──────────────────┘
 └─────────────────┘                  ▲                            ▲
            贯穿：结构化长期记忆（W4.2）· 操作审计（已有）· 口手分离（W4.1）
```

**依赖顺序 W1 → W2 → W3 → W4**（对应阶段 8 / 9 / 10 / 11）。
理由：先有闸门再扩感知（否则主动性 = 骚扰）；先有持久任务再谈无人值守；W4 是体验补齐，属收益而非地基。

| 阶段 | 内容 | 关键落点 | 验收要点 |
|---|---|---|---|
| **阶段 8（W1）** 判断层 | 确定性策略引擎 + 授权租约 + 打扰预算 + 无人值守 | 新增 `agent/core/policy/{engine,lease,budget}.py`；`~/.jarvis/policy.yaml`；`ProactiveEngine.on_notify` 前插预算过滤 | 同一操作在"有租约/无租约/away"下三态确定且可解释；静默时段只入库；权限零回归 |
| **阶段 9（W2）** 感知层 | 统一事件总线（前台窗口 / 文件 / 仓库 / 邮件 / 日历 / 系统） | 新增 `agent/core/percept/`（bus + 一源一文件）；`Scheduler` 降级为事件源之一；**默认全关 + 逐源开关** | 四类事件各产出**恰好一条**聚合提醒；常驻 CPU 增量 < 1%；单源故障隔离 |
| **阶段 10（W3）** 兑现层 | 持久任务脊柱（条件等待/断点续跑）+ 可撤销行动账本 | 新增 `agent/core/tasks/spine.py`（`~/.jarvis/tasks/`）、`agent/core/actions/journal.py`（`~/.jarvis/actions.jsonl`）、`/undo` `/tasks` | 重启续跑；条件等待不烧轮询；副作用可一键回滚；不可逆动作有延时窗口 |
| **阶段 11（W4）** 体验补齐 | 口手分离（语音真能干活）+ 结构化长期记忆 | `realtime_tools.select_tools_for_turn()`（tool-RAG，≤12 个）；"要动手"意图转后台 Agent 异步回报；新增 `agent/core/memory/facts.py` | 按轮挂 ≤12 工具建响应 < 1s；语音说"帮我查一下 XX"能异步拿结果；记忆带时效与出处 |

**W4 · 口手分离的实测依据**（官方 endpoint，文本触发轮）：

| 工具 schema 数 | `response.created` 延迟 | 结果 |
|---|---|---|
| 2 | 0.67s | completed |
| 38 | 0.89s | completed |
| 120 | 1.65s | completed |
| 294 | 3.45s | completed |
| 450 | 4.89s | completed |

服务端始终会建响应，但延迟随工具数**线性增长**（≈12ms/个）。两级的正解：
**L1 按轮 tool-RAG（先做，低成本）**，**L2 手口分离（形态正解：实时链路只负责听/答/判意图，执行交给后台 Agent 异步回报）**。

> 约束：在 W4 完成并经实机验证前，`realtime_tools_mode` 默认值保持 `builtin`，不再改动。

**本期明确不做**：IoT/智能家居接入（除非定位扩到"居家管家"）、云端全时环境感知、
引入第三方调度/工作流引擎（既有 `Scheduler` + 自研 spine 足够）。

| 挑战 | 说明 | 解决思路 |
|---|---|---|
| **低功耗常驻** | 7×24 运行不能占大量 CPU/内存 | 分层唤醒：轻量监听 + 需要时再启动完整 Agent；本地规则先判不每次调 LLM |
| **隐私保护** | 摄像头/麦克风/屏幕常驻引发顾虑 | 本地优先、状态可见（"正在观察：前台窗口"）、逐源开关、敏感操作确认、采集范围可导出查看 |
| **跨应用自动化可靠性** | GUI 自动化易受界面变化影响 | 语义（UIA）优先 + 视觉兜底 + 可学习工作流回放 |
| **主动与打扰的平衡** | 过于主动会打扰用户 | 打扰预算 + 重要度评分 + 静默时段 + 聚合 + 用户可配主动等级（阶段 8） |
| **多设备协同** | 设备间状态同步与任务接力 | 本地优先的端到端加密同步协议（Tailscale 类私有网络打底） |
| **离线能力** | 没网时仍需基础功能 | 本地模型 + 本地语音（sherpa-onnx/FunASR）+ 本地工具执行 |
| **不可逆动作的风险** | 发邮件/提交代码/系统设置无法撤销 | 强制 dry_run + 二次确认 + 延时发送窗口 + 副作用账本（阶段 10） |
| **可信自主执行** | 敢放手才叫管家 | = 策略引擎 + 授权租约（阶段 8）+ 可撤销账本（阶段 10），二者齐备才成立 |

---

## 11. 里程碑验收总表

### 阶段 8–11（主线）

- [ ] **W1**：策略四态可解释 + 租约过期即回 `ask` + 静默时段聚合 + 权限零回归
- [ ] **W2**：四类事件各产出恰好一条聚合提醒 + 常驻 CPU < 1% + 单源故障隔离
- [ ] **W3**：重启续跑 + 条件等待不烧轮询 + 副作用可回滚 + 不可逆有延时窗口
- [ ] **W4**：按轮挂 ≤12 工具时建响应 < 1s + 语音说"帮我查一下 XX"能异步拿到结果 + 记忆带时效与出处

### 电脑管家八件事（第 6 节）

- [ ] 健康体检报告（CPU/内存/磁盘/温度/电池/启动项 + 趋势）可一条命令生成
- [ ] 清理有规则表 + 预览 + 隔离区，且绝不碰项目文件
- [ ] 文件整理可一键回滚（走 W3 账本）
- [ ] 杀毒走 Defender 编排并可解读结果
- [ ] Office 内容级工具层可用（Excel/Word/PPT/Outlook）
- [ ] 线上事务写操作默认 dry_run，可延时撤回

### 长期成功标准（第 3.3 节）

- [ ] 一周不主动开窗口也感知不到缺失
- [ ] 换机导入记忆即"认识我"
- [ ] 能说"上次您是这么处理的，要照旧吗"
