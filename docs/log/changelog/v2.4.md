## [2.4.0] — 2026-11-06

这一版给系统装上了**自我认知**。起因是 2026-11-03 那次贪吃蛇：它汇报“我已经用浏览器打开
验证过了”，而本机根本没装 playwright 浏览器内核——代码层把“工具有没有”等价于“包能不能
import”，所以它只能从“工具在列表里”推断“我做得到”。本轮把“能力”变成代码里一等的、
带实测证据的事实，并给它一个受约束的动手权限。事故复盘见
[snake-visual-claim-fix.md](../../fixlogs/snake-visual-claim-fix.md)，设计取舍见
[20-能力自检与自我修复](../../architecture/20-能力自检与自我修复.md)。

### 新增（桌面多 Agent 协作，2026-11）

- **serve 路径补齐协作工具**：`Agent` / `TeamCreate` / `TeamDelete` / `TeamStatus` /
  `SendMessage` / `TaskCreate` / `TaskGet` / `TaskList` / `TaskUpdate` / `TaskStop` 在
  `_ensure_session`（provider 建好后）注册，桌面壳不再只有终端能用多 Agent。
- **活动台账** `agent/collaboration/activity.py`：进程内线程安全台账，记录每个子代理/
  队友的 `status / task / current_tool / activity / output / iterations / tool_calls`；
  变更节流 300ms、起止/失败立即通知。
- **桌面协议**：新增 `agents.exec`（`status` / `stop` / `message`）与 `agents_state`
  事件；同步子代理可在面板单独停止（取消自身 asyncio 任务），队友走 shutdown 协议。
- **主聊天隔离**：`AgentActivityUI` 把子代理的流式文本/工具事件收进台账，只有
  `ask_user` / `warn` / `error` 仍转发宿主。
- **自动派发**：系统提示词新增「多代理协作」段（仅注册了 Agent 工具时注入），
  说明何时拆分、四种角色、并行与后台队友的用法。

### 新增（能力自检层 `agent/capabilities/`）

- **13 项能力的声明式能力表 + 静态探测**：按包 / 二进制 / 资产 / 凭据 / 平台五类前置条件
  分别探测，版本要求一律问库自己（`importlib.metadata.version()`）而不写死，避免版本漂移
  报出不存在的问题。整体状态六值，其中 **`probe_failed` ≠ `missing`**：探针自己出错一律
  不拦调用、不给安装命令、不进修复白名单（“不知道缺什么就动手”那不叫修复）。
- **冒烟档**：子进程里真起一次 headless 浏览器、真截一帧屏（90s / 20s 硬超时），结果写回
  同一份缓存——这样“目录在、但内核真的起不来”也能反过来拦住工具。
- **两个时间尺**：TTL 300s 拢住热路径成本（静态档实测 <50ms，但一个任务能调上百次工具）；
  不可逆动作到点执行与修复后复测走 `force=True` 当场重探。
- **`/health caps`**：静态档 / `--deep` / `<能力名>` 详情 / `--json` / `--markdown` /
  `--repair` / `--history` 七个入口；入口放在 `/health` 下而不另开一个 `/doctor`，
  沿用仓库已有判断：两套并存只会让人搞不清该信哪个。注意 `jarvis --doctor` **尚未**
  改成读同一份结论（它自带 `_PKG_CHECKS` 表），两者现在是互补但不同源，已记为后续项。

### 新增（缺件在调用前拦住）

- **编排器能力门**：位置刻意在“权限 → W1 → 钩子”全部定案**之后**、不可逆延时窗口与
  自愈层**之前**——缺件动作不挂“待发”、不进重试、零副作用。回执里硬写「本次调用没有
  执行，禁止当成已验证、已看到、已跑通写进回复」。
- **两条逃逸路径补门**：预约动作到点真执行那条（`force=True` 强制重探，防止拿 5 分钟前的
  缓存结论放行一个外发动作）、实时语音自己拼调度那条。
- **`ToolSearch` 标注能力缺失**（不隐藏缺件项，让用户看见为什么它现在跑不了）。
- **提示词新增两段条件注入**，均排在 `# 可用工具` 之前（先看见“哪些跑不通”，再看见工具备忘）：
  `# 你今天的实际能力`与`# 当前模型的视觉输入`。**两者在一切正常时返回空串，
  一个字节都不加**，不给前缀缓存增加无意义变化。

### 新增（自我修复 `/repair`）

- **四个白名单动作**：`fetch-browser`（硬顶 400MB）与 `pip-extras`（300MB）可代执行；
  `fetch-model` 因无可核对 URL 清单、`config-fix` 因必须走已有权限判定的 `ConfigSet`，
  两个只给命令不代办。不在表里的一律只输出建议命令。
- **六道门按序判**：总闸 → 单动作开关 → 是否可代执行 → 体积硬上限 → `/away` 升回待批 →
  超询问线先问（默认 200MB，**就算开了 yolo 也问**）；预计超 30s 转后台任务而非前台阻塞。
- **修完必须复测才算成**（`deep_check(cap, force=True)`），一次失败只试一条路；结果写进
  **已有的副作用账本**（`Repair:` 条目），不另建一份流水；首次自动修复强制播报（文字 + 语音）。
- **`[repair]` 五个配置字段**（`enabled` / `ask_threshold_mb` / `disabled_actions` /
  `background_over_s` / `announce_voice`）四处联动（settings / domains / example.toml /
  真源表），`/repair off` 一句话急停。

### 新增（模型能力面）

- **`model_type` 从两值改三值**：`text` / `multimodal` / **`unknown`**，默认 `unknown`，
  判据收敛到单一裁决点 `agent/llm/model_capability.py`（此前以各种写法散在
  **14 个文件、20 处**）。口径沿用仓库在 `PLAN-self-config.md` P4 记录 ② 已定过的决定：
  宁可少给一项能力，不猜多模态——误判“有”会让模型声称看见没收到的图，误判“无”只是
  少一项能力且当场可见。
- **内置发货清单是刻意例外**（`BUILTIN_MODEL_TYPE = multimodal`）：qwen3.x 走 DashScope
  多模态端点，改用 `Generation.call()` 会 `400 url error`。
- **四家 provider 统一“省略必须留文字”**；`anthropic` 补齐 `model_type` 参数与
  `set_model_type()`（此前没有，切模型时被 `hasattr` 探测静默跳过）。
- **图片类工具回执改为「图片附上: 是…附上不等于看见」**，三处工具共用一个出处。
- **热切换**：仅当图片通路**翻转**时重拼 system prompt，不翻转不动，避免白丢前缀缓存。

### 变更（收敛与去重）

- **`cli_anything/market.py` 拆分**：harness 启用/禁用状态（82 行）与 id 归一化纯函数
  分别移到 `harness_state.py` / `ids.py`，market.py 905 → 828 行。起因是本轮给它补
  `TYPE_CHECKING` 时越过了仓库 900 行上限，被 `test_engine_split_guards` 拦下——门禁
  生效了。对外名字不变（market 顶部重导出那四个入口，调用方与现有打桩用例都不用改）。
- **`compose_system_prompt()` 成为拼提示词的唯一入口**：此前“build 再拼一段用户自定义内容”
  这两步被抄了六遍，漏拼第二处的调用点在切模型/换项目后会把用户自己加的段弄丢；
  现全部调用点（REPL 启动、`/think`、`/memory`、桌面会话装配、切模型、切项目）已收敛。
- **图片编码从三份逐字相同的副本收拢为 `core/images.py::encode_pil_image()`**：顺带消除
  `core/images.py` 为复用其中一份而反向 import `ScreenShotTool` 的分层违规（下层依赖上层），
  以及 pyautogui 缺失时被那句 `except ImportError` 误报成「缺少 Pillow」。新增结构约束测
  防副本复活。

### 修复（本轮实测撞出的既存缺陷）

- **纯图片消息在纯文本模型下整条消失**（openai 兼容支）：旧实现只在“有文字块可挂”时才写
  省略说明，用户单发一张图时该 turn 直接不发了，而界面与回执都显示已发送。已改为保留
  占位说明，并同步改掉钉住旧行为的那条用例（理由写进测试注释）。
- **REPL 侧提示词在 `ToolSearch` 注册之前就拼完了**：桌面端已踩过并修过同一个坑
  （`engine_session.py` 同段注释），REPL 没同步——模型收到“用 ToolSearch 加载工具”的
  指引却找不到该工具。已把拼提示词移到钥匙工具注册之后。
- **测试隔离污染源**：`build_default_registry()` 是 `@lru_cache` 的共享实例，
  `tests/llm/test_tool_registry.py` 往里注册 72 个 harness 会污染同进程后续用例
  （症状是“单独跑绿、混跑红”，实测 deferred 25 → 97）。改用独立实例，并在能力契约测
  里显式豁免动态前缀。
- **`[repair]` 漏登记一个字段**：五个设置字段只进了真源表四个（`background_over_s`），
  后果不是“改不了”而是会被 `describe_missing()` 报成「没有这个配置项」。已补登记，
  并新增 `[repair]` 段的反向对账测（旧测只查 spec → 真源方向，查不出漏登记）。
- **能力契约测自己犯了自己要治的错**（Linux CI 独红、本地永绿）：
  `test_declared_tool_names_actually_exist` 拿 `build_default_registry()` 的**运行时**
  注册表当“工具是否存在”的唯一证据，而摄像头 / 浏览器那两组是“可选依赖没装就整组不
  注册”——CI 上没装 opencv 就报「表里登记了不存在的工具：CameraShot」，而那个工具真的
  存在。已改为 `ast` 静态扫源码取工具名全集（与装了什么包、开了哪些配置、什么平台无
  关），加一条防自身失效断言，并删掉要逐台机器手改的 `CONDITIONAL_TOOLS` 豁免表（表里
  已有一条 `RealtimeTalk` 根本不在能力表中）。只改测不改表，反方向对账刻意不静态化
  的理由与实测数字见 [capability-tool-name-contract-fix.md](../../fixlogs/capability-tool-name-contract-fix.md)。

- **REPL 里打 `/doctor` 直接 NameError 把会话打崩**：`core_commands._doctor()` 用了
  `Path`，而这个模块从来没导入过它——`git log -S` 追到是 `4b77351`（main 拆分那次）
  留下的，潜伏了两个月。拿 `ruff check --select F821` 扫全仓又扫出 17 处未定义名字，
  其中 `lsp_tool` 的 `uri_to_path` 是真崩的第二起：分发函数里写了函数内局部导入，
  而真正用它的四个格式化函数在模块作用域里找不到，goToDefinition / findReferences /
  goToImplementation / prepareCallHierarchy 四条操作 100% 报错（LSP 工具默认不注册，
  所以从来没人撞到）。7 处真崩补模块级导入、10 处字符串注解补 `TYPE_CHECKING`；
  `ci.yml` / `publish.yml` 各加一步 `ruff check --select F821 agent/`（只选这一条：
  全量 lint 有上百条既存噪音，门禁要能长期绿着才有人看）。复盘见
  [undefined-name-imports-fix.md](../../fixlogs/undefined-name-imports-fix.md)。
