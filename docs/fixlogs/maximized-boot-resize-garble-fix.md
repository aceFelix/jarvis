# 修复：最大化启动后缩窗画面错乱（渲染封顶 + 定格帧分流）

- **日期**：2026-08-29（第二轮：按用户实测反馈重构方案）/ 2026-08-30（第三轮：反应炉定格保留）
- **作者**：aceFelix
- **影响范围**：`agent/ui/cli.py`、`agent/ui/boot_animation.py`、
  `tests/ui/test_capped_console.py`、`tests/ui/test_boot_banner.py`

## 现象

1. 终端最大化启动，启动完成后缩回默认窗口：启动横幅、欢迎面板折行重排、画面错乱。
2. 第一轮仅做渲染宽度封顶后用户实测反馈：最大化时内容偏左不居中；
   缩到默认窗口后静态反应炉画布依然很大；再放大后画面残缺、无法滚动。
3. 用户准确指出本质：**静态画面一旦输出就无法随窗口动态缩放**。

## 根因（终端硬限制）

terminal 已输出到 scrollback 的内容无法重绘。两类受害者：

1. **超宽行**：最大化时按 200+ 列渲染，缩窗后被折行重排 → 错乱。
2. **超高块**：原实现 Live 退出后把高大的反应炉盲文画布（~26 行）
   作为静态画面重印进 scrollback —— 缩窗/放大 reflow 后断裂、残缺、
   把后续内容顶出可视区（"画面只剩一半、滚不上去"）。
动画阶段本身是 Rich Live transient（退出即清除），不是问题源。

## 修复（两层）

### ① REPL 渲染宽度封顶（第一轮，保留）
`agent/ui/cli.py` `_CappedConsole(Console)`：动态覆写 `size` =
`min(实际终端宽, 120)`——所有面板/Markdown 输出恒 ≤120 列，缩窗不折行。

### ② 紧凑静态横幅（第二轮）
`agent/ui/boot_animation.py`：
- Live 动画阶段改用无封顶的独立 Console（transient，不污染 scrollback）：
  最大化时动画真实尺寸居中、随窗口缩放重建画布。
- Live 退出后**不再重印反应炉画布**，改输出 `_compact_banner`：
  固定 60 列宽、≤9 行的标题+会话信息面板。
- `_banner_with_safe_center` 安全居中：缩进 =
  `min(居中偏移, 20, 渲染宽-面板宽)`——最大化下轻微偏左（可接受），
  换取缩窗永不折行；窄窗口（80 列）也不超宽。
- 居中无法完美是终端本质限制：居中靠空格垫宽，垫宽超过未来缩窗后的宽度
  就会折行——"完美居中"与"缩窗不乱"二选一，选后者。
- **遗留问题**：反应炉在启动完成后完全消失，用户明确要求保留。

### ③ 定格帧分流（第三轮，核心）
`agent/ui/boot_animation.py`：Live 退出后按"定格瞬间的真实窗口宽度"
（`shutil.get_terminal_size()` 直读，不受封顶 Console 影响）分流：
- **小窗（≤120 列）→ `_static_reactor_frame`**：满功率静态反应炉定格帧
  （盲文画布上限 128px = 64 列，缩窗不折行）+ 标题 + 紧凑信息面板；
  之后放大窗口，画面尺寸位置固定不变（终端特性，可接受）。
- **大窗/最大化（>120 列）→ `_ascii_art_banner`**：J.A.R.V.I.S 方块艺术字
  （≤53 列，字形逐行等宽校验）+ 紧凑信息面板；之后缩回默认小窗不折行。
- 分流阈值 `_LARGE_TERMINAL_WIDTH = 120` 与 REPL 封顶宽度对齐。
- 异常/中断路径仍回退紧凑横幅，保证横幅必有输出。

按用户实测反馈又补四项打磨：
- **标题排版**：定格帧中 `J.A.R.V.I.S` / 副标题 / `系统就绪` 各自单独一行；
  信息面板内删除重复的标题行，只留会话信息。
- **面板宽度 60→62 列**：容纳 workdir 路径行与 `/help` 命令提示行（约 57 列）
  单行展示；workdir 超长时由 Panel 自动换行（用户预期）。
- **`/help` 行 `no_wrap`**：命令提示必须单行，绝不拆行。
- **静态帧高度封顶**（后被推翻，见下）：曾新增 `_calc_static_geo`（画布封顶 56px）
  修"小窗定格→切全屏→切回后画面显示不全"；但用户随后指出**定格帧与动画尺寸不一致**，
  明确要求"动画多大，定格就多大"。最终方案：**定格帧直接继承动画最后一帧的几何参数**
  （`_calc_geo` 计算、含播放中的缩放跟踪），删除 56px 封顶；视口高度风险由
  `_CANVAS_RATIO=0.72`（底部预留 28%）与 `_calc_geo` 的 11 行预留消化。

用户再次实测发现 `/help` 行仍被拆行（"退出"掉到下一行），定位两个真根因并重构：
- **根因 1：Rich `Panel(width=N)` 是外框总宽**，扣除边框 2 列 + padding 2 列后内容区只有
  N-4 列；旧版 `/help` 行实测 60 cells（旧双空格分隔符），内容区 58 列装不下 → 拆行。
- **根因 2：`no_wrap` 不是防拆行而是改截断**：超长时直接丢弃尾部字符（"退出"丢失），
  比拆行更糟，已移除。
- **重构：面板宽度按内容动态计算**（`_banner_content_width` / `_banner_total_width`）：
  用 `cell_len` 实测 `/help` 行与 provider/model 行，取最长者 + 4 列余量（吸收
  CJK 歧义宽字符如 `·` 的终端渲染偏差）作为内容宽；`_HELP_HINT` 分隔符缩减为
  单空格（54 cells）。workdir 仍允许面板内自动换行。
- 实测渲染验证：`/help 命令 · /voice 语音 · /talk 实时聊天 · /exit 退出` 完整单行。

### ④ 最大化定格帧按 80 列预居中（第四轮）

用户实测：最大窗口启动完成后切回默认小窗，排版不在正中间。根因：
大窗定格帧按封顶 120 列居中（艺术字前导空格 40、总宽 84）——超出默认小窗宽，
缩回后前导空格被终端 reflow 吞掉/折行，排版偏左。

修复（新增常量 `_RESTORE_TARGET_WIDTH = 80`，终端业界默认窗口宽度）：
- 大窗定格帧改为**按 80 列预居中**：最大化状态下轻微偏左（同既有取舍），
  缩回默认小窗后恰好正中。艺术字块、副标题、信息面板宽度各异，
  各自按 80 列基准独立计算缩进（共用同一缩进会让窄的副标题偏左）。
- **剔除艺术字全空行**：字形顶/底的纯空格行拼接后仍带前导缩进，
  缩窗 reflow 时会被折成多行打散排版；`_ascii_art_lines` 拼接后过滤全空行。
- 新增回归测试 `test_maximized_frame_centered_for_default_small_window`：
  断言所有可见行总宽 ≤ 80、艺术字块/副标题/面板各自在 80 列下居中（±1 列容差）。
  测量注意：字形行自带内部前导空格，须按块边缘（min 前导 / max 右缘）测量。
- 实测渲染（80 列视口）：艺术字、副标题、信息面板左右边距对称，正中。

## 教训

- **终端输出是"一次成像"的**：留到 scrollback 的 UI 必须同时满足"窄"（防折行）
  和"矮"（防 reflow 断裂/顶出可视区）。动画类内容用 transient Live 展示、
  退出即清除，是安全的；静态 `console.print` 只能放紧凑内容。
- **居中与安全互斥**：居中靠空格垫宽，垫宽就是未来的折行风险；
  对缩窗不可预知的场景，缩进必须封顶。
- 验证"终端渲染类"修复时，按字节测量行宽/行数比目测可靠；
  行尾空格在终端不可见且无折行危害，测量时应去除。
- **仪式感与安全不必然互斥**：静态反应炉只要宽度封顶（≤64 列）就能安全留在
  scrollback；真正危险的是"按最大化窗口尺寸定格的超宽画面"，用分流而非一刀切。
- **静态帧尺寸必须与动画一致**：曾为防视口溢出给定格帧单独封顶高度，导致定格后
  反应炉变小，用户不接受。正确做法：定格帧直接继承动画最后一帧的几何参数，
  高度风险通过动画几何自身的预留行（_CANVAS_RATIO + 11 行）消化，而非二次缩放。
- **Rich Panel 的 width 是外框总宽**，内容区 = width - 边框 2 - padding 2；
  定宽面板塞文本前必须用 `cell_len` 实测（CJK 字符按 2 cells 计），
  而不是 `len()` 估算。`no_wrap` 只截断不防拆行，需"必须单行"时应把容器做宽。
- **居中基准要选"用户最终停留的窗口宽"而非当前窗口宽**：最大化定格的画面，
  用户大概率会缩回默认窗口，按终端默认 80 列预居中才能在目标状态下正中；
  按当前（120+ 列）居中只会让垫宽超出小窗、被 reflow 吞掉后偏左。
  宽度不同的多行元素（艺术字/副标题/面板）必须各自独立计算缩进。
- **渲染类测试别依赖宿主编码环境**：`io.StringIO().encoding` 是只读的 `None`，
  Rich 据此判定 `ascii_only`、把面板边框降级成 ASCII `+--`；本地设了
  `PYTHONIOENCODING=utf-8` 掩盖了差异，CI（Linux 无该变量）挂掉。
  测试里用自定义 buffer（encoding="utf-8"）固定环境，边框断言同时认 ┌/└ 与 +。
