# /talk 星期五体验修复：标签错乱、退出规则死板、报时后自发挂断

> 修复日期：2026-11-26　分支：`refactor/talk-voice-layering`　作者：aceFelix

## 1. 问题现象

用户在 `/talk` 实机对话（2026-11-26）：

1. 转录界面仍显示 `🤖 贾维斯:`，但模型自称星期五，身份看起来自相矛盾；
2. 问完时间后，模型**自发调用 `end_conversation`**（用户并没有要退出）；
3. 被意图门拦下后，模型把拒绝原因原样念出来：
   「…但我需要您明确说“退下”、“结束对话”或“再见”才能离开…」
   ——像在教训用户；
4. 用户说“做饭。”，模型口头说“我这就退下”，却**没有调用工具**，会话并未结束；
5. 用户整体感受：星期五“太死板，非得让我明确正确的指令”。

## 2. 排查过程

- **标签**：`agent/ui/cli.py` 的 `on_ai_transcript()` 写死 `🤖 贾维斯:`；/talk 的转写
  统一走这里（`realtime_recv` → `ui.on_ai_transcript`），所以人设改了标签没改。
- **自发挂断**：`_allow_end_conversation()` 用「最近一轮用户文本」做硬门；问时间后的
  上一轮是“你是星期五”，不含结束语，门禁拒绝是**正确行为**。真正的问题是模型不该
  在回答后调工具——提示词/工具描述里“绝不/必须明确”的强否定堆叠，反而让它更关注
  这个工具。
- **念规则**：拒绝时 `execute_tool` 把一句完整的规则说明作为 `result` 回给模型，
  模型自然把它当“该说的话”念出来。
- **口号不一致**：启动横幅写着“说「退下/不聊了/去忙吧」进入待机”，但
  `_END_INTENT_WORDS` 里没有“去忙”——用户按提示说也会被拒。

## 3. 根因

| 问题 | 根因 |
|---|---|
| 标签显示贾维斯 | UI 层硬编码标签，未与人设同源 |
| 念规则、要求换说法 | 工具拒绝结果是一条可被照念的规则句 |
| 回答后自发挂断 | 提示词与工具描述过度强调“绝不”，缺少“回答完不构成结束理由”的正向约束 |
| 口头退下但不挂断 | 没有“要结束必须实际调用工具”的约束 |
| 去忙吧被拒 | 横幅承诺词表与硬门词表不一致 |

## 4. 修复方案

- `agent/ui/cli.py::on_ai_transcript`：标签改为 `🤖 星期五:`，注释说明与人设对齐；
- `agent/talk/realtime_talk.py` 两份 instructions 的结束段改为自然表达：
  用户表达离开（含“退下吧/不聊了/去忙吧/再见/拜拜/没事了”）就直接调用并顺口告别，
  **不要要求用户换说法、不要把规则念给用户听**；只是“停一下/等一下/暂停”时继续听；
  **回答完问题本身不构成结束理由**；**要结束必须实际调用工具**，不能只在嘴上说退下；
- `agent/talk/realtime_tools.py`：`end_conversation` 描述同步改写；意图门拒绝时只回
  `{"result": "continue"}`（中性标记），并在描述里说明“返回 continue 就自然继续，
  不要解释或复述规则”；
- `agent/talk/realtime_engine.py::_END_INTENT_WORDS`：补“去忙/先这样/晚安/走吧/
  结束吧/退出/关闭语音”等自然说法，与横幅口径一致。

## 7. 经验总结

- **工具拒绝结果绝不能是一句完整规则**：LLM 会把它当台词念给用户。拒绝只回机器标记，
  规则写进工具描述。
- 提示词里“绝不/必须明确”的强否定堆叠会放大对应工具的显著性，容易诱发误调用；
  用“什么时候该做 + 什么时候不该做”的正向行为描述更稳。
- 启动口号里承诺的说法，必须与硬门词表逐条对齐，否则用户按提示操作反而被拒。
- UI 展示标签与人设是两个源，改人设时要全仓搜一次可见文案（`贾维斯:` 这类）。
