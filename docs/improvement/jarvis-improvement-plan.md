# JARVIS 改进计划

> 基于代码审查的系统性改进文档，记录当前差距和后续优化方向。
>
> 审查时间：2026-07-26
> 代码版本：2.0.1
> 审查范围：`agent/`、`configs/`、`tests/`、`npm/`

---

---

## 1. 架构与代码组织（60% → 85%）

### 现状问题

- `agent/main.py` 单文件 1300+ 行，承担 CLI 入口、命令分发、模型管理、会话管理等多重职责
- `agent/config/settings.py` 700+ 行，配置加载、环境变量覆盖、模型切换逻辑混在一起
- LLM Provider 层思考模式参数散落在 if-else 分支里，每加一个厂商就要改代码

### 改进项

| ID | 改进项 | 说明 | 优先级 |
|---|---|---|---|
| A-01 | 拆分 `main.py` | 命令路由、模型管理、会话管理各自独立模块（✅ 已完成 2026-07-26） | 中 |
| A-02 | 思考模式策略化 | 用策略模式或配置表替代 if-else，新增厂商只加配置不改代码（✅ 已完成 2026-07-29）| 中 |
| A-03 | 拆分 `settings.py` | 拆成 `loader.py` + `model_registry.py` + `env.py`（✅ 已完成 2026-07-29）| 低 |
| A-04 | Provider 参数表驱动 | 各厂商的 base_url、思考参数、模型特性用配置表描述（✅ 已完成 2026-07-29）| 中 |

---

## 2. 测试覆盖（20% → 70%）

### 现状问题

- `tests/` 只有约 10 个测试文件，主要覆盖 collaboration、permissions、sandbox、query_loop
- 核心的 `OpenAIProvider`、`settings.py`、`main.py` 命令分发几乎没有测试
- 没有 CI 配置

### 改进项

| ID | 改进项 | 说明 | 优先级 |
|---|---|---|---|
| T-01 | Provider 层单元测试 | mock HTTP，验证参数构造、流式解析、错误处理（✅ 已完成 2026-07-30）| 高 |
| T-02 | 命令路由集成测试 | 测试 `/models`、`/voice`、`/talk` 等命令的分发逻辑（✅ 已完成 2026-07-26） | 高 |
| T-03 | 配置加载/迁移测试 | 测试 settings.toml 解析、环境变量覆盖、custom_models 合并（✅ 已完成 2026-07-30）| 中 |
| T-04 | 工具注册测试 | 验证 build_default_registry、MCP 工具注册、权限检查（✅ 已完成 2026-07-30）| 中 |
| T-05 | GitHub Actions CI | push/PR 时自动跑测试 + 语法检查（✅ 已完成 2026-07-30）| 中 |

---

## 3. 错误处理与健壮性（40% → 80%）

### 现状问题

- LLM 错误信息不友好（如智谱 405 返回原始 HTML，用户看不懂）
- MCP 连接失败静默跳过，用户不知道为什么工具不可用
- 实时语音模块有 `except Exception: pass`，会吞掉诊断信息

### 改进项

| ID | 改进项 | 说明 | 优先级 |
|---|---|---|---|
| E-01 | LLM 错误分类 | 鉴权失败、模型不存在、限流、网络超时，给用户可操作的提示（✅ 已完成 2026-07-30）| 高 |
| E-02 | MCP 连接状态反馈 | 连接失败时通知用户哪些工具不可用（✅ 已完成 2026-07-30）| 中 |
| E-03 | 消除静默异常 | `except Exception: pass` 改成 `except Exception as e: logger.warning(...)`（✅ 已完成 2026-07-30）| 中 |
| E-04 | 结构化日志 | 关键路径用 logging 替代 print，支持日志级别和文件输出（✅ 已完成 2026-07-30）| 低 |
| E-05 | 重试与降级 | 网络超时自动重试，模型不可用时提示切换（✅ 已完成 2026-07-30）| 低 |

---

## 4. 用户体验（50% → 80%）

### 现状问题

- 配置全靠 toml 手写，没有 `jarvis init` 引导命令
- 模型添加时不检测 API Key 是否有效
- 终端 UI 交互粗糙（模型选择器竖向列表问题折腾了多轮）

### 改进项

| ID | 改进项 | 说明 | 优先级 |
|---|---|---|---|
| U-01 | `jarvis init` 引导命令 | 交互式引导首次配置：选厂商→输入 Key→测试连接→保存（✅ 已完成 2026-07-30）| 中 |
| U-02 | 添加模型时测试连接 | 输入 API Key 后自动发一个测试请求验证 | 中 |
| U-03 | 错误提示友好化 | "OpenAI API error: <html>..." → "智谱 API 调用失败：模型不存在或无权限"（✅ 已完成 2026-07-30，见 E-01）| 高 |
| U-04 | 终端 UI 优化 | 考虑用 `questionary` 或 `InquirerPy` 替代手写 prompt_toolkit 布局 | 低 |
| U-05 | `jarvis config show` | 查看当前生效的完整配置（含优先级合并结果）（✅ 已完成 2026-07-30）| 中 |

## 5. 部署与分发（40% → 75%）

### 现状问题

- 用户必须预装 Python，没有独立可执行文件
- 配置文件分散在 `configs/settings.toml`、`~/.jarvis/settings.toml`、环境变量三层
- wheel 打包基本可用，但首次安装体验不够顺滑

### 改进项

| ID | 改进项 | 说明 | 优先级 |
|---|---|---|---|
| D-01 | PyInstaller 打包 | 打包成独立 exe/dmg，无需预装 Python | 中 |
| D-02 | Docker 镜像 | 无 GUI 模式的 Docker 镜像，适合服务器部署 | 低 |
| D-03 | `jarvis doctor` | 诊断命令：检查 Python 版本、依赖完整性、API Key 配置、音频设备 | 中 |
| D-04 | 安装后自动配置 | pip install 后自动运行 init 引导 | 低 |

---

## 6. 安全性（45% → 75%）

### 现状问题

- `settings.toml` 里明文存了 SMTP 密码、API Key
- yolo 模式下大量操作自动放行
- 没有操作审计日志

### 改进项

| ID | 改进项 | 说明 | 优先级 |
|---|---|---|---|
| S-01 | API Key 加密存储 | 走系统 keyring 或加密存储，不明文写在 toml 里（✅ 已完成 2026-07-30）| 中 |
| S-02 | 操作审计日志 | 记录所有工具调用（尤其是 yolo 模式下的写操作）（✅ 已完成 2026-07-30）| 中 |
| S-03 | 敏感字段保护 | settings.toml 中的密码字段自动脱敏显示（✅ 已完成 2026-07-30）| 低 |

---

## 7. 性能（50% → 75%）

### 现状问题

- 实时语音启动慢（MCP 连接串行、工具注册重复初始化）
- 没有连接池复用
- `build_default_registry()` 每次调用都重新加载所有模块

### 改进项

| ID | 改进项 | 说明 | 优先级 |
|---|---|---|---|
| P-01 | MCP 连接并行化 | `connect_all` 内部并发连接各 MCP server（✅ 已完成 2026-07-30）| 中 |
| P-02 | Provider HTTP 连接复用 | httpx.AsyncClient 单例复用，避免每次新建（✅ 已完成 2026-07-30）| 中 |
| P-03 | 工具注册缓存 | build_default_registry 结果缓存，不每次重建（✅ 已完成 2026-07-30）| 低 |
| P-04 | 实时语音延迟初始化 | 先连 WebSocket 显示"已连接"，MCP 工具后台连完后热更新（✅ 已完成 — realtime_talk.py _load_mcp_tools_async）| 中 |
| P-05 | 多厂商缓存策略管理 | cache_policy.py 配置表驱动：显式缓存注入 cache_control（DashScope/Anthropic），隐式缓存自动适配（DeepSeek/智谱），usage 统计统一归一化（✅ 已完成 2026-07-30）| 中 |

## 优先级排序（建议实施顺序）

### 第一阶段：核心可用性（高优先级）
1. **E-01** LLM 错误分类 — 用户看到原始 HTML 报错体验极差
2. **U-03** 错误提示友好化 — 同上
3. **T-01** Provider 层单元测试 — 核心路径必须有测试
4. **T-02** 命令路由集成测试

### 第二阶段：工程化基础（中优先级）
5. **E-03** 消除静默异常
6. **E-02** MCP 连接状态反馈
7. **A-02** 思考模式策略化
8. **T-05** GitHub Actions CI
9. **U-01** `jarvis init` 引导命令
10. **D-03** `jarvis doctor` 诊断命令

### 第三阶段：产品化（中低优先级）
11. **P-01** MCP 连接并行化
12. **P-04** 实时语音延迟初始化
13. **A-01** 拆分 `main.py`
14. **S-01** API Key 加密存储
15. **D-01** PyInstaller 打包
16. **F-01~F-04** 文档补全
