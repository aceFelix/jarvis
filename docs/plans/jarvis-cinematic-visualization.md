> 来源：用户提出的产品构想——参考《钢铁侠》中 JARVIS 操作电脑／检索信息时的多弹窗与数据可视化。
> 状态：构想记录，后续分阶段实现；当前不阻塞窗口跟随（见 [window-observer.md](window-observer.md)）。

## 1. 电影里的 JARVIS 到底在演什么

那套界面是**叙事性 UI**，不是真实软件界面。拆开只有四类元素：

| 元素 | 电影里的表现 | 对应到 jarvis 的真实信息 |
|---|---|---|
| 任务弹窗 | 每个子任务一个小窗，层层叠叠，完成一个收一个 | 每个工具调用 / 子代理 / 任务步骤 |
| 数据流 | 滚动的文字、坐标、日志 | trace 事件、工具入参、抓取结果 |
| 网络图 | 节点 + 连线，不断生长 | 网页抓取拓扑（URL 图） |
| 扫描框 | 在画面上圈出目标 | 窗口矩形 / 视觉定位框 |

**结论**：不需要 3D 全息、不需要人脸追踪。只要把上面四类信息做成"看得见的层"，就有 JARVIS 味。

## 2. "爬虫可视化"的两层含义

用户说的"爬虫可视化"通常同时指这两件事，实现时要分开：

### 2.1 抓取过程可视化（Crawl Topology）

- 节点：一个 URL / 一个页面；
- 边：从哪一页跳到哪一页（`parent_url → url`）；
- 状态色：待抓 / 抓取中 / 成功 / 失败 / 重复跳过 / 被规则拦截；
- 统计：队列长度、已抓数、失败数、去重命中、平均耗时、字节数；
- 布局：环形或力导向，节点随抓取逐步出现。

### 2.2 抽取结果可视化（Extraction Stream）

- 每个页面抓完后，把结构化字段实时填进表格：
  `标题 | 时间 | 作者 | 摘要 | 来源 URL`
- 点击某行可回到抓取拓扑里对应的节点；
- 字段来自 `web_extract` 事件，不由界面猜测。

> jarvis 当前没有完整"爬虫"（没有 frontier 队列、深度控制、去重库）。
> 现有的是 `Browser*` 工具、`WebSearch`、`WebFetch`。本构想先做**可视化层**，
> 抓取语义可以后补；事件结构按"未来会有 crawler"来定，避免返工。

## 3. 三层落地形态

### 3.1 终端层（先做）

用 Rich Live 做一个"任务驾驶舱"，不抢占输入行：

```
┌─ 任务面板 ──────────────────────────────┐ ┌─ 数据流 ──────────────┐
│ ▶ BrowserNavigate  https://example.com  │ │ 12:01 GET / 200 8KB   │
│ ▶ BrowserExtract   字段 6 个             │ │ 12:01 去重命中 3      │
│ ✓ 完成 2 / 失败 0                        │ │ 12:02 GET /a 200 12KB │
└────────────────────────────────────────┘ └──────────────────────┘
┌─ 抓取拓扑（ASCII） ─────────────────────────────────────────────┐
│            (root)                                                │
│        ┌──────┼──────┐                                           │
│      /a      /b      /c                                          │
│      │        │                                                  │
│     /a1      /b1                                                 │
└──────────────────────────────────────────────────────────────────┘
┌─ 抽取结果 ───────────────────────────────────────────────────────┐
│ 标题            │ 时间       │ 作者   │ 来源                    │
│ React 19 新特性 │ 2026-11-01 │ 张三   │ https://example.com/a   │
└──────────────────────────────────────────────────────────────────┘
```

限制：终端是字符网格，做不到电影级浮窗；但"多面板 + 实时增长"已经能传达同样的信息结构。

### 3.2 桌面层（后做）

Electron 壳新增 **PanelManager**：

| 能力 | 实现要点 |
|---|---|
| 多浮窗 | 每个任务卡一个 `BrowserWindow`：无边框、透明、`alwaysOnTop`、`skipTaskbar` |
| 错位堆叠 | 按任务深度计算 `(x+24n, y+18n)`，完成时向左上收起并淡出 |
| 任务分组 | 同一子代理的窗口同色边框，完成后整组收起 |
| 不抢焦点 | 浮窗 `focusable: false`，只展示不接收键鼠 |
| 可暂停 | 标题栏「暂停可视化」一键停止所有动画与推流 |
| 性能 | 卡片窗口复用池，最多 N=6 个，超出折叠为一行 |

### 3.3 拓扑图（桌面）

- Canvas 2D（不引 3D 引擎）；
- 力导向布局，节点上限 200，超出聚合为分组节点；
- 状态色：灰（待抓）/ 蓝（抓取中）/ 绿（成功）/ 红（失败）/ 黄（重复）；
- 点击节点 → 右侧显示该页抽取结果；
- 拓扑数据只从 `web_fetch` 事件来，不反推。

## 4. 需要补的事件（宿主无关）

现有 trace 是工具级事件，需要新增三类。终端与桌面共用同一份 JSONL / WS 事件：

```json
{"type":"web_fetch","url":"https://example.com/a","parent_url":"https://example.com/",
 "depth":1,"status":"ok","http_status":200,"bytes":12288,"duration_ms":340}

{"type":"web_extract","url":"https://example.com/a",
 "fields":{"title":"React 19 新特性","published":"2026-11-01","author":"张三"},
 "field_count":3}

{"type":"crawl_stats","queued":12,"done":8,"failed":1,"dedup_hits":3,"bytes":98304}
```

采集位置：
- `Browser*` 工具：导航/抓取/抽取处埋点；
- `WebFetch`/`WebSearch`：只记 `web_fetch`（无窗口）；
- 未来 crawler：由 crawler 自身发 `crawl_stats`。

## 5. 分阶段

| 阶段 | 内容 | 载体 | 验收 |
|---|---|---|---|
| **C1** | 终端任务驾驶舱：任务面板 + 数据流 + 抽取表 | Rich Live | 一轮抓取任务能实时看到三块内容，不干扰输入 |
| **C2** | 终端 ASCII 拓扑 | Rich / 字符画 | 节点随抓取增长，状态色可辨 |
| **C3** | 桌面多浮窗 + 错位堆叠 | Electron PanelManager | 任务卡实时出现/收起，不抢焦点 |
| **C4** | 桌面 Canvas 拓扑 + 抽取联动 | Electron | 点击节点联动右侧结果 |
| **C5** | 电影感打磨 | 动画/音效 | 可关闭，默认克制 |

> 先 C1/C2：不改抓取逻辑，只做展示层；确认"感觉对了"再进桌面。

---

## 6. 非目标

- ❌ 3D 全息投影、透明悬浮球、语音口型同步；
- ❌ 实时视频墙 / 屏幕录制流；
- ❌ 为"炫"牺牲可读性：默认信息密度优先，动画可关；
- ❌ 让可视化反向影响抓取策略（展示层只读事件）。

---

## 7. 风险

| 风险 | 对策 |
|---|---|
| 浮窗太多干扰用户 | 上限 6 个 + 一键暂停 + 完成后自动收起 |
| 动画耗电/掉帧 | Canvas 限 30fps；后台标签暂停 |
| 数据量过大 | 拓扑节点上限 200；抽取表分页；事件采样 |
| 隐私 | URL/字段沿用窗口标题脱敏规则；可关闭持久化 |
| 与窗口跟随抢屏 | 浮窗 `focusable:false`；跟随仍走 show 档不激活 |
