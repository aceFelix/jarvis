# 14 - 跨设备与微信接入

> 本文档详解 J.A.R.V.I.S 的两种远程接入渠道：跨设备协同（`/connect-phone`，Bridge 模块）和微信 ClawBot 接入（`/connect-wechat`，WeChat 模块）。

@author aceFelix

---

## 一、概述

J.A.R.V.I.S 支持两种远程接入方式，让用户脱离电脑终端也能与 JARVIS 对话：

| 渠道 | 命令 | 模块 | 协议 | 适用场景 |
|------|------|------|------|----------|
| 手机 PWA | `/connect-phone` | `agent/bridge/` | 局域网 WebSocket | 同一 Wi-Fi 下手机远程操控 |
| 微信 ClawBot | `/connect-wechat` | `agent/wechat/` | 腾讯 iLink Bot API | 任意网络，通过微信聊天对话 |

两者共享同一设计范式：
- **独立线程**运行，不阻塞 REPL 主循环
- **全局单例**管理，一个会话只有一个实例
- **共享 messages**，远程对话与电脑终端看到同一对话历史
- **串行化锁**保护共享 messages 不被并发写入

## 二、跨设备协同（Bridge 模块）

### 2.1 架构

```
┌─────────────┐   HTTP(8765): 静态文件 + /api/config + /upload
│  手机 PWA   │ ───────────────────────────────────────────────┐
│ (index.html)│                                                │
└─────────────┘   WebSocket(8766): 双向通信（token 认证）      │
     │  ↑                                                      │
     ↓  │  event: assistant_text / tool_use / done             │
┌──────────────────────────────────────────────────────────────┐
│                    BridgeServer (电脑端)                       │
│  ┌──────────────┐  ┌──────────────┐  ┌───────────────────┐  │
│  │ThreadingHTTP │  │ websockets   │  │ threading.Lock    │  │
│  │Server(线程)  │  │ serve(loop)  │──│ 并发控制:单query  │  │
│  └──────────────┘  └──────────────┘  └───────────────────┘  │
│                                              │              │
│              共享 messages ┌─────────────────┘              │
│                            ▼                                │
│  ┌──────────────┐  ┌──────────────────┐  ┌─────────────┐  │
│  │  BridgeUI    │←─│  ToolContext     │←─│  QueryLoop  │  │
│  │ (UIProtocol) │  │  (plan 权限)     │  │ (daemon共享)│  │
│  └──────────────┘  └──────────────────┘  └─────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 文件结构

```
agent/bridge/
├── __init__.py      # 模块导出（BridgeServer, BridgeUI, BroadcastUI）
├── server.py        # BridgeServer 核心（HTTP + WS + 单例管理）
├── ui.py            # BridgeUI（UIProtocol → WS 事件流）+ BroadcastUI
└── static/
    └── index.html   # PWA 前端（暗色主题单文件）
```

### 2.3 核心流程

1. **启动**：`/connect-phone` → `start_bridge_in_thread()` → 独立线程启动 HTTP + WS 服务
2. **认证**：手机连接 WS 时通过 `?token=xxx` 校验，token 自动生成
3. **对话**：手机发消息 → WS → `_run_query()` → 加锁执行 `QueryLoop.run()` → 流式推送事件回 WS
4. **同屏**：`BroadcastUI` 把电脑端对话同步推送给已连接的手机端
5. **停止**：终端退出或手动调用 `stop_bridge()`

### 2.4 设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 权限模式 | `plan`（只读） | 手机端远程操控风险高，写操作需确认 |
| HTTP 服务 | `ThreadingHTTPServer` | 同步简单，独立线程不干扰 asyncio |
| WS 库 | `websockets` | 与 realtime_talk 共用依赖 |
| 并发控制 | `threading.Lock` | 跨线程串行化，保护共享 messages |
| 事件传输 | 线程安全 `queue.Queue` | UIProtocol 回调是同步的，避免跨 loop 问题 |

### 2.5 配置

```toml
[bridge]
http_port = 8765    # PWA 页面端口
ws_port = 8766      # WebSocket 通信端口
token = ""          # 认证 token，留空自动生成
```

## 三、微信 ClawBot 接入（WeChat 模块）

### 3.1 架构

```
┌─────────────┐         ┌──────────────┐         ┌─────────────────────┐
│  微信 APP   │ ←────→  │  腾讯云 iLink │ ←────→  │  agent/wechat/      │
│ (ClawBot)   │         │  (消息中转)   │         │  ilink.py (HTTP)    │
└─────────────┘         └──────────────┘         └─────────┬───────────┘
                                                           │
                                                 ┌─────────▼───────────┐
                                                 │  server.py          │
                                                 │  WeChatBridge       │
                                                 │  (独立线程+单例)    │
                                                 └─────────┬───────────┘
                                                           │
                                                 ┌─────────▼───────────┐
                                                 │  QueryLoop          │
                                                 │  (共享 messages)    │
                                                 └─────────────────────┘
```

### 3.2 文件结构

```
agent/wechat/
├── __init__.py      # 模块导出（WeChatBridge, start/stop/get）
├── ilink.py         # iLink Bot API 客户端（扫码/轮询/收发消息）
├── server.py        # WeChatBridge（消息循环 + 单例 + 24h 重连）
└── ui.py            # WeChatUI（UIProtocol，收集回复文本）
```

### 3.3 iLink Bot API 协议

基于腾讯官方 `@tencent-weixin/openclaw-weixin` 2.x 协议：

**域名**：`ilinkai.weixin.qq.com`

**请求头**（每次请求）：
```
Content-Type: application/json
AuthorizationType: ilink_bot_token
X-WECHAT-UIN: <随机uint32的base64>
iLink-App-Id: bot
iLink-App-ClientVersion: 132099
Authorization: Bearer <bot_token>
```

**核心 API**：

| 端点 | 方法 | 用途 |
|------|------|------|
| `ilink/bot/get_bot_qrcode?bot_type=3` | POST | 获取登录二维码 |
| `ilink/bot/get_qrcode_status?qrcode=xxx` | GET | 轮询扫码状态 |
| `ilink/bot/getupdates` | POST | 长轮询接收消息（hold ~35s） |
| `ilink/bot/sendmessage` | POST | 发送文本消息 |
| `ilink/bot/sendtyping` | POST | 显示/取消"正在输入" |
| `ilink/bot/getconfig` | POST | 获取 typing_ticket |

**sendmessage 必填结构**（缺少字段会静默丢失）：
```json
{
  "msg": {
    "from_user_id": "",
    "to_user_id": "<用户ID@im.wechat>",
    "client_id": "openclaw-weixin-<随机hex>",
    "message_type": 2,
    "message_state": 2,
    "context_token": "<从收到的消息中原样取>",
    "item_list": [{"type": 1, "text_item": {"text": "回复内容"}}]
  },
  "base_info": {"channel_version": "2.4.3", "bot_agent": "jarvis-wechat/1.0.0 (python)"}
}
```

### 3.4 核心流程

```
/connect-wechat
    │
    ▼
ILinkClient.fetch_login_qrcode()
    │ 返回 qrcode + qrcode_img_content
    ▼
终端渲染 ASCII 二维码
    │
    ▼
ILinkClient.wait_login_confirmation()  ← 轮询 get_qrcode_status
    │ 用户扫码 → "scanned" → 确认 → "confirmed"
    │ （可能需配对码 → verify_callback → 终端 input）
    ▼
获得 bot_token → 启动消息循环线程
    │
    ▼
┌─── run_loop() ────────────────────────────────┐
│  while running:                               │
│    result = getupdates(buf)   # 长轮询 35s    │
│    for msg in result.msgs:                    │
│      _handle_message(from_id, ctx_token, text)│
│        ├─ sendtyping(status=1)                │
│        ├─ QueryLoop.run(text, ctx)  # 加锁    │
│        ├─ sendmessage(reply)        # 分段    │
│        └─ sendtyping(status=2)                │
└───────────────────────────────────────────────┘
```

### 3.5 扫码状态机

```
wait → scanned → confirmed (→ 拿到 bot_token)
  │        │
  │        └→ need_verifycode → 输入配对码 → confirmed
  │
  └→ expired → 重新获取二维码（最多 3 次）
  └→ scaned_but_redirect → 切换轮询节点
  └→ binded_redirect → 已连接过，沿用
```

### 3.6 设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 权限模式 | `default`（完整能力） | 微信是私人对话，应能用全部工具 |
| HTTP 客户端 | `aiohttp` | 异步、支持长轮询超时控制 |
| 消息共享 | 共享 REPL messages | 与 bridge 一致，多端同一对话 |
| 长消息 | 超 2000 字分段发送 | 微信单条消息有长度限制 |
| 重连 | 24h 到期前终端提醒 | iLink token 有效期 24h，需重新扫码 |
| 并发控制 | `threading.Lock` | 与 bridge 一致，保护共享 messages |

### 3.7 依赖

```toml
[project.optional-dependencies]
wechat = [
    "aiohttp>=3.9.0",    # iLink API HTTP 客户端
    "qrcode>=7.4.0",     # 终端二维码渲染
]
```

安装：`pip install "jarvis-agent[wechat]"`

### 3.8 限制与注意事项

- 仅支持**文本消息**（图片/语音/文件需额外实现 CDN 加密上传）
- 微信版本需 ≥ 8.0.70，设置 → 插件中可看到 ClawBot
- `context_token` 必须使用当前消息中的值，不可复用旧 token
- 每次扫码 bot_id 会变化（iLink 平台设计，正常现象）
- 腾讯保留内容过滤和限速权利，不建议用于核心业务

## 四、两模块对比

| 维度 | Bridge（/connect-phone） | WeChat（/connect-wechat） |
|------|--------------------------|---------------------------|
| 网络要求 | 同一局域网 | 任意网络（走腾讯云中转） |
| 认证方式 | 自动生成 token | 微信扫码（iLink 协议） |
| 权限模式 | plan（只读） | default（完整能力） |
| 流式输出 | 支持（WS 实时推送） | 不支持（等 QueryLoop 完成后一次发送） |
| 消息类型 | 文本 + 图片 | 仅文本 |
| 有效期 | 随终端生命周期 | 24h（需重新扫码） |
| 依赖 | websockets + qrcode | aiohttp + qrcode |
| 合规性 | 自建服务 | 腾讯官方接口，不封号 |

### Bridge

```python
from agent.bridge import start_bridge_in_thread, stop_bridge, get_bridge_server

server = start_bridge_in_thread(query_loop, ctx, http_port=8765, ws_port=8766)
print(server.url)  # http://192.168.x.x:8765/?token=xxx
stop_bridge()
```

### WeChat

```python
from agent.wechat import start_wechat_in_thread, start_wechat_loop, stop_wechat, get_wechat_bridge

bridge = start_wechat_in_thread(query_loop, ctx, ui, main_loop=loop)
success = await bridge.login(verify_callback=..., qrcode_callback=...)
if success:
    start_wechat_loop()  # 启动消息循环线程
stop_wechat()
```
