# 10 - 扩展生态

J.A.R.V.I.S 提供多层扩展点：MCP / Skill / Plugin / LSP / Hook。

## 一、扩展点总览

| 扩展点 | 用途 | 加载方式 |
|---|---|---|
| **MCP** | 连接外部 MCP server，注册其工具 | `~/.jarvis/mcp.json` |
| **Skill** | 注入专业知识/工作流程到 system prompt | `~/.jarvis/skills/*/SKILL.md` |
| **CLI-Anything harness** | 把任意第三方软件包装为 Agent 工具 | `~/.jarvis/cli_anything/<id>/SKILL.md` |
| **Plugin** | 社区插件管理 | `/plugin install` |
| **LSP** | 代码智能（诊断/补全） | `[lsp.servers]` 配置 |
| **Hook** | 钩子干预执行流程 | 代码注册 |
| **Self-Healing** | 工具错误自动分类、重试、降级 | `ToolRecoveryExecutor` |

### 目录结构

```
~/.jarvis/cli_anything/
├── blender/               # 官方 harness（目录型）
│   └── SKILL.md
├── wps/                   # 自定义市场 harness（pip 型）
│   └── SKILL.md           # pip install jarvis-harness-wps 已安装全局命令
└── xmind/                 # 自定义市场 harness（pip 型）
    └── SKILL.md
```

### SKILL.md 格式

```markdown
---
name: Blender
id: blender
description: 通过 CLI 控制 Blender 3D 建模软件
when_to_use: 用户需要创建/修改 3D 模型、渲染场景时
trigger_words: [blender, 3d, 建模, 渲染]
command: cli-anything-blender      # 官方 harness 命令前缀
args:
  - name: subcommand
    type: string
    required: true
    positional: true               # 位置参数：只传值不加 --name
    enum: [scene, render, export]
    description: 子命令
  - name: output_path
    type: string
    required: false
    description: 导出路径           # flag 自动转为 --output-path（下划线→连字符）
examples:
  - "cli-anything-blender scene new -o scene.json"
---
```

### 执行流程

1. 启动时 `register_dynamic_tools()` 调用 `discover_and_register()`
2. 扫描 `~/.jarvis/cli_anything/` + 项目级 `.jarvis/cli_anything/`，解析每个 `SKILL.md`
3. 生成 JSON Schema，创建 `CliAnythingTool` 实例（工具描述含参数列表）
4. 工具名格式：`cli_anything__<id>`
5. system prompt 中自动注入 harness 能力说明

### runner 安全与兼容设计

| 特性 | 实现 |
|------|------|
| **命令白名单** | `python` / `node` / `npm` / `npx` / `cli-anything-*` / `jarvis-harness-*` |
| **位置参数** | `positional: true` 时只传值不加 `--name` 前缀 |
| **flag 连字符** | arg 名下划线自动转连字符（`output_path` → `--output-path`） |
| **路径自动转换** | Git Bash 路径 `/e/...` 自动转 Windows 路径 `E:\...` |
| **未知参数忽略** | LLM 多传参数不报错，仅日志 warning |
| **`--harness-dir`/`--workdir`** | 放在子命令前（argparse 要求可选参数在位置参数前） |
| **UTF-8 编码** | Windows 上 harness CLI 自动 `sys.stdout.reconfigure(encoding="utf-8")` |
| **超时强制终止** | 默认 120 秒 |
| **图片提取回传** | JSON 输出中的图片路径自动编码为 `ImageContent`，视觉模型可直接看到 |

### 市场管理

```text
/cli_anything list              # 列出已安装 harness
/cli_anything market            # 列出市场可用 harness（官方 + 自定义）
/cli_anything install <id>      # 安装 harness（pip 型自动 pip install）
/cli_anything uninstall <id>    # 卸载 harness
```

多级市场源（同 id 自定义覆盖官方）：
1. jarvis 自定义市场远程 registry.json
2. CLI-Anything 官方远程 registry.json
3. jarvis 自定义市场本地目录
4. CLI-Anything 官方本地仓库（含缓存）

### 安全设计

- 默认 **ASK** 权限
- 不通过 shell 执行（`asyncio.create_subprocess_exec`）
- 超时强制终止（默认 120 秒）
- command 白名单校验

**为什么用 CLI-Anything harness**：无需编写 Python Tool 代码，就能把任意第三方软件包装成 Agent 可调用的工具。当前已安装 71 个 harness。

完整测试清单、用例、步骤与使用指南见 [../cli-anything-testing.md](../cli-anything-testing.md)。

Plugin 系统和 CLI-Anything harness 是**两个独立的市场**，命令、状态、脚手架都各管各的：

| 安装 | `/plugin install` | `/cli_anything install` |
| 卸载 | `/plugin uninstall` | `/cli_anything uninstall` |
| 启用 | `/plugin enable <名称>` | `/cli_anything enable <id>` |
| 禁用 | `/plugin disable <名称>` | `/cli_anything disable <id>` |
| 创建 | `/plugin create <名称>` | `/cli_anything create <id>` |
| 校验 | `/plugin validate <路径>` | `/cli_anything validate <路径>` |

### CLI-Anything harness 命令

```bash

```

### 启用/禁用

Plugin 和 harness 的禁用状态分别持久化：
- Plugin：`~/.jarvis/plugins/disabled.json`，skills 被移动到 `~/.jarvis/plugins/disabled/<名称>/`
- harness：`~/.jarvis/cli_anything/disabled.json`，harness 目录保留在原位

与卸载不同，禁用保留文件，可快速重新启用。启用/禁用后需重启 Jarvis 或执行 `/reset` 生效。

### 插件创建脚手架

- `/plugin create <名称>` 生成 `plugin.json` + `skills/` 目录 + `README.md`
- `/cli_anything create <id>` 生成 `SKILL.md` + `README.md`

### 配置

```toml
[plugins]
enable = true
marketplace_url = ""      # Plugin 系统远程 marketplace.json URL（留空使用默认）
marketplace_local = ""    # 本地插件市场目录（绝对或相对于 jarvis 项目目录）
```

本地市场支持两种目录结构：

```text
# 扁平布局
<marketplace_local>/
├── weather/
│   └── plugin.json
└── everything-sdk/
    └── plugin.json

# 仓库布局（与 aceFelix/jarvis-plugins 一致）
<marketplace_local>/
├── marketplace.json
└── plugins/
    ├── weather/
    │   └── plugin.json
    └── everything-sdk/
        └── plugin.json
```

搜索顺序：
1. 远程 marketplace.json
2. 本地 `plugins/<name>/plugin.json`（优先，可直接本地安装）
3. 本地根目录 `<name>/plugin.json`
4. 本地 marketplace.json 中 subdir 指向本地 `plugins/` 的条目

同 id 时本地覆盖远程。

CLI-Anything harness 市场配置：

```toml
[cli_anything]
market_url = ""           # CLI-Anything 自定义市场远程 URL
market_local = ""         # CLI-Anything 自定义市场本地路径
```

## 七、Hook 钩子系统

### 核心文件

[hooks.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/core/hooks.py)

### 钩子事件

| 事件 | 触发时机 | 可做 |
|---|---|---|
| `USER_PROMPT` | 用户输入后 | 修改输入 |
| `ASSISTANT_RESPONSE` | 响应完成后 | 后处理/记录 |
| `TOOL_BEFORE` | 工具执行前 | 拒绝/修改输入 |
| `TOOL_AFTER` | 工具执行后 | 记录/分析 |
| `FILE_CHANGED` | 文件类工具后 | 通知/索引 |
| `ERROR` | 工具异常时 | 告警/重试 |

### 注册钩子

```python
from agent.core.hooks import get_hooks, HookEvent

async def my_hook(payload):
    print(f"工具执行: {payload['tool_name']}")
    return HookResult(allow=True)

get_hooks().register(HookEvent.TOOL_BEFORE, my_hook)
```

### HookResult

```python
@dataclass
class HookResult:
    allow: bool = True           # 是否允许执行
    reason: str | None = None    # 拒绝原因
    modify_input: dict | None = None  # 修改工具输入
```

**为什么用 Hook**：解耦。想加日志/监控/审计，注册钩子即可，不用改核心代码。

## 九、DevServer 开发服务器

[tools/extensions/dev_server_tool.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/tools/extensions/dev_server_tool.py) 提供一键启动前端/Node 开发服务器的能力。

### 为什么单独做 DevServer

之前 Jarvis 用 Bash 工具执行 `npm run dev` 启动项目时频繁失败，原因包括：
- 把 Vite 等长期运行的开发服务器当短命令执行，超时后误判失败
- Windows 路径写法混乱（`E:\\...` vs `/e/...`）
- 端口被占用后不会自动切换
- 后台进程管理不当，jarvis 退出时子进程一起挂掉

DevServer 把启动过程封装成工具，统一处理这些问题。

### 能力

- **项目类型自动识别**：Vite / Next.js / Nuxt / Vue CLI / Webpack / CRA / Gatsby
- **Package manager 自动选择**：pnpm / yarn / npm
- **端口占用自动递增**：默认端口被占用时找下一个可用端口
- **后台进程隔离**：Windows 用 `CREATE_NEW_PROCESS_GROUP`，Unix 用 `start_new_session`
- **日志重定向**：`~/.jarvis/dev_server_logs/<项目名>_<时间戳>.log`
- **URL 自动提取**：从日志中解析 `http://localhost:port`

### 命令

```bash
/server                                  # 启动当前目录项目
/server jarvis-website                   # 启动指定目录项目
/server --port 3000                      # 指定端口
/server --command "pnpm run dev"         # 自定义命令
```

### AI 工具

```
DevServer(project_dir="jarvis-website", port=3000)
→ 返回 {project_type, command, pid, port, url, log_file}
```

### 设计取舍

- 不替代 Bash：复杂自定义命令仍可走 Bash
- 不管理进程生命周期：开发服务器随 Jarvis 退出而退出（如需常驻，应使用 daemon 或其他进程管理方案）

## 十、工具错误自愈

[core/error_recovery.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/core/error_recovery.py) 是 P0 升级新增的核心能力，负责在工具调用失败时自动分类、重试、降级或询问用户。

### 核心组件

| 组件 | 职责 |
|---|---|
| `ToolErrorClassifier` | 把错误文本/异常分类为 `ToolErrorCategory` |
| `ToolRecoveryExecutor` | 按策略执行重试、自动修复、询问用户 |
| `RecoveryTelemetry` | 进程内单例，记录自愈事件供 `/doctor` 展示 |

### 错误分类

| 分类 | 策略 |
|---|---|
| `NETWORK_TRANSIENT` | 指数退避重试 3 次 |
| `RATE_LIMIT` | 指数退避重试 3 次，基数更长 |
| `TIMEOUT` | 重试 + 自动延长 `timeout` 参数 |
| `NOT_FOUND` | 重试 + 自动创建父目录（写类工具） |
| `PERMISSION_DENIED` | 不重试，直接提示用户 |
| `AUTH_MISSING` | 不重试，提示检查 API Key |
| `DEPENDENCY_MISSING` | 一次重试，给出安装建议 |
| `CONFIG_INVALID` | 一次重试，检查配置 |

### 集成位置

- `ToolOrchestrator._run_one()` 在调用 `tool.call()` 前用 `ToolRecoveryExecutor.execute()` 包装
- REPL / headless / ACP / daemon / teammate / subagent 全部统一装配 `recovery_executor`

### 配置

```toml
[self_healing]
enable_tool_self_healing = true
tool_retry_max = 3
tool_retry_backoff_base = 1.0
tool_retry_backoff_max = 30.0
```

### 为什么放在 Orchestrator 而不是单个工具里

- 统一策略：所有工具自动获得自愈能力，无需每个工具自己实现
- 可观测：Telemetry 在进程内聚合所有工具的失败/恢复情况
- 可关闭：一个配置开关即可全局禁用

## 十一、设计取舍

| 决策 | 选择 | 理由 |
|---|---|---|
| MCP | 标准协议 | 生态丰富 |
| Skill | Markdown | 低门槛，非程序员也能写 |
| CLI-Anything harness | SKILL.md + run.py | 无需改代码即可包装第三方软件 |
| Plugin | 命令管理 | 用户友好 |
| LSP | 标准 LSP | 复用语言生态 |
| Hook | 事件驱动 | 解耦 |
| Self-Healing | Orchestrator 层统一包装 | 所有工具无侵入获得自愈能力 |
