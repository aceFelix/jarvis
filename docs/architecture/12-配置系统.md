## 二、四文件分层配置合并

### 优先级（后者覆盖前者）

```
1. 内置默认值 (Settings dataclass)
       ▼
2. configs/settings.toml (项目级通用配置，随仓库分发)
       ▼
3. configs/models.toml (项目级模型域，同层覆盖上一项)
       ▼
4. ~/.jarvis/settings.toml (用户级通用配置，自动创建)
       ▼
5. ~/.jarvis/models.toml (用户级模型域，同层覆盖上一项)
       ▼
6. 环境变量 (JARVIS_* / 厂商专属 *_API_KEY，由 env.py 处理)
       ▼
7. API Key 系统 keyring (仅 api_key，env.py 兜底)
       ▼
8. CLI 参数 (--model / --provider / --api-key，main.py 处理)
```

### 配置查找策略

[load_settings()](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/config/settings.py#L301)：

```python
def load_settings(workdir: str | None = None) -> Settings:
    cwd = Path(workdir or os.getcwd()).resolve()
    _pkg_root = Path(__file__).resolve().parent.parent.parent

    s = Settings(workdir=str(cwd))

    # 2. 项目级 settings.toml（找不对则回退 agent/configs/*.example.toml）
    project_cfg = cwd / "configs" / "settings.toml"
    s = _apply_toml(s, _read_toml(project_cfg))
    # 2b. 项目级同层 models.toml（模型域）
    s = _apply_toml(s, _read_toml(models_path_for(project_cfg)))

    # 3. 用户级 settings.toml（兼容 ~/.my-agent/）
    # 先跑 schema 迁移，再把模型域拆分到同层 models.toml（幂等）
    user_cfg, user_models_cfg = user_config_paths()
    auto_split_user_config(user_cfg)
    s = _apply_toml(s, _read_toml(user_cfg))
    # 3b. 用户级 models.toml（同层覆盖 settings.toml，用户级整体覆盖项目级）
    s = _apply_toml(s, _read_toml(user_models_cfg))

    # 4. 环境变量（内部含 keyring 兜底）
    return apply_env_overrides(s)
```

**为什么分层**：
- 项目级：随仓库分发，提供默认值
- 用户级：个人偏好，持久化（如 last_model、custom_models）
- 同层两个文件：模型域（含密钥、程序回写）与通用域隔离，互不牵连
- 环境变量：CI/CD、容器化部署

> `user_config_paths()` 成对返回 settings/models 路径，两者必须同目录：
> 目录优先 `~/.jarvis`，仅当 `~/.jarvis/settings.toml` 不存在且 `~/.my-agent/settings.toml`
> 存在时才用旧目录（否则会出现「settings 读老的、models 读新的」而模型配置失效）。

### 上下文压缩

```python
context_compaction: bool = True
context_window: int = 128000  # 模型窗口大小（token），换模型时同步修改，勿设 0
compact_ratio: float = 0.5    # 触发比例（占窗口百分比）
compact_refreeze_growth: float = 1.25  # 防抖：冻结后总量增长不足此倍数不重复压缩
compact_max_output_tokens: int = 2048  # 压缩摘要请求的输出 token 上限
tool_result_keep_recent: int = 4  # 工具结果折叠时保留最近 N 条完整输出
```

自动压缩触发条件（唯一机制，比例模式）：

- 总 token（冻结摘要 + 活跃窗口 + system prompt）≥ `context_window × compact_ratio` 时才触发；未超比例绝不压缩，用满窗口前半程。
- 附带防抖：总量较上次冻结后增长不足 `compact_refreeze_growth` 倍不重复压缩，避免窗口配置过小时每轮白压。
- 旧的 `compaction_threshold`（绝对阈值）与 `keep_recent_messages`（可配保留条数）已移除：保留条数固定为内部默认 6。

## 八、last_model 持久化

### 为什么持久化

用户切换模型后，下次启动自动恢复上次选择。

### 实现

- `last_model` 存在 `~/.jarvis/models.toml` 顶层（由 `models_config.upsert_last_model`
  经 `upsert_top_scalar` 写入，始终落在顶层键区，不会掉进子表）
- 启动时若 `last_model` 存在，覆盖 `model`
- 切换模型时调用 `save_last_model()` 持久化

### 关联字段

切换模型时一起持久化：
- `last_model`
- `provider` / `api_format` / `base_url` / `api_key`
- `default_provider` / `default_api_format` / `default_base_url` / `default_api_key`（原始值）

**为什么存 default_*：切回内置模型时用这些值重建 provider，避免停留在自定义模型配置上。

### 配置结构


`_apply_toml()` 解析 `models.toml` 的 `[llm.custom_models]` 表到 `settings.custom_models` dict。
单条结构（由 `upsert_custom_model` 写入）：`name` / `base_url` / `api_key` /
`provider_type` / `model_type` / `vendor`；读取时把 `provider_type` 归一化为 `api_format`
（两者均可手写），缺 `provider` 时按 `api_format` 推断 vendor。

### 故障转移

`vendor_fallback` 设置后，主模型失败时按 vendor 查找备选：

```python
for name, cfg in self._custom_models.items():
    if cfg.get("vendor") == vendor:
        # 重建 provider，切换模型
        ...
```

## 十、模型域拆分（models.toml）

### 边界

| 归属 `models.toml` | 留在 `settings.toml` |
|---|---|
| 12 个模型域顶层键：`provider` / `api_format` / `model` / `last_model` / `api_key` / `base_url` / `dashscope_api_key` / `max_tokens` / `temperature` / `enable_thinking` / `thinking_budget` / `vendor_fallback` | 运行时（`workdir` / `permission_mode` / `max_iterations`）、语音 `[tts]` `[stt]` `[voice]` `[realtime_talk]`、`[context]`、`[memory]`、`[skills]` `[mcp]` `[plugins]` `[cli_anything]`、`[email]`、`[lsp]`、`[daemon]` `[monitor]` `[deadline]` `[calendar]`、`[sandbox]` `[tools]` `[profile_bridge]` 等 |
| `[llm]` / `[llm.models]` / `[llm.custom_models.*]` | `[tts.custom_voices]`（音色仍属语音域） |

> `dashscope_api_key` 归模型域（[realtime_talk] 的 api_key 映射而来），与 LLM 密钥同源。

### 读写实现（models_config.py）

- 路径：`models_path_for(settings_path)` 同目录换名；用户级由 `user_config_paths()` 成对给出
- 读写：`read_toml_text` / `write_toml_text`（统一 `\n` 处理，按原文件换行符还原，不写 BOM）
- 写入：`upsert_top_scalar`（顶层键替换/补写）、`upsert_table_block`（段整块替换，
  段名归一化去方括号，注释保留）、`upsert_custom_model` / `upsert_last_model` /
  `save_init_model` / `remove_custom_model`
- 迁移：`split_model_config` / `auto_split_user_config`（幂等；仅首次创建 `.bak`；
  失败静默 + 诊断日志，不阻塞启动）

### 幂等拆分规则

1. 文件头注释（与后续内容有空行分隔）留在原文件；紧贴第一个块的注释仍随块搬走；
2. 块级归属：前导注释/空行跟随其后的顶层键或段；块末的「空行 + 注释」交还下一块，
   避免把下一段的说明搬错文件；
3. 模型块搬入 `models.toml` 并重排（顶层键在前、段在后），保留原分组空行。

### 兼容性

- 老配置把模型键留在 `settings.toml`：`_apply_toml` 照常读取（同层多文件按顺序覆盖，语义不变）
- 老路径 `~/.my-agent/`：仅当 `~/.jarvis/settings.toml` 缺失且 `~/.my-agent/settings.toml` 存在时才启用
- `.gitignore` 忽略 `configs/models.toml`（含明文密钥，永不入库）；随包分发模板为 `agent/configs/models.example.toml`

## 十三、配置覆盖工具与引导命令

### with_overrides

```python
def with_overrides(self, **kwargs) -> Settings:
    """返回用 kwargs 覆盖部分字段的新 Settings（None 值不覆盖）。"""
    data = {k: v for k, v in kwargs.items() if v is not None}
    return Settings(**{**self.__dict__, **data})
```

用于子代理等场景创建配置变体。

## 十四、设计取舍

| 决策 | 选择 | 理由 |
|---|---|---|
| 配置格式 | TOML | Python 3.11+ 内置支持 |
| 合并层级 | 四文件（settings/models × 项目/用户）+ env + keyring | 灵活覆盖 |
| 持久化 | 用户级文件 | 跨会话保持 |
| 环境变量 | env.py 独立模块（A-03） | 职责单一，易维护 |
| 模型持久化 | model_registry.py 薄封装 + models_config.py 实现 | 与加载逻辑解耦 |
| 模型域拆分 | 独立 `models.toml`（同层成对加载） | 程序回写与密钥隔离，避开顶层键顺序陷阱 |
| API Key | keyring 加密存储（S-01） | 减少明文暴露面 |
| 敏感字段 | mask.py 统一脱敏（S-03） | 展示场景一致安全 |
| last_model | 顶层存储 | 早期存 [llm] 段导致不加载 |
| custom_models | [llm.custom_models] | 结构化存储 |
