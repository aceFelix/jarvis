# 04 - 五层权限系统

J.A.R.V.I.S 的权限系统是安全核心，采用 **fail-closed** 原则，五层管线层层把关。

## 一、设计哲学

> **fail-closed**：所有安全属性默认为"危险"侧，工具必须显式声明自己安全。

- `is_read_only` 默认 False（假设会写）
- `is_concurrency_safe` 默认 False（假设不能并行）
- `check_permissions` 默认返回 ASK
- 判定合并规则：`DENY > ASK > ALLOW`（取更严格）

## 二、五层管线

[checker.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/permissions/checker.py#L88-L119) 的 `check()` 方法：

```
工具调用请求
    │
    ▼
0. 输入校验（validate_input）
    │ 不通过 → DENY
    ▼
1. 工具特判（tool.check_permissions）
    │ 工具最懂自己
    ▼
2. 路径守护（path_guard）
    │ 永远生效，返回 DENY（敏感目录）
    ▼
3. 模式覆写（mode）
    │ plan/yolo/accept_edits 策略
    ▼
4. 规则匹配（rules）
    │ allow/deny/ask 三态
    ▼
5. 默认 ASK
    │ fail-closed，没 allow 命中就问用户
    ▼
最终判定：ALLOW / DENY / ASK
```

### 判定合并规则

```python
_SAFETY_RANK = {ALLOW: 0, ASK: 1, DENY: 2}

def _stricter(a, b) -> PermissionResult:
    return a if _SAFETY_RANK[a.behavior] >= _SAFETY_RANK[b.behavior] else b
```

模式覆写特殊处理（`_relax_by_mode`）：yolo 可放宽 ASK 为 ALLOW，但**不可放宽 DENY**。

## 四、L1 工具特判

```python
# 1. 工具特判（工具最懂自己）
result = tool.check_permissions(args, ctx)
```

每个工具可重写 `check_permissions()` 实现自己的权限逻辑。例如：
- `BashTool` 解析命令前缀做白名单匹配
- `FileReadTool` 可能对某些路径返回 ASK
- `FileWriteTool` 检查是否覆盖重要文件

默认返回 ASK（最安全）。

## 五、L2 路径守护

[path_guard.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/permissions/path_guard.py) 保护敏感目录：

```python
# 永远禁止写入的危险目录
DANGEROUS_DIRS = [
    ".ssh", ".aws", ".gnupg",        # 凭证
    "system32", "/etc", "/usr",      # 系统
    "Windows", "System32",
]

def is_dangerous_write_path(workdir, raw_path) -> tuple[str, str]:
    """返回 ("deny"/"ask"/"safe", reason)"""
```

### 守护逻辑

1. **绝对禁止写入**（返回 `deny`）：`.ssh`/`.aws`/`.gnupg` 等凭证目录、系统目录
2. **工作目录外**（返回 `ask`）：提醒用户
3. **符号链接逃逸**（返回 `deny`）：防止通过软链接绕过守护

### 符号链接检测

```python
def is_symlink_escape(workdir, raw_path) -> tuple[bool, str]:
    """检测符号链接是否逃出工作目录。"""
```

**为什么**：攻击者（或 AI）可通过创建指向 `/etc/passwd` 的软链接绕过路径检查。

## 六、L3 命令分类

[shell_classifier.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/permissions/shell_classifier.py) 把 shell 命令分三级：

| 分类 | 含义 | 示例 |
|---|---|---|
| `readonly` | 只读，安全 | `ls`/`cat`/`git status`/`pwd` |
| `dangerous` | 危险，需确认 | `rm -rf`/`curl|sh`/`sudo`/`mkfs` |
| `unknown` | 未知，默认 ASK | 其他 |

### 危险命令识别

```python
DANGEROUS_PATTERNS = [
    r"rm\s+-rf\s+/",           # rm -rf /
    r"curl\s+.*\|\s*sh",       # curl | sh
    r"sudo\s+",                # sudo
    r"mkfs",                   # 格式化
    r"dd\s+.*of=/dev/",        # dd 写设备
    r">\s*/dev/sda",           # 重定向到设备
]
```

### 只读白名单

## 七、L4 权限模式

[modes.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/permissions/modes.py) 定义四种模式：

| 模式 | 行为 | 适用场景 |
|---|---|---|
| `default` | 逐次确认 | 谨慎使用 |
| `plan` | 只读规划，禁止写操作 | 分析/审查 |
| `accept_edits` | 文件编辑自动放行 | 信任的批量编辑 |
| `yolo` | 非 DENY 全部放行 | 完全信任自动化 |

### 模式策略

```python
def _apply_mode(self, tool, args, ctx) -> PermissionResult | None:
    if self._mode == PermissionMode.PLAN:
        if tool.name in PLAN_ALLOWED_TOOLS or tool.is_read_only(args):
            return PermissionResult.allow("plan 模式放行只读工具")
        return PermissionResult.deny(f"plan 模式禁止写操作: {tool.name}")

    if self._mode == PermissionMode.ACCEPT_EDITS:
        if tool.name in AUTO_ALLOW_EDIT_TOOLS:
            return PermissionResult.allow("accept_edits 模式放行文件编辑")
        return None  # 其他工具交给后续判定

    if self._mode == PermissionMode.YOLO:
        return PermissionResult.allow("yolo 模式自动放行")

    return None
```

**关键**：yolo 可放宽 ASK 为 ALLOW，但**不可放宽 DENY**（路径守护/危险命令/deny 规则永远生效）。

## 八、L5 规则匹配

[rules.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/permissions/rules.py) 支持 `allow`/`deny`/`ask` 三态规则：

### 规则格式

```yaml
rules:
  - pattern: "Bash(git *)"          # 允许所有 git 命令
    value: allow
  - pattern: "Bash(rm -rf *)"       # 拒绝 rm -rf
    value: deny
  - pattern: "Read(~/.ssh/*)"       # 拒绝读 .ssh
    value: deny
  - pattern: "Write(/etc/*)"        # 询问写 /etc
    value: ask
```

### 匹配机制

[PermissionMatcher](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/core/tool.py#L99-L131) 支持 fnmatch 通配符：

```python
matcher.matches("Bash(git *)")  # 匹配 Bash 工具的 git 命令
matcher.matches("Read(src/**)") # 匹配 Read 工具读 src 目录
```

- 工具提供 `prepare_permission_matcher()` 解析入参（如 BashTool 解析命令前缀）
- 按**优先级 + deny 优先**顺序找第一条命中

### 默认规则

`load_default_rules()` 始终生效：
- `rm -rf /` → deny
- `.ssh`/`.aws`/`.gnupg` 写 → deny
- 系统目录写 → deny

## 九、完整校验流程示例

假设用户在 yolo 模式下，AI 调用 `Bash(command="rm -rf /tmp/test")`：

```
1. validate_input → pass
2. tool.check_permissions → ASK（BashTool 默认）
3. path_guard → safe（/tmp 不在危险目录）
4. mode (yolo) → ALLOW（放宽 ASK）
5. 规则匹配 → 命中 "Bash(rm -rf *)" → DENY
   _stricter(ALLOW, DENY) → DENY
6. 最终：DENY（拒绝执行）
```

假设 AI 调用 `Bash(command="ls -la")`：

```
1. validate_input → pass
2. tool.check_permissions → ASK
3. path_guard → safe
4. mode (yolo) → ALLOW
5. 规则匹配 → 命中 "Bash(ls *)" → ALLOW
   _stricter(ALLOW, ALLOW) → ALLOW
6. 最终：ALLOW（允许执行）
```

## 十一、设计取舍

| 决策 | 选择 | 理由 |
|---|---|---|
| 默认值 | fail-closed | 安全侧优先 |
| 合并规则 | DENY > ASK > ALLOW | 取更严格 |
| 模式覆写 | 不可放宽 DENY | 硬约束不可绕过 |
| 路径守护 | 永远生效 | 防止模式放宽导致危险 |
| 规则格式 | fnmatch 通配 | 灵活匹配 |
| Shell 分类 | 正则+白名单 | 覆盖常见危险命令 |
