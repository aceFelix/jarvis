## 一、解决什么问题

五层权限管线（见 [04-权限系统](04-权限系统.md)）只能回答"**允不允许**"，
回答不了管家形态的两个问题：

1. **这次调用值不值得打断用户**——允许 ≠ 现在就该问；
2. **人不在场时该不该做**——ASK 在无人时应转为"入库待批"而不是干等。

W1 判断层挂在管线结论之后，作为统一闸门 `policy_gate()`，由四个确定性
零件组成（刻意不引入 LLM 判断——权限路径必须可解释、可审计、可复现）：

| 零件 | 文件 | 职责 |
|---|---|---|
| 策略引擎 | `engine.py` | policy.yaml 四态规则（allow/ask/deny/dry_run），mtime 热重载 |
| 授权租约 | `lease.py` | 有限期、有限范围的免打断授权，到期自动失效 |
| 打扰预算 | `budget.py` | 主动播报的五步闸门：额度/静默时段/聚合窗口/重要度 |
| 共享状态 | `state.py` | away 标志 + 待批清单，跨进程 JSON 落盘 |
| 统一闸门 | `__init__.py` | `policy_gate()` 合并次序 + `init_policy(settings)` 注入 |

## 二、合并次序（fail-closed）

```
PermissionChecker.check（五层管线结论 base）
      │
      ▼
① 策略引擎 evaluate ──▶ apply_to 合并：
      │        · base DENY 原样返回（任何层不放宽 DENY）
      │        · deny → DENY；allow 仅当 base ASK 时放宽
      │        · dry_run / ask → 收紧为 ASK（policy_escalated=True）
      ▼
② 授权租约：只放宽"管线原生 ASK"
      │        · 策略显式收紧（escalated）时租约不生效
      │        · 命中 = 工具名 fnmatch ∧（未限路径 ∨ path_within 命中）
      ▼
③ away 分流：仍为 ASK 的调用
             · 入待批清单（~/.jarvis/pending_approvals.json）
             · 本次 DENY（"回来 /back 呈批"）
```

关键语义与既有管线对齐：**规则 ALLOW 放宽不了工具默认 ASK**
（`_stricter` 只收紧），因此放宽走独立的租约/策略通道，不塞进 RuleSet，
避免"配了 allow 不生效"的口径混乱。未命中任何规则时原样回落管线结论，
`policy_enabled=false` 时零介入（权限零回归）。

## 四、打扰预算（Horvitz 注意力模型的确定性近似）

`NotifyBudget.gate()` 五步顺序：

1. 非静默时段先**冲刷积压**（静默期入库的多条聚合成一条播出）；
2. 静默时段（支持跨午夜，如 23:00-07:00）只入库不播；
3. 聚合窗口（默认 300s）内同源事件（dedup_key）合并抑制；
4. 重要度 = 来源权重 × 紧迫度 × 相关性 × 历史接受率，低于门槛入库；
5. 当日播报超 `daily_max` 上限 suppress。

历史接受率由 `record_accept(source, accepted)` 滑动更新（初始 1.0），
是"越用越懂你"反馈闭环的入口。接入点：`ProactiveEngine._dispatch_notify`
为唯一播报出口（简报/截止日期/日历三源统一过闸）；budget 异常时降级
直接播，不因闸门拖垮提醒。

## 五、跨进程状态与配置

CLI / serve(hub) / daemon 是不同进程，全部状态落盘 `~/.jarvis/`，
tmp + `os.replace` 原子写、mtime 缓存读：

| 文件 | 内容 |
|---|---|
| `policy.yaml` | 策略规则（模板 `agent/configs/policy.example.yaml`） |
| `leases.json` | 授权租约（读到过期顺带 GC） |
| `policy_state.json` | away 标志 + 最近活动时间（60s 节流） |
| `pending_approvals.json` | 待批清单（上限 50，丢最旧） |
| `notify_state.json` | 预算当日计数 / 待发队列 / 接受率统计 |

settings.toml 配置域（解析见 `config/settings.py` [policy] 节）：

```toml
[policy]
enabled = true            # 总开关（false = 全回落既有管线）
path = ""                 # policy.yaml 位置；空 = ~/.jarvis/policy.yaml
away_idle_minutes = 0     # 0 = 仅认手动 /away；>0 启用空闲推断

[policy.notify_budget]
enabled = true
daily_max = 10
quiet_hours = "23:00-07:00"
aggregate_window_s = 300
min_salience = 0.3
```

启动接线：`main()` 在最终 settings 定型后调 `init_policy(settings)`；
hub 构造 `ProactiveEngine` 时传 `get_budget()` 单例。

## 六、命令面

| 命令 | 处理器 | 说明 |
|---|---|---|
| `/away` | `policy_commands.handle_away` | 手动无人值守；ASK 入待批清单转 DENY |
| `/back` | `handle_back` | 解除并取回清单给简报（本期不自动重放，留 W3） |
| `/pending` | `handle_pending` | 查看待批清单（不清空） |
| `/lease <tools> [路径] [分钟]` | `handle_lease` | 签发租约（缺省 120 分钟） |
| `/lease list` / `/lease revoke <id>` | 同上 | 查看 / 撤销（撤销即回逐次确认） |

空闲推断 away 只认时间阈值；视觉（VisionWatcher 人脸离开）事件源接入
留给阶段 9（W2），本期不动摄像头。
