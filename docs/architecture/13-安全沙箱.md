# 13 - 安全沙箱

安全沙箱是 J.A.R.V.I.S 的进程级安全执行环境（P3-8 新增），在权限系统之上提供**资源限制 + 文件保护 + 审计追踪**三重保障。

## 一、设计哲学

> 权限系统决定"能不能执行"，沙箱决定"在什么约束下执行"。

- **透明执行**：命令不知道自己被限制了，不改变命令本身
- **进程级约束**：内存/CPU/子进程数/超时，超限强制终止整个进程树
- **跨平台**：Windows / macOS / Linux 各有原生实现，不依赖第三方库
- **渐进式安全**：低风险直接放行，中风险沙箱内自动放行，高风险沙箱+快照，极高风险仍需用户确认

## 三、四级风险评分

[RiskScorer](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/core/sandbox/risk_scorer.py) 将命令/操作分为四级：

| 等级 | 含义 | 示例 | 沙箱策略 |
|---|---|---|---|
| `LOW` | 只读操作 | `ls`/`cat`/`grep`/`git status` | 直接放行，无需沙箱 |
| `MEDIUM` | 有副作用但可逆 | `git commit`/`npm install`/`pip install` | 沙箱开启时自动放行（沙箱内执行）；未开启时 ASK |
| `HIGH` | 不可逆或影响范围大 | `rm`/`del`/`git push --force` | 强制沙箱 + 文件快照保护 |
| `CRITICAL` | 系统级破坏性 | 格式化/注册表修改/系统服务操作 | 沙箱 + 快照 + 用户确认（即使沙箱开启） |

### RiskLevel 属性

```python
class RiskLevel(IntEnum):
    LOW = 0
    MEDIUM = 1
    HIGH = 2
    CRITICAL = 3

    @property
    def needs_sandbox(self) -> bool:    # >= MEDIUM
    @property
    def needs_snapshot(self) -> bool:     # >= HIGH
    @property
    def needs_confirm(self) -> bool:    # >= CRITICAL（即使沙箱开启也需确认）
```

### 与权限系统的关系

```
权限系统（五层管线）→ 决定 ALLOW / DENY / ASK
        │
        ▼ ALLOW 或 沙箱自动放行
沙箱风险评分 → 决定执行约束级别
        │
        ▼
沙箱执行器 → 施加资源限制
        │
        ▼
文件快照 → HIGH+ 操作前备份
        │
        ▼
审计日志 → 记录所有操作
```

## 四、跨平台沙箱执行器

[SandboxExecutor](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/core/sandbox/executor.py) 根据平台选择原生机制：

| 平台 | 机制 | 实现方式 |
|---|---|---|
| Windows | Job Object | ctypes 调用 Win32 API（`CreateJobObject` + `AssignProcessToJobObject`） |
| Linux | resource.setrlimit | 标准库 `resource` 模块（RLIMIT_AS/RLIMIT_CPU/RLIMIT_NPROC） |
| macOS | sandbox-exec + setrlimit | Apple 沙箱配置文件 + resource 限制 |

### 资源限制

```python
@dataclass
class SandboxConfig:
    enabled: bool = False
    max_memory_mb: int = 512           # 最大内存（MB）
    max_cpu_seconds: int = 60          # 最大 CPU 时间（秒）
    max_processes: int = 10            # 最大子进程数
    timeout: int = 120                 # 总超时（秒，含 I/O 等待）
    block_network: bool = False        # 是否阻断网络
    allow_write_paths: list[str] = []  # 允许写入的路径
    deny_write_paths: list[str] = []   # 禁止写入的路径
    auto_allow_medium_risk: bool = True  # 沙箱开启时自动放行中等风险
    excluded_commands: list[str] = []    # 不走沙箱的命令
```

### Windows Job Object 关键特性

- `KILL_ON_JOB_CLOSE`：Job 关闭时自动终止所有子进程（防止孤儿进程）
- `JOB_OBJECT_LIMIT_PROCESS_MEMORY`：内存上限
- `JOB_OBJECT_LIMIT_ACTIVE_PROCESS`：子进程数上限
- `JOB_OBJECT_LIMIT_PROCESS_TIME`：CPU 时间上限

### 网络隔离

`block_network=True` 时通过设置代理环境变量阻断网络：

```python
env["HTTP_PROXY"] = "http://127.0.0.1:1"   # 不可达代理
env["HTTPS_PROXY"] = "http://127.0.0.1:1"
env["NO_PROXY"] = ""
```

## 五、文件快照与回滚

[FileGuard](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/core/sandbox/file_guard.py) 在高风险操作前创建文件备份：

### 工作流程

```
1. 操作前：guard.snapshot("config.toml", reason="修改配置")
2. 执行操作（沙箱内）
3. 操作失败/用户撤销：guard.rollback(snap_id)
```

### 快照存储

```
~/.jarvis/sandbox_snapshots/
├── 20260721_153000_a1b2c3/
│   ├── manifest.json          # 快照元数据
│   └── config.toml            # 备份文件
└── 20260721_160000_d4e5f6/
    ├── manifest.json
    └── src/                   # 目录备份
```

### 设计约束

| 约束 | 值 | 说明 |
|---|---|---|
| 大文件阈值 | 50MB | 超过此大小只记录元数据不备份内容 |
| 最大快照数 | 20 | 超出自动清理最旧的 |
| 快照粒度 | 文件/目录 | 支持单文件和整目录 |

### SnapshotEntry 结构

```python
@dataclass
class SnapshotEntry:
    original_path: str       # 原始路径
    backup_path: str         # 备份路径（空=大文件未备份）
    is_directory: bool
    existed: bool            # False=新建文件（回滚时删除）
    size: int
    mtime: float
```

## 六、审计日志

[SandboxAuditor](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/core/sandbox/audit.py) 记录所有沙箱操作：

### 记录事件

| 事件类型 | 触发时机 |
|---|---|
| `execution` | 命令执行（沙箱内/外） |
| `violation` | 资源超限事件 |
| `snapshot` | 文件快照创建 |
| `rollback` | 文件回滚 |
| `permission` | 权限决策（自动放行/用户确认/拒绝） |

### 存储

- 格式：JSON Lines（`~/.jarvis/sandbox_audit.jsonl`）
- 自动轮转：超过 500 条时截断旧记录
- 命令截断：过长命令只保留前 200 字符

### AuditEntry 结构

```python
@dataclass
class AuditEntry:
    timestamp: float
    event_type: str          # execution/violation/snapshot/rollback/permission
    command: str
    risk_level: str
    sandboxed: bool
    exit_code: int | None
    timed_out: bool
    resource_exceeded: bool
    snapshot_id: str
    permission_decision: str  # allow/deny/ask/auto_allow_sandbox
    detail: str
    cwd: str
```

### 全量工具调用审计（S-02）

[ToolAuditor](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/core/audit/tool_auditor.py) 扩展审计覆盖**所有工具调用**（而不仅是沙箱命令），
特别记录 yolo 模式下自动放行的写操作：

- **写操作重点审计**：`Bash` / `FileWrite` / `FileEdit` / `DeleteFile` 等
- **记录字段**：工具名、输入参数（截断）、权限模式（yolo/ask/default）、耗时、成功/失败

## 七、与 Bash 工具的集成

沙箱在 `BashTool` 执行流程中的位置：

```
BashTool.call(command)
    │
    ├─ 1. shell_classifier.classify(command) → readonly/dangerous/unknown
    ├─ 2. risk_scorer.score(command) → LOW/MEDIUM/HIGH/CRITICAL
    │
    ├─ 3. 沙箱决策：
    │     ├─ LOW → 直接执行
    │     ├─ MEDIUM + sandbox.enabled → 沙箱内执行（自动放行）
    │     ├─ HIGH → 沙箱 + FileGuard.snapshot()
    │     └─ CRITICAL → 沙箱 + 快照 + 用户确认
    │
    ├─ 4. SandboxExecutor.run(command, config)
    │     └─ 施加资源限制 → 执行 → 超时/超限强制终止
    │
    ├─ 5. 审计记录
    └─ 6. 返回结果
```

## 九、设计取舍

| 决策 | 选择 | 理由 |
|---|---|---|
| 沙箱机制 | 平台原生 | 不引入第三方依赖，稳定可靠 |
| 风险分级 | 四级 | 渐进式安全，不过度打扰用户 |
| 文件保护 | 快照/回滚 | 高风险操作可撤销 |
| 审计 | JSON Lines | 轻量、可 grep、易轮转 |
| 默认关闭 | 是 | 大多数用户不需要，避免性能开销 |
| 网络隔离 | 代理环境变量 | 简单有效，不需要防火墙规则 |
| 大文件 | 只记录元数据 | 避免快照占用过多磁盘 |
| 与权限系统关系 | 互补 | 权限管"能不能"，沙箱管"怎么跑" |
