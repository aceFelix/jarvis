# 05 - 工具系统

J.A.R.V.I.S 的能力来自工具。工具是"带元数据 + 权限 + 执行 + 渲染"的对象，不是函数。

## 一、Tool 协议

详见 [02-Agent运行时](02-Agent运行时.md#四tool-协议)。核心要点：

- **fail-closed**：`is_read_only`/`is_concurrency_safe`/`is_destructive` 默认全 False
- **权限默认 ASK**：新工具不显式声明就要求用户确认
- **max_result_chars**：结果超长自动截断+落盘（默认 20000 字符）

### LoadSkill 工具详解

[LoadSkillTool](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/tools/extensions/skill_tool.py) 是 P 系列性能优化新增的核心工具，配合 Skill 按需加载机制：

```python
class LoadSkillTool(Tool):
    """加载技能包的完整指令。

    当你需要某个技能的详细操作规范时，传入技能名加载完整正文。
    技能名在 system prompt 的"可用技能"摘要列表里列出。
    """
    name = "LoadSkill"
    description = "加载技能包的完整指令。当你需要某个技能的详细操作规范时，..."
    input_schema = {
        "type": "object",
        "properties": {
            "skill_name": {
                "type": "string",
                "description": "要加载的技能名（system prompt 技能摘要列表里的名字）",
            },
        },
        "required": ["skill_name"],
    }
    deferred = False  # 核心工具，始终携带（不被 ToolSearch 延迟加载）
```

**为什么是核心工具**：Skill 摘要里告诉模型"调用 LoadSkill 工具传入技能名加载"，如果 LoadSkill 本身被延迟加载，模型连加载工具都找不到，形成死循环。

**调用流程**：
1. 模型看到 system prompt 里的 skill 摘要列表
2. 需要某个 skill 的详细规范时调用 `LoadSkill(skill_name="python-expert")`
3. 工具返回完整正文（含 description/when_to_use/content）
4. 模型在下一轮迭代中按 skill 规范执行

**未找到时的处理**：返回可用 skill 名列表，帮助模型纠正技能名。

详见 [10-扩展生态 - Skill 按需加载机制](10-扩展生态.md#三skill-技能包按需加载机制)。

### P1 GUI 增强设计

阶段二 GUI 工具只能进行基础坐标点击。P1 增强后覆盖以下场景：

1. **拖拽**：`MouseDrag` 支持从一个坐标拖拽到另一个坐标，用于文件移动、滑块、调整大小等。
2. **右键菜单**：`MouseClick` 的 `button=right` 支持右键，弹出菜单后可配合 `KeyTap` 的方向键选择。
3. **等待目标**：`WaitFor` 基于 pyautogui 模板匹配轮询等待按钮/弹窗出现，或等待画面发生变化，避免模型盲目重试。
4. **多窗口协调**：`WindowRect` 获取窗口屏幕绝对坐标，`WindowClick` 基于窗口相对坐标点击，窗口移动后仍准确。
5. **视觉定位**：`VisualClick` 用模板匹配在屏幕或指定区域找图标/按钮，找到后自动点击中心，降低对绝对坐标的依赖。

设计取舍：
- 视觉定位优先用 pyautogui 内置的 `locateOnScreen`，无需额外依赖 opencv-python。
- 所有 GUI 操作默认 ASK 权限；只读工具（GetScreenSize/ScreenShot/WindowList/WindowRect/WaitFor）自动放行。
- GUI 操作 `is_concurrency_safe=False`，编排器不会并行执行 GUI 工具，避免光标竞争。

## 四、Bash 工具详解

[bash.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/tools/bash.py) 是最复杂的工具之一：

### 执行流程

1. **命令分类**：调 `shell_classifier.classify(command)` 判断 readonly/dangerous/unknown
2. **权限校验**：`prepare_permission_matcher()` 解析命令前缀（如 `git`/`npm`）
3. **Shell 选择**：Windows 上自动检测 Git Bash（跳过 WSL relay），用 `bash -c` 执行；其他平台用 `/bin/bash -c`
4. **执行**：subprocess 异步执行，支持超时和 `cwd` 参数
5. **输出处理**：
   - stdout/stderr 合并
   - 超长截断（max_result_chars）
   - 非 UTF-8 字符容错
6. **返回**：`ToolResult(data=output_str)`

### Windows Git Bash 支持

```python
# 自动检测 Git Bash（跳过 System32 下的 WSL relay）
bash_path = self._find_bash()
if bash_path:
    shell_args = [bash_path, "-c", command]
else:
    shell_args = ["cmd", "/c", command]  # 回退
```

- 优先检查 `D:\SoftwareDevelopmentKit\Git\bin\bash.exe` 等常见路径
- 跳过 `C:\Windows\System32\bash.exe`（WSL relay，子进程执行会失败）
- 支持 `cwd` 参数指定工作目录
- Unix 风格路径（`/e/...`）原生可用

### 危险命令拦截

```python
# classify_shell 返回 dangerous → check_permissions 返回 DENY
if classify_shell(command) == "dangerous":
    return PermissionResult.deny("危险命令")
```

## 五、ScreenShot 工具详解

[system/screen.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/tools/system/screen.py) 返回多模态结果：

```python
async def call(self, args, ctx) -> ToolResult:
    import pyautogui
    screenshot = pyautogui.screenshot()
    # 转 JPEG base64
    buf = io.BytesIO()
    screenshot.save(buf, format="JPEG", quality=85)
    data = base64.b64encode(buf.getvalue()).decode()
    return ToolResult(
```

## 七、并发安全分组

```python
safe = [p for p in pending if p.tool.is_concurrency_safe(p.tool_use.input)]
unsafe = [p for p in pending if not p.tool.is_concurrency_safe(p.tool_use.input)]

# 串行组顺序执行
for p in unsafe:
    content = await self._run_one(p, ctx)

# 并行组用信号量限流（默认 5 并发）
sem = asyncio.Semaphore(self._max_concurrency)
gathered = await asyncio.gather(*(run_safe(p) for p in safe))
```

**为什么这样设计**：
- 文件读写不能并行（竞争）
- Web 请求/glob/grep 可以并行
- 工具自己声明并发安全性

## 九、如何添加新工具

### 方式 1：继承 Tool 基类

```python
from agent.core.tool import Tool
from agent.core.result import ToolResult

class MyTool(Tool):
    name = "MyTool"
    description = "做某件事"
    input_schema = {
        "type": "object",
        "properties": {
            "param": {"type": "string", "description": "参数"}
        },
        "required": ["param"]
    }

    async def call(self, args, ctx) -> ToolResult:
        result = do_something(args["param"])
        return ToolResult(data=result)

    # 可选：声明安全属性
    def is_read_only(self, args) -> bool:
        return True  # 只读，安全

    def is_concurrency_safe(self, args) -> bool:
        return True  # 可并行
```

### 方式 2：注册到 Registry

```python
from agent.core.tool import build_default_registry

registry = build_default_registry()
registry.register(MyTool())
```

### 方式 3：CLI-Anything harness（无需写 Python 代码）

在 `~/.jarvis/cli_anything/<id>/` 下放置 `SKILL.md`（描述能力、参数 schema、触发场景），
启动时 `register_dynamic_tools()` 会自动扫描并注册为 `cli_anything__<id>` 工具。

当前已安装 71 个 harness（Blender/GIMP/WPS/Obsidian/FreeCAD/Xmind 等），
通过 `/cli_anything install <id>` 从市场安装。

详见 [10-扩展生态 - CLI-Anything harness](10-扩展生态.md#三cli-anything-harness)。

## 十、设计取舍

| 决策 | 选择 | 理由 |
|---|---|---|
| 工具是对象 | 不是函数 | 带元数据+权限+渲染 |
| 可选依赖 | 静默跳过 | 用户可能只装核心包 |
| 工具加载 | deferred 延迟（需 ToolSearch 发现） | 减少每次请求 schema 的 token 开销 |
| 注册缓存 | @lru_cache（P-03） | 避免重复构建 Registry |
| 并发安全 | 声明式 | 工具自己最懂 |
| 结果截断 | 落盘+预览 | 防 token 爆炸 |
| 图片透传 | 独立通道 | 不受截断影响 |
