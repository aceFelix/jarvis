## 二、shadow git 原理

在 `~/.jarvis/checkpoints/<basename>-<hash12>/git` 建独立 git 目录，通过
`--git-dir` 指向它、`--work-tree` 指向用户工作目录，把用户目录当作这个"影子仓库"
的工作树：

- **不污染用户仓库**：分支 / 暂存区 / 历史完全隔离，非 git 项目目录同样适用；
- **存储按 workdir 指纹定位**（小写规范化路径 sha1 前 12 位 + 可读 basename）：
  `/load` 恢复旧会话、`/rename` 改标题后检查点仍可命中；项目切换后旧目录
  检查点天然隔离（跨目录回滚自然查不到 cid 而失败）；
- **孤儿 commit**：`add -A` → `write-tree` → `commit-tree`（plumbing，无父提交、
  不动 HEAD），每个检查点一条独立 ref `refs/jarvis/ckptNNNNN`——互不牵连，
  配额修剪只删最旧 ref 再 `gc --prune=now`；
- **台账**：`manifest.json` 记 `{id, ref, seq, ts, reason}`，是修剪顺序的依据；
- **排除策略**：shadow 仓库 `info/exclude` 预置重目录（`.venv` / `node_modules` /
  `dist` / `build` / `__pycache__` / `.jarvis` 等），同时天然尊重用户仓库自己的
  `.gitignore`；被忽略的文件不参与快照，恢复时也不会被删除；
- **中文文件名**：`-c core.quotepath=false` 保证 describe 列表可读。

### 回滚语义

检查点 C_i 在用户消息 U_i **发出前**创建（= U_i 这轮改动前的世界）。撤回从
U_i 起的全部消息 → 工作区恢复到 C_i：

```
git read-tree -u --reset <cid>   # index + 工作树整体刷回检查点状态
git clean -fd                    # 删除检查点之后新建的未跟踪文件（不带 -x，
                                 # 被忽略的 node_modules 等不受波及）
```

### 降级规则

`shutil.which("git")` 失败 / `[checkpoint] enabled=false` / 单条 git 命令超时 /
检查点已被配额修剪 → `create()` 返回 `None`、`restore()` 返回 `(False, 原因)`，
调用方据此只提供**对话回退**，文件不动。全部路径静默降级不抛异常。

## 三、检查点绑定与持久化

- REPL（`main.py`）与工作台（`engine.py::_handle_send`）每轮 `loop.run` 之前：
  `cid = mgr.create(reason=消息前 80 字)`，轮末（finally，出错轮次同样绑定）把
  `cid` 写进本轮用户消息 `extra["checkpoint_id"]`；
- `store.py` 的 `_message_to_dict` / `_message_from_dict` 往返 `extra`——旧会话
  文件无此字段默认空 dict，向后兼容；`/load` 后仍可回溯（只要检查点未修剪）；
- 远程通道（手机 / 微信）的轮次不打检查点，其消息撤回自动退化为仅对话回退。

## 四、终端 `/rewind` 联动回滚

`/rewind [n] [--chat-only]`（`core_commands.handle_rewind`）：

1. 仍按"弹 n 条消息"计算范围（保持旧语义）；
2. 非 `--chat-only` 时，在弹出范围内找**最早一条带有效检查点的用户消息**
   （最早 = 回滚幅度最大，覆盖范围内所有轮次的文件修改）；
3. 找到 → `describe(cid)` 列出改动文件清单，询问「是否同时回滚工作区？y/N」：
   y → `mgr.restore(cid)` 成功后再弹消息；N → 仅回退对话；
4. 找不到检查点 / 未启用 / git 缺失 / `--chat-only` → 维持纯对话回退。

CheckpointManager 经 `ctx.extra["checkpoint_mgr"]` 注入 CommandContext，不改命令签名。

## 五、serve 协议（桌面撤回）

| 指令/事件 | 方向 | 参数 → 回执 |
|---|---|---|
| `checkpoint.preview` | 桌面 → serve | `{user_tail_count}` → `{ok, has_checkpoint, checkpoint_id, files, untracked, reason}`（只读不入队） |
| `checkpoint.rewind` | 桌面 → serve | `{user_tail_count, restore_files}` → 入队即返 `{ok:true, pending:true}` |
| `rewound` | serve → 桌面 | `{ok, removed, removed_user, files_restored, reason}`（真实结果，前端据此裁气泡） |

- **定位口径 `user_tail_count`**：从尾部数第 N 条**可见**用户消息
  （`_is_visible_user_message` 只数含非空文本/图片的 user 消息，与桌面气泡同口径）。
  不用 message_id：引擎 emit `user_message` 时后端消息尚未由 query_loop 创建，
  上下文压缩会重写旧消息使绝对索引漂移，而尾部计数不受前缀压缩影响；
- **串行**：`checkpoint.rewind` 在引擎指令队列内执行，与在跑轮次天然排队；
- **原子性**：`restore_files=true` 且文件回滚失败 → 放弃本次撤回（消息也不截断，
  前端保持原样）；成功截断后立即 `_auto_save`，防会话文件残留已撤回内容；
- 桌面确认弹窗展示 `describe` 的改动清单（`git diff --name-status <cid>` +
  `ls-files --others` 的 untracked 列表）。

## 六、桌面撤回交互（jarvis-desktop）

- 用户气泡 hover 显示「撤回」按钮（与复制按钮同排，`ChatArea.tsx`）；
- 点击 → `previewCheckpoint(userTail)` 拉改动清单（reqId 防预览竞态）→
  `RewindDialog` 确认（文件列表 + 「同时回滚工作区文件」复选框，
  `has_checkpoint=false` 时禁用勾选仅提示）→ `rewindMessage` 发指令；
- 裁气泡由 `rewound` 事件驱动：dispatcher 按 `removed_user` 调
  `chatStore.rewindTailFromUser(tail)`（本地发送侧不裁，防双裁）；
- 失败 / 降级提示走 `addSystem`（事件驱动系统消息，非静态 chrome 不走 i18n）。

## 七、与 FileGuard 的分工

| | FileGuard（13-安全沙箱） | CheckpointManager（本模块） |
|---|---|---|
| 粒度 | 单次高风险 bash 命令执行前 | 每轮消息（对话粒度） |
| 手段 | 整目录复制兜底 | shadow git 孤儿 commit |
| 目的 | "这一次操作别把文件搞坏" | "这条消息引发的修改全部撤销" |

两者互不依赖、互不牵连。

## 八、配置

`settings.toml`：

```toml
[checkpoint]
enabled = true          # 总开关（关闭后仅支持对话回退）
max_per_session = 20    # 每会话检查点保留上限（超出修剪最早的）
timeout_seconds = 10    # 单条 git 命令超时（秒）
```

字段映射 `checkpoint_enabled` / `checkpoint_max_per_session` /
`checkpoint_timeout_seconds`，`/config` 展示。

## 十、设计取舍

- **shadow git 而非自建 diff**：零依赖（仅需系统 git）、天然处理增删改/重命名/
  二进制；代价是依赖 git 可执行文件——故全链路优雅降级。
- **孤儿 commit + 独立 ref 而非线性历史**：修剪任意旧检查点不牵断链，无需 rebase；
- **按 workdir 而非会话名存储**：/load、/rename 不失效；跨目录回滚天然被拒
  （不同指纹查不到 cid），符合"不回滚别的目录"的安全预期；
- **尾部计数定位而非消息 id**：对上下文压缩与历史回放重建免疫；
- **已知边界**：不回滚工作区之外的文件（如 `~/.jarvis` 内被工具改动的文件）；
  被 `.gitignore`/exclude 排除的目录不参与回滚（这正是期望行为）；检查点被
  配额修剪后旧消息只支持"仅对话回退"。
