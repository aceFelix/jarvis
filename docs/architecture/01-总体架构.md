# 01 - 总体架构

## 一、系统定位

J.A.R.V.I.S. 是一个**本地优先、工具驱动、终端原生**的个人 AI Agent。它不是简单的 ChatBot，而是一个能操作电脑、常驻后台、能听会说的智能助手。

核心设计目标：
- **随叫随到**：daemon 常驻 + 全局热键 + 语音唤醒
- **能操作一切**：49 内置工具 + 71 CLI-Anything harness + MCP 外部工具 + 浏览器/GUI 自动化
- **能听会说**：双套语音系统（STT+TTS 管线 + 全双工实时语音）
- **安全可控**：五层权限系统，fail-closed 默认安全
- **可扩展**：Tool / Skill / Plugin / MCP / Hook 多层扩展点

## 二、技术栈

| 层次 | 技术 | 用途 |
|---|---|---|
| **语言** | Python 3.13+ | 主语言（也兼容 3.11+） |

| **终端 UI** | rich + prompt_toolkit | REPL 界面、Markdown 渲染、命令补全 |

| **GUI 自动化** | pyautogui + pygetwindow | 鼠标/键盘/截屏/窗口操作 |

## 三、运行环境

- Python 3.11+（最低 3.11），推荐 3.13
- pip 包管理器

### 平台支持

| 功能 | Windows | macOS | Linux |

| LLM Provider | ✅ | ✅ | ✅ |

| 实时双工 /talk | ✅ | ✅ | ✅ |

¹ macOS GUI 操作需授权：系统设置 → 隐私与安全性 → 辅助功能/屏幕录制
² Linux GUI 需 X11 环境（DISPLAY 环境变量），Wayland 下部分功能受限
³ Linux 不支持后台分离，以前台模式运行 daemon

> ⚠️ macOS 和 Linux 仅完成代码层适配，**未经过完整实机测试**。建议优先在 Windows 上使用。

### 平台系统依赖
- **Windows**：无额外依赖（WebView2 通常预装）
- **macOS**：`brew install portaudio` + 辅助功能/屏幕录制授权 + `pip install pynput`（热键）
- **Linux**：`portaudio19-dev` + `libgtk-3-dev` + `python3-tk`

### 动态平台适配

System Prompt 根据 `platform.system()` 动态生成对应平台的操作规范（Shell 路径规则、权限模型、特有命令），
避免向 macOS/Linux 用户发送 Windows 规则。详见 [prompts/system.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/prompts/system.py) 的 `_platform_section()`。

## 七、核心设计原则

### 1. 协议优先（Protocol over Implementation）
- [UIProtocol](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/core/context.py#L22-L38)：UI 层抽象，RichCLI 和 Webview 都实现它
- [LLMProvider](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/llm/base.py)：LLM 层抽象，五种 Provider（OpenAI/Anthropic/DashScope/Zai/Mock）都实现它
- [RealtimeTalkUI](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/core/context.py#L41-L77)：实时语音 UI 抽象，终端和窗口都实现它

**为什么这样设计**：解耦。QueryLoop 只依赖抽象协议，不关心是终端还是窗口，也不关心是 OpenAI 还是 Anthropic。这让新增 UI/Provider 变得简单。

### 2. fail-closed 安全
- [Tool 基类](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/core/tool.py#L30-L97) 的 `is_read_only` / `is_concurrency_safe` / `is_destructive` 默认全 False
- `check_permissions` 默认返回 ASK
- 权限校验合并规则：`DENY > ASK > ALLOW`（取更严格）

**为什么这样设计**：安全侧优先。新工具如果不显式声明安全，默认会被当作危险操作要求用户确认。

### 3. 流式优先
- LLM 响应是 `AsyncIterator[LLMEvent]` 流式
- TTS 支持流式播放（`StreamTTSPlayer`）
- STT 支持流式识别（WebSocket 实时）
- 实时双工语音是真正的全双工流式

**为什么这样设计**：低延迟体验。用户不需要等模型完整生成才看到输出。

### 4. 上下文自管理
- [LayeredContext](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/core/layered_context.py)：冻结前缀 + 滑动窗口，超阈值自动压缩合并，前缀稳定 → 缓存友好
- 反应式压缩：API 报 context too long → 自动压缩重试（冻结前缀不变）
- 图片驱逐、工具结果折叠（仅活跃窗口）、文件回灌

**为什么这样设计**：长对话不可避免，token 爆炸会撞模型上下文窗口。自动压缩让用户无感地持续对话。

### 5. 可扩展架构
- **Tool**：继承 `Tool` 基类，注册到 `ToolRegistry`
- **Skill**：放 `~/.jarvis/skills/<name>/SKILL.md`
- **Plugin**：`/plugin install` 命令管理
- **MCP**：配置 `~/.jarvis/mcp.json` 连接外部 server
- **Hook**：注册 `USER_PROMPT` / `TOOL_BEFORE` / `TOOL_AFTER` 等钩子

**为什么这样设计**：核心团队不可能覆盖所有场景。多层扩展点让社区能贡献能力。

### 6. 跨平台适配
- System Prompt 根据 `platform.system()` 动态注入平台操作规范
- 热键监听：Windows 用原生 RegisterHotKey，macOS 用 pynput，Linux 用 keyboard
- 沙箱执行：Windows 用 Job Object，macOS 用 sandbox-exec，Linux 用 setrlimit
- GUI 操作失败时自动附加平台权限配置指引

**为什么这样设计**：JARVIS 面向多平台用户，不能假设所有人都在 Windows 上。动态适配让每个平台获得原生体验。

## 八、为何选择这种架构

### Q: 为什么用 Python 而不是 Node.js/TypeScript（Claude Code 用 TS）？
- Python 生态在 AI/ML/语音/视觉领域更成熟（dashscope SDK、mediapipe、opencv）
- pyaudio/pystray/pyautogui 等系统操作库 Python 更齐全
- 性能瓶颈在 LLM API 调用（IO bound），Python 的 asyncio 足够

### Q: 为什么用 dataclass 而不是 pydantic？
- [message.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/core/message.py#L1-L5) 明确说明：内部数据结构不需要序列化校验开销
- pydantic 适合外部输入校验，内部传递用 dataclass 更轻量

### Q: 为什么用 multiprocessing 而不是 threading 做实时聊天窗口？
- pywebview 必须在主线程运行
- daemon 主线程已被托盘占用
- multiprocessing.spawn 启动子进程，子进程主线程跑 webview

### Q: 为什么有两套语音系统？
- `/voice`（STT+LLM+TTS）：逐轮对话，模型可选任意 LLM，适合复杂推理
- `/talk`（全双工 WebSocket）：边说边听，延迟极低，但绑定 DashScope 实时模型
- 两者适用场景不同，不能互相替代
