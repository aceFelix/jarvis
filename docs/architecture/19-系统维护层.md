## 一、解决什么问题

用户真正问的三件事，在 jarvis 里此前一件都答不上来：

| 症状 | 现实 | 本层对策 |
|---|---|---|
| 「C 盘红了，清一下」 | 没有任何工具能列出「哪些是可回收的垃圾」；`FileGuard` 的写前留底是**复制式**，GB 级垃圾复制一份等于先把盘占满 | 声明式规则库 + 隔离区（**移动**，同盘 rename 微秒级）+ `/clean --restore` 不覆盖还原 |
| 「电脑有没有病毒」 | 完全盲区。而直接查 `Get-MpComputerStatus` 会对装了第三方杀软的用户报「你没有实时防护」——**彻头彻尾的误报** | 以 `root/SecurityCenter2` 的 `productState` 位为**权威**判定，`Get-MpComputerStatus` 只作 Defender 自身状态的补充 |
| 「电脑最近好慢，是哪的问题」 | 只有 `daemon/monitor.py` 的阈值告警（CPU/内存/磁盘数字），没有人读得懂的一句话结论 | 七区块聚合体检 + 按实测阈值生成的建议清单 + Markdown 报告 |

三条**设计底线**（不写进代码就等于没有）：

1. **不自研查杀引擎**。Defender 已够用，多一个引擎多一份维护成本与误报来源。
2. **不自动杀进程**。进程只能报告，热点进程是不是"内存泄漏"取决于用户当时在干什么，机器判断不了。
3. **不碰白名单之外的任何文件**。清理目标全部来自 `cleaners.toml`，三道闸逐条校验，绝不接受运行时传入的任意路径。

## 三、清理链路

### 3.1 规则库：借 CleanerML 的形，不借它的规则

`agent/config/cleaners.toml` 用 [CleanerML](http://bleachbit.sourceforge.net/) 的字段风格（`id / name / kind / paths / include / protect / category / risk / requires_admin / desc`），但**规则一条都不抄**——那些规则是别的程序在别的年份按别的系统写的，抄过来等于把别人的误删风险也抄进来。

当前 19 条：7 条 `low` / 9 条 `medium` / 3 条 `high`；15 条 `paths` 型 + 4 条 `command` 型；8 条需要管理员。

**刻意不收录**的两个：

- `prefetch` —— 删了会让常用程序启动变慢，被无数"优化大师"当成垃圾是这类软件最经典的伤害。
- `node_modules` —— 那是工程目录，不是系统垃圾；删了别人的构建就废了。

### 3.2 三道解析闸（`rules.py`）

`parse_rule()` 对每条规则做硬校验，**不合法直接 `ValueError`，连进清单的机会都没有**：

| 闸 | 拦什么 | 为什么 |
|---|---|---|
| 必须绝对路径 | `%TEMP%\..\..\` 这类相对写法 | 相对路径的基准是"当前工作目录"，运行时不可预测 |
| 不许通配符 | `C:\Users\*` | 展开成几百个用户目录后，误删面积不可控 |
| 不许盘根 | `C:\`、`D:\` | 盘根永远不在"可回收垃圾"的定义里 |

命令型规则另过一道白名单：`ALLOWED_COMMAND_BINARIES = {dism.exe, vssadmin.exe, powercfg.exe, cleanmgr.exe}`。`clean_cmd` 是 `list[str]`，**不走 shell**——shell 一进来 `; rm -rf` 就能接上去。

白名单里 **`cleanmgr` 是唯一能删到用户文件的一个**：`/sageset` 的勾选项包含「下载」文件夹。它还能待在白名单里，是因为两点同时成立——必须先用 `/sageset` 走一遍 GUI 勾选（等于用户亲手审过范围），且命令型规则在本项目里**从不代执行**（见 3.5 的 `cleaner.clean` 拒绝表）。扩容这张表要同步改 `test_allowed_binaries_are_the_known_ones`——那里是精确等值断言，刻意不做成子集，就是逼人停下来想一遍。

`%VAR%` 手动展开：Python 的 `ntpath.expandvars` 只认 `$`，不认 `%LOCALAPPDATA%`，所以 `expand_path()` 自己实现，并特判 `%ALLDRIVES%`（按盘展开成多条）。

`desc` 字段是**必填**。这不是洁癖：`/disk` 的每一行都要告诉用户"删了会怎样"，没有 `desc` 的规则无法向用户交代，等于埋雷。

### 3.3 扫描的三道性能闸（`scanner.py`）

`os.scandir` 递归（比 `Path.rglob` 快一个量级，后者每个条目都要构造 `Path` 对象）。三个闸防止"清理工具把自己卡死"：

| 闸 | 默认 | 触发后的行为 |
|---|---|---|
| `_Deadline`（wall clock） | 120s | 停止累加，条目上标 `truncated`，报告里**如实写"已截断"**而不是假装扫完 |
| `max_bytes`（单条规则体积上限） | 50GB | 同上 |
| 不跟随符号链接 | 恒开 | 链接指向的可能是另一个盘甚至网络位置，跟进去等于扫出整个网络 |

还有 `file_budget`（默认 40 万文件）与 `min_size_mb` 报告阈值（默认 100MB）。

**权限错误不中断扫描**：`PermissionError` 记进 `protected_count`，报告里体现为"还有 N 项没权限读"，而不是静默跳过。

### 3.4 为什么用隔离区而不是快照

这是本层最关键的一条决策，直接推翻了直觉方案：

| 方案 | GB 级垃圾时的表现 | 结论 |
|---|---|---|
| `FileGuard` 写前留底（现有设施） | 复制 → 先占一份同等空间 → 磁盘更红 | 阈值只有 50MB，**不可用** |
| shadow git 检查点（W3 设施） | 同上，且 git 对二进制大文件本就低效 | 不可用 |
| **移动到隔离区** | 同盘 rename 是元数据操作，微秒级、不占新空间 | **采用** |

`~/.jarvis/quarantine/<batch_id>/`，`batch_id` 形如 `clean-20261031-142530`。同盘时 `shutil.move` 直接 rename；跨盘时降级为复制+删除（此时体积上限会提前挡下来）。

配套的三条纪律：

1. **只清目录内容、保留目录本身**。`%TEMP%` 这类目录消失后 Windows 不会自动重建，只会报一堆怪错。
2. **`manifest.json` 写临时文件再 `os.replace`**，避免"移到一半断电"留下半个清单。
3. **`RESTORE_COMMAND = "/clean --restore"`**——不能写 `/undo`。`/undo` 走 W3 账本的 `EffectRecord`，隔离区批次是另一套记录，写错等于让用户敲一条注定落空的命令。

### 3.5 执行期的拒绝对照表

`cleaner.clean()` 在这些情形下**一个文件都不动**：

| 情形 | 结果 |
|---|---|
| `ids` 为空 | `error`："必须显式指定规则 id，不接受全清" |
| 规则风险档高于 `auto_clean_max_risk` | 条目标"超过当前允许上限" |
| 命令型规则（不可还原） | 条目标"命令型规则不从这里执行，请手动运行 XXX" |
| 目标路径落在隔离区内部 | 直接拒——否则清完就撤不回来 |
| 命中 `protect` 模式 | 跳过并**记原因**（"命中保护规则"） |

最后一条值得单说：只报"成功释放 300MB"而不说"还有 300 个文件没删"，等于骗人。

### 3.6 `top_dirs`：PLAN 没写但必须有的能力

实测本机：C 盘 100GB 只剩 14.6GB（85.4% 占用），可回收垃圾加起来**只有 27MB**。

这说明用户问"清一下"时，真正想知道的是**"空间被谁占了"**，不是"垃圾有多少"。所以补了 `top_dirs(root, limit=15)`：对根目录下每个一级目录做体积排行，输出 `DirEntrySize(path, name, size_bytes, file_count, truncated)`。

`/disk --top [目录]` 触发。报告里明确分两段：上半是"可清理项"（会动的），下半是"体积排行"（只是看一眼，`/clean` 不会碰它们）。

**两个被真实对话踩出来的细节（2026-10-31）**：

- **`top_root` 不存在时不能静默返回空数组**。实测里模型把用户主目录猜成 `C:\Users\acefelix`（真机是中文用户名），拿到 `top_dirs: []` 后只能自己连跑 `ls` / `du` 反复试错——空数组看起来像"没有东西占空间"，是这里最贵的误导。现在返回 `top_error`，并直接写出该传什么（真实用户主目录）。目录存在但一个都没超过阈值时另给 `top_note`。
- **`trend_7d_gb` 的裸数字会被读反方向**。实测 `-1.58` 的真实含义是"可用空间变多"，模型却读成"7 天又少了 1.58 GB"，还据此催用户清理（"以 1.58GB 的速度减少"）。原因不是实现错，而是字段名没交代是"已用增"还是"可用减"。
  现在 `DriveInfo` 同时给 `trend_7d_text`（「近 7 天占用下降 1.58 GB（已用变少、可用变多）」），`/disk` 终端输出也改写成「近 7 天**已用** ↓1.58 GB」——把"已用"两个字写出来，只给箭头不够。

### 3.7 无人值守自动清理：许可不复用 `risk`

用户提的需求是「那些完全不影响系统和我日常工作的垃圾，可以让 jarvis 随时监控并随时清理」。
落地时最关键的一个决定是：**自动许可不能直接拿 `risk` 档做阀。**

#### 为什么 `risk=low` 不能当自动许可

`risk` 回答的是「删了会怎样」，而自动清理要回答的是「删了用户会不会发现」。两者不是一回事：

| 规则 | risk | 能自动清吗 | 为什么 |
|---|---|---|---|
| `recycle_bin` | low | ❌ | 用户刚删的文件就在里面，自动清等于替他做了「这些不要了」的决定 |
| `user_temp` | low | ❌ | 正在运行的程序可能正拿着 Temp 里的文件 |
| `thumbcache` | low | ❌ | 删了第一次浏览相册会卡一下——有感知，只是轻微 |
| `shader_cache` | low | ❌ | 同理，游戏首次启动慢几秒 |
| `crash_dumps` | low | ✅ | 只有拿转储去提 bug 时用得上，平时永远不会被察觉 |
| `wer_reports` | low | ✅ | 上报队列与缓存，已发送的报告不在里面 |
| `delivery_optimization` | low | ❌ | 需管理员，后台进程提不了权 |

所以自动许可是一个**独立字段 `auto_ok`**，默认 `false`，逐条人工评估后显式打开。
好处是 fail-closed：新加一条规则不会因为漏标风险档而被悄悄自动执行。

#### 两道反向闸（`rules.py` 直接作废违规规则）

1. **`kind=command` 不许 `auto_ok`**——DISM / vssadmin / powercfg / cleanmgr 都不可还原，
   隔离区那套救不了它们。允许就等于给「命令型从不代执行」这条承诺开个后门。
2. **`requires_admin` 不许 `auto_ok`**——后台进程提不了权，只会在日志里刷 `PermissionError`，
   用户既没看到清理发生了，也没看到它失败。

#### 三个触发点，任何一层生效就够

| 触发点 | 代码位置 | 覆盖场景 |
|---|---|---|
| 每日定时（04:30） | `daemon/auto_clean_schedule.py` 的 `register` | 桌面常驻（`ProactiveEngine`）与 REPL（`CliReminderHost`）都会注册 |
| 启动时机会清理 | 同模块 `run_on_startup_if_due` | 纯 CLI 是短会话，可能从没撞上 04:30 那一刻；距上次超 20 小时才跑 |
| 手动 | `/clean --auto` | 用户想立刻看效果时 |

三条都走同一个 `run_auto_clean()`，不存在「定时清的和手动清的不是一回事」这种分叉。

#### 两个阈值与静默策略

- **`auto_clean_min_mb`（默认 20）**：低于它不建批次。零感知垃圾常只有几 MB，
  天天建一个隔离区目录、写一份 manifest、再 7 天后删一遍，成本高于收益，
  还会把 `/clean --batches` 刷满噪音。
- **`auto_clean_notify_mb`（默认 200）**：低于它**完全静默**。天天报一句「我清了 3 MB」
  反而是在消耗用户的注意力——这正是自动清理要避免的。只有清出真东西才提示一句。
- **两件事都不做时写 DEBUG 日志而非 INFO**：跳过的理由留在日志里可查，但不刷终端。

#### 自动清掉的东西必须能还原

这一点不议价：自动清理走的就是 `cleaner.clean()`，隔离区、`protect` 名单、跨盘检测全部照旧。
单测里有一条专门钉它（`test_auto_cleaned_content_is_restorable`）——
它失效的话，「零感知清理」就变成了「零感知删除」，用户永远不会发现，也永远拿不回来。

#### 怎么查它到底清了什么、为什么不清某一条

```
/clean --auto-status     # 每条规则在/不在名单里的原因
/clean --auto            # 立即跑一次
/clean --batches         # 看历次批次（含自动清的）
```

## 四、查毒链路

### 4.1 实测驱动的核心发现

2026-10-31 在本机跑探针，两个数据源给出互相矛盾的画面：

```jsonc
// root/SecurityCenter2 —— 权威：系统注册了哪些杀软、各自开没开
[{"displayName":"电脑管家系统防护","productState":266240,  // 0x041000 → 启用位 = 1
  "pathToSignedProductExe":"D:\\Program Files (x86)\\QQPCMgr\\15.6.23169.211\\QQPCMgr.exe"},
 {"displayName":"Windows Defender","productState":393472, // 0x060100 → 启用位 = 0
  "pathToSignedProductExe":"windowsdefender://"}]

// Get-MpComputerStatus —— 只反映 Defender 自己，且被接管后照常返回全关闭态
{"AMServiceEnabled":false, "AntivirusEnabled":false,
 "RealTimeProtectionEnabled":false, "SignatureAge":65535, "SignatureVersion":null}
```

**只看第二个，就会对一个装了腾讯电脑管家的用户报「你没有实时防护」**。这就是本模块存在的全部理由。

### 4.2 `productState` 位解码

Windows Security Center 的公开编码（`defender.parse_product_state()`）：

| 位 | 含义 |
|---|---|
| `0x1000` | 启用中 |
| `0x10` | 特征库为最新 |

实测值验算：`266240 = 0x041000` → 启用、库过期；`393472 = 0x060100` → 未启用、库过期。非整数值一律返回 `(False, False)`，不做猜测。

年龄字段的溢出哨兵 `65535` / `4294967295` 映射为 `None`——把"从未扫描过"显示成"49 万天前"是假数据。

### 4.3 判定顺序（`security_status()`）

```
SecurityCenter2 读到产品列表？
├─ 有产品且任一 enabled → primary = 该产品
│    ├─ 是 Windows Defender → realtime 取 Get-MpComputerStatus
│    └─ 是第三方            → note = "由「XXX」接管实时防护，Defender 自身处于关闭态属正常"
└─ 全部未启用            → note = "当前没有实时防护，建议开启 Windows Defender"
SecurityCenter2 读不到 → 退回 Get-MpComputerStatus，并在 note 里写明降级
```

只有**所有产品都未启用**时才允许说"没有实时防护"。这条被单测钉死（`test_security_reports_no_protection_only_when_真没有`）。

### 4.4 扫描编排（异步，不阻塞对话）

`start_scan(kind, path, allow_full)`：

- `kind ∈ {quick, full, custom}`，`custom` 必须带 `path`，否则拒。
- **全盘默认拒绝**：`allow_full=False` 时直接返回 `"全盘扫描可能耗时数小时，需 [maintenance].allow_full_scan = true"`。要用户自己开，不是悄悄跑。
- 用 `Popen(..., CREATE_NEW_PROCESS_GROUP)` 后台起进程，任务状态写 `~/.jarvis/maintenance/scans/<id>.json`，`/health status [job_id]` 查进度。
- 特征库更新 `update_signatures()` 是同步的（`Update-MpSignature`，通常几十秒），单独入口。
- `recent_threats()` 读 `Get-MpThreatDetection`，状态码映射 0~6/102 → 中文。**读不到时返回原因而不是空列表**——空列表会被误读成"很安全"，所以 `err` 非空时命令层会额外加一句"不代表没有防护"。

## 五、性能诊断（体检聚合）

### 5.1 七区块一次取回

`health.collect()` 只调**一次** PowerShell（`_HEALTH_SCRIPT`），脚本内按区块 `try/catch`，任何一块失败不影响其它六块：

| 区块 | 数据源 | 非管理员可用 |
|---|---|---|
| `resource` | `Get-Counter`（CPU / 可用内存 / 磁盘队列 / 磁盘繁忙）+ `Win32_OperatingSystem`（开机时间） | ✅ |
| `disk` | `Get-PhysicalDisk`（型号 / 介质类型 / HealthStatus / 容量） | ✅ |
| `security` | 委托 `defender.security_status()` | ✅ |
| `processes` | `Get-Process` 按内存 Top 10 | ✅ |
| `startup` | `Win32_StartupCommand` + 自动服务数 + 登录触发计划任务数 | ✅ |
| `power` | `Win32_Battery`（电量 / 状态） | ✅ |
| `thermal` | `MSAcpi_ThermalZoneTemperature` | ❌ 拒绝访问 |

### 5.2 提权降级：如实标注，不假装有数据

本机实测（`isAdmin = false`）以下全部拒绝访问：

- `Get-StorageReliabilityCounter`（SMART 磨损）→ "无法从客户端中访问 CIM 资源"
- `MSAcpi_ThermalZoneTemperature`（温度）→ "拒绝访问"
- `vssadmin list shadowstorage`（卷影占用）→ "你没有正确的权限"
- `dism /AnalyzeComponentStore`（WinSxS 可回收量）→ 错误 740 需要提升权限
- 开机性能事件日志 → "尝试执行未经授权的操作"

处理方式统一为 `HealthSection(ok=False, need_admin=True, note="...需要以管理员身份运行才能读取")`。**不显示 0、不显示"--"、不吞掉这个区块**——用户看到"读不到，因为要管理员"才能自己决定要不要提权。

`psrun.classify_failure()` 用一组标记词（拒绝访问 / 未经授权 / 没有正确的权限 / 需要提升 / Access is denied / not authorized / requires elevation）把它们归到 `denied`，而不是笼统的 `error`。

### 5.3 建议清单（`_advise()`）

阈值全部来自实测而非拍脑袋：

| 条件 | 建议 |
|---|---|
| 系统盘可用 < 15% | 先 `/disk --top` 看空间被谁占，再考虑清理 |
| 可用内存 < 1GB | 列 Top 进程，让用户自己判断该关哪个 |
| 磁盘队列 ≥ 2 或繁忙 ≥ 90% | 磁盘是瓶颈（不是 CPU），机械盘尤其明显 |
| 开机时长 ≥ 168h | 找个空档重启一次，比任何花哨的优化工具都有效 |

## 六、工具与命令

### 6.1 三个工具（模型侧）

| 工具 | 只读 | 延迟加载 | 关键参数 |
|---|---|---|---|
| `DiskReport` | ✅ 恒只读 | 否 | `scope / min_size_mb / include_top / top_root / deep` |
| `DiskClean` | 无 `confirm` 时只读 | ✅ | `ids / confirm` |
| `SystemHealth` | `action ∈ {report, security, threats, scan_status, save}` | 否 | `action / scan_kind / out_file` |

两条容易写错的地方，单测逐条钉住：

1. **`DiskClean.is_irreversible()` 必须返回 `False`**。有隔离区可还原，挂上不可逆就等于每次清理白等 30 秒延时窗口（PLAN 4.6 的明确要求）。`is_destructive()` 仍返回 `True`（有 `confirm` 时），走账本。
2. **工具参数里不许出现 `path` / `file_path` / `target` 这类键**。`file_effects.extract_targets()` 命中 `_PATH_KEYS` 会给目标做**写前留底**——把 `%LOCALAPPDATA%\Temp` 整个复制一份，比清理本身还占空间。所以清理工具用的是 `ids` / `scope` / `top_root`。

### 6.2 三条命令（用户侧）

```
/disk                 # 可回收清单（低于阈值的项不列）
/disk --all           # 含小项
/disk --top [目录]    # 附带目录体积排行（回答"空间被谁占了"）
/disk --deep          # 附带命令型规则（WinSxS / 卷影 / 休眠 / 磁盘清理）
/disk <id> [id...]    # 只查这些规则

/clean <id> [...]           # 预览（不动文件）
/clean --yes <id> [...]     # 执行（移入隔离区）
/clean --batches            # 列出隔离区批次
/clean --restore <batch_id> # 从隔离区还原（不覆盖已存在的同名文件）

/health                  # 完整体检
/health --markdown       # Markdown 输出
/health --save [路径]    # 存 .md 报告
/health security         # 只看杀软与实时防护
/health threats          # 威胁检测记录
/health scan [quick|full|custom <路径>]
/health status [job_id]  # 扫描进度
```

全部 `await asyncio.to_thread(...)`——一次扫描 1~15 秒，同步跑会把终端卡住。

`system_commands.py` 用 `if TYPE_CHECKING: from agent.commands.router import CommandContext` + 字符串注解，避免 `router → handler → router` 的循环导入（与既有 handler 同口径）。

### 6.3 输出的排版细节

- `_escape()` 包一层 Rich 转义：`ui.info()` **不做** markup 转义（`warn()/error()` 做），而规则名称、进程名、路径都是外部动态文本，里头出现 `[` 就会把整行吃掉。
- `_pad()/_truncate()` 按**中文占 2 列**计算宽度，否则中英混排的表格必然错位。

## 七、权限姿态

| 工具 | 无副作用 | 有副作用 |
|---|---|---|
| `DiskReport` | `allow` | — |
| `DiskClean` | `allow`（预览） | `ask`（`confirm=true`） |
| `SystemHealth` 只读动作 | `allow` | — |
| `SystemHealth action=scan` | — | `ask` |
| `SystemHealth action=scan, kind=full` | — | **`deny`**（除非 `allow_full_scan = true`） |

`[maintenance].enabled = false` 时：`/disk` 与 `/health` **照常可用**（纯只读），只有 `/clean` 与 `DiskClean(confirm=true)` 报"清理未启用"。这个不对称是刻意的——默认关掉的是"会动文件"的能力，不是"能看一眼"的能力。

## 九、已知边界与不做的事

| 不做 | 理由 |
|---|---|
| 自研查杀引擎 / 接 ClamAV | Defender 已够，多一个引擎多一份维护成本与误报来源（PLAN 十.4） |
| 自动杀进程 | 热点进程是不是泄漏取决于用户当时在干什么，机器判断不了 |
| 自动提权（`Start-Process -Verb RunAs`） | 会弹 UAC，且提权后清理的授权链断了。当前策略：(a) 只报告 + 提示手动提权 |
| 清理 `WinSxS` / 卷影 / 休眠文件 / 磁盘清理 | 直接 `dism` / `vssadmin` / `powercfg` / `cleanmgr` 才能做，**不可还原**，不进 `/clean` 执行链路，只在 `--deep` 里给出命令让用户自己跑 |
| 全盘扫描默认开 | 可能跑几小时，必须用户显式开 `allow_full_scan` |
| 跨盘隔离区 | 跨盘 `move` 退化为复制+删除，GB 级时与"快照式留底"同样病态；体积闸会提前挡下 |
