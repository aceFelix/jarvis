# 06 - 语音系统

J.A.R.V.I.S 有两套独立的语音系统，各自适用不同场景。

## 一、两套系统对比

| 维度 | `/voice` 语音对话 | `/talk` 实时双工 |
|---|---|---|
| **技术路线** | STT → LLM → TTS 管线 | 全双工 WebSocket |
| **交互模式** | 逐轮对话（听→想→说） | 边说边听 |
| **延迟** | 较高（三段串行） | 极低（流式全双工） |
| **模型** | 任意 LLM + TTS + STT | 绑定 DashScope 实时模型 |
| **打断** | ESC 键/关键词 | 服务端 VAD 自动检测 |
| **复杂推理** | 支持（任意 LLM） | 受限（实时模型能力） |
| **UI** | 终端 | 终端 + 方舟反应炉窗口 |

**为什么有两套**：
- `/voice` 适合需要复杂推理的场景（任意 LLM）
- `/talk` 适合低延迟自然对话（全双工打断）
- 两者不能互相替代

### 回声消除 AEC（/talk）

[aec.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/voice/aec.py) 用 WebRTC AudioProcessor 消除扬声器回声：

- 近端麦克风（24kHz）与远端参考（扬声器）统一重采样到 **16kHz**
- 按 **10ms 帧**（160 samples = 320 bytes）送入 AudioProcessor
- 依赖：`pip install aec-audio-processing numpy`

**为什么需要 AEC**：实时对话中扬声器播放的 AI 语音会被麦克风拾取形成回声，AEC 让"边说边听"不炸麦。

### StreamTTSPlayer

## 四、STT 语音识别

[stt.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/voice/stt.py) 提供三种后端（`fun-asr-realtime` 与 paraformer 复用同一后端类）：

### 三后端对比

| 配置 model | 实际后端 | 协议 | VAD | 适用 |
|---|---|---|---|---|
| `qwen3-asr-*` | `QwenASR` | WebSocket 流式（OmniRealtimeConversation） | 服务端 | 高质量中英文混合 |
| `paraformer-*` | `ParaformerSTT` | WebSocket 流式（Recognition） | 客户端 RMS | 通用场景 |
| `fun-asr-realtime` | `ParaformerSTT` | WebSocket 流式（Recognition） | 客户端 RMS | 与 paraformer 同后端 |
| `fun-asr-flash-*` | `FunASRFlashSTT` | HTTP POST（WAV base64 文件上传） | 客户端 RMS | 非实时，/voice 体验差，不推荐 |

### 自动选择逻辑

根据 `settings.stt_model` 名称：
- `"qwen"` 开头 → QwenASR（OmniRealtimeConversation，服务端 VAD）
- `"paraformer"` 开头 → ParaformerSTT
- `"fun-asr-realtime"` → ParaformerSTT（同为 Recognition 实时识别后端）
- `"fun-asr"` 开头 → FunASRFlashSTT（HTTP POST WAV base64，非实时）
- 其他 → 默认 ParaformerSTT

### 客户端 VAD（RMS 静音检测）

```python
def listen(self, *, max_seconds, silence_seconds, silence_threshold, on_partial):
    # 录音循环
    while recording:
        data = stream.read(CHUNK)
        rms = calculate_rms(data)
        if rms < silence_threshold:
            silence_duration += CHUNK_SECONDS
            if silence_duration >= silence_seconds:
                break  # 静音结束
        else:
            silence_duration = 0
    # 发送音频到 STT 服务
```

### 配置

```toml
[stt]
model = "qwen3-asr-flash-realtime"  # 推荐：服务端 VAD，质量最高；也可用 paraformer-realtime-v2
max_seconds = 15            # 单次录音最长秒数
silence_seconds = 1.5       # 静音检测秒数
silence_threshold = 500     # 静音 RMS 阈值（仅 Paraformer 客户端 VAD 用）
```

## 五、/voice 闭环

[voice_loop.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/voice/voice_loop.py) 实现 **听 → 想 → 说** 循环：

```
🎤 聆听 → STT 识别 → LLM 思考回答 → TTS 朗读 → 🎤 聆听 → ...
```

### 单轮流程

```python
async def _voice_loop_round(ui, settings, loop, ctx, tts, stt):
    # 1. 听：STT 录音识别
    ui.info("🎤 聆听中...")
    result = stt.listen(
        max_seconds=settings.voice_max_seconds,
        silence_seconds=settings.stt_silence_seconds,
        silence_threshold=settings.stt_silence_threshold,
        on_partial=_on_partial,  # 实时显示识别中
    )

    # 2. 想：LLM 流式推理（复用 QueryLoop）
    stream_player = StreamTTSPlayer(api_key=_voice_api_key(settings), ...)
    stream_player.start()
    ctx.on_assistant_text = stream_player.feed  # LLM 每吐一句 → 送 TTS
    # 重置 abort_event，防止上一轮残留信号跳过本轮 LLM 调用
    ctx.abort_event = asyncio.Event()
    stats = await loop.run(user_text, ctx)

    # 3. 说：冲刷剩余缓冲 + 阻塞等播完（WS 断开自动降级整段播放）
    player_stats = stream_player.finish()
```

### 关键设计

- **复用 QueryLoop**：语音模式复用当前 REPL 的 QueryLoop 和 LLM（含工具调用）
- **流式 TTS**：`ctx.on_assistant_text` 回调把文本增量喂给 `StreamTTSPlayer`
- **思考隔离**：思考内容只显示终端面板，不进入 TTS
- **markdown 清洗**：在 [tts_text.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/voice/tts_text.py) 集中剥离代码块/markdown 符号/`<think>`/工具占位符标签；`stream_tts.py` 内置一份等价清洗，改动需保持同步
- **API Key 隔离**：`_voice_api_key(settings)`（在 voice_config.py）始终从 `DASHSCOPE_API_KEY` 环境变量取值，不受 LLM 模型切换影响（切到 DeepSeek 时 STT/TTS 仍用 DashScope Key）
- **待机双层检测**：① 关键词快速匹配——用户说"退下/拜拜/不聊了"等（`_EXIT_WORDS`）；② LLM 意图——回复末尾输出 `<standby/>` 标记。`_detect_standby(since_index=...)` 只检查本轮新增消息（防止旧会话残留误触发），且去掉标记后正文超过 30 字视为正常回答误触，不待机
- **残留清理**：退出语音模式时 `_clean_standby_messages()` 移除 goodbye 消息及其前一条 user 消息，避免下次语音会话误触发待机

### 打断机制

- **ESC 键**：`barge_in_key`（默认开）。[barge_in.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/voice/barge_in.py) 的 `_KeyBargeInWatcher` 用 `keyboard.is_pressed("esc")` 每 100ms 轮询（非全局钩子，免管理员权限），立即停止 TTS 播报；待机阶段按 ESC 退出语音模式
- **关键词打断**：`barge_in`（默认关）TTS 播报期间检测"闭嘴""等一下"等（`_INTERRUPT_WORDS`）
- **退出**：说"退下"（或任意结束意图）→ LLM 告别 → 进入待机，说"贾维斯"唤醒

### 配置

```toml
voice_max_seconds = 300.0     # 单轮最长录音（超时自动提交）
barge_in = false              # 关键词打断（默认关，避免与 TTS 的 PyAudio 并发崩溃）
barge_in_key = true           # ESC 键盘打断（默认开）
```

## 六、/talk 全双工实时语音

[realtime_talk.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/voice/realtime_talk.py) 基于 DashScope 实时语音 WebSocket：

### 架构

```
麦克风 ──→ _send_audio ──→ WebSocket ──→ DashScope 实时模型
                                    ↓
扬声器 ←── _recv_events ←── WebSocket ←── (VAD/理解/生成/TTS)
```

### 核心组件

```python
class RealtimeTalk:
    def __init__(self, api_key, model, voice, ws_url):
        self._api_key = api_key
        self._model = model          # qwen-audio-3.0-realtime-flash
        self._voice = voice          # longanqian
        self._ws_url = ws_url        # wss://dashscope.aliyuncs.com/api-ws/v1/realtime
```

### 连接建立

```python
async def run(self, ui: RealtimeTalkUI):
    url = f"{self._ws_url}?model={self._model}"
    headers = {"Authorization": f"Bearer {self._api_key}"}

    async with websockets.connect(url, additional_headers=headers) as ws:
        # 发送 session.update 配置
        await ws.send(json.dumps({
            "type": "session.update",
            "session": {
                "modalities": ["text", "audio"],
                "voice": self._voice,
                "turn_detection": {"type": "server_vad"}
            }
        }))

        # 并发运行三个协程
        await asyncio.gather(
            self._send_audio(ws, ui),    # 发送麦克风音频
            self._recv_events(ws, ui),   # 接收服务端事件
            self._esc_watcher(ui),       # ESC 退出监听
        )
```

### 三个协程

#### 1. `_send_audio` — 发送麦克风音频

```python
async def _send_audio(self, ws, ui):
    stream = pyaudio.open(format=PCM_16BIT, channels=1, rate=24000, input=True)
    while self._running:
        data = stream.read(CHUNK)
        # 计算音量通知 UI
        volume = calculate_rms(data) / MAX_RMS
        ui.on_volume(volume)
        # 发送音频块
        await ws.send(audio_append_event(data))
```

#### 2. `_recv_events` — 处理服务端事件

```python
async def _recv_events(self, ws, ui):
    async for message in ws:
        event = json.loads(message)
        t = event.get("type")

        if t == "speech_started":
            # 服务端 VAD 检测到人声 → 打断 AI
            ui.on_user_speaking(True)
            self._restart_speaker()  # 截断当前 AI 语音

        elif t == "response.audio.delta":
            # AI 语音增量
            audio_data = base64.decode(event["delta"])
            self._speaker.write(audio_data)
            ui.on_ai_speaking(True)

        elif t == "response.audio_transcript.done":
            # AI 转录完成
            ui.on_ai_transcript(event["transcript"])

        elif t == "conversation.item.input_audio_transcription.completed":
            # 用户转录完成
            ui.on_user_transcript(event["transcript"])
```

#### 3. `_esc_watcher` — ESC 退出

```python
async def _esc_watcher(self, ui):
    while self._running:
        if keyboard.is_pressed("esc"):
            self._running = False
            break
        await asyncio.sleep(0.1)
```

### 打断机制（VAD）

服务端 VAD 检测到人声 → 下发 `speech_started` 事件 → 客户端重启扬声器流截断当前 AI 语音。

**为什么用服务端 VAD**：
- 客户端 VAD 需要持续检测，延迟高
- 服务端 VAD 与模型理解一体，准确度高
- 真正的"说话即可打断"

> ⚠️ **barge_in_enabled 默认 False**：为防止 AI 语音被截断（用户偏好完整播报），
> 打断能力默认关闭，避免"没说完就被掐断"的体验问题。

### 实时工具调用（Function Calling）

`/talk` 支持实时工具调用：
- 工具集 = `ToolRegistry` 全部工具（排除 `AskUserTool`）
- 高风险的写操作（命令执行/文件删除/发邮件）由模型层指示**先语音确认**再执行
- 权限层 `check_permissions` 对 deny 级操作（如 `rm -rf /`）**直接拒绝**，不依赖模型判断
- 语音模式下强制开启思考（防止 TTS 朗读 reasoning_content）

## 八、PyAudio 音频处理

[audio.py](file:///e:/2.MyProjects/MyAgentChat/J.A.R.V.I.S/jarvis/agent/voice/audio.py)：

- **/talk 输入（麦克风）**：PCM 16-bit, 单声道, **16000 Hz**（`INPUT_RATE`）
- **/talk 输出（扬声器）**：**24000 Hz**（`OUTPUT_RATE`，DashScope 实时模型要求 24kHz）
- **/voice 录音**：统一 16kHz 单声道 16-bit PCM
- **PyAudio 全局单例**：Windows PortAudio 非线程安全，audio.py 用模块级单例统一管理，防 segfault
- **音量计算**：RMS（均方根）

## 九、两套系统资源冲突

- 两套系统共用麦克风硬件
- 同时开启可能导致 PyAudio 设备占用错误
- **建议**：一次只用一套

## 十、设计取舍

| 决策 | 选择 | 理由 |
|---|---|---|
| 两套语音系统 | 并存 | 适用场景不同 |
| /voice 复用 QueryLoop | 是 | 支持任意 LLM + 工具调用 |
| /talk 全双工 | WebSocket | 真正边说边听 |
| VAD | 服务端 | 准确度高，延迟低 |
| AEC | WebRTC AEC3（aec-audio-processing） | 消除扬声器回声，边听边说不炸麦 |
| TTS | 流式优先 | 低延迟体验 |
| STT | 三后端 | 不同场景不同选择 |
| 实时工具 | Function Calling + 语音确认 | 高风险操作先语音确认，deny 级直接拒绝 |
| 思考隔离 | 不进 TTS | 避免朗读思考过程 |
