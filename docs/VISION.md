# J.A.R.V.I.S 愿景文档

> **Just A Rather Very Intelligent System**
> 这不是一份产品需求文档，是一份给未来自己和贡献者的"造物宣言"。

---

## 北极星

**让每个人拥有一位真正懂你、主动打理、随叫随到的电脑管家。**

不是聊天框，不是语音助手，是电影里贾维斯那样——你还没开口，它已经把事情办了。

---

## 愿景陈述

想象一下 2027 年的一个普通工作日：

你坐到电脑前，按下热键唤醒 JARVIS。它开口说："先生，早上好。昨晚您睡得晚，今天前两小时我先把不急的通知压着了。您关注的两个 GitHub 仓库发了新版，我看了 release notes，有一个值得关注，摘要在我整理的早报里。9 点您有个会，相关文档我已经打开在第二个桌面。另外，磁盘空间剩 15% 了，我清理了 3GB 缓存，没动您的项目文件。"

你不需要问它任何问题。它**记得你**（知道你昨晚熬夜）、**懂你的习惯**（开会前自动备料）、**主动打理**（清了磁盘、压了通知）、**只在必要时打扰你**。

这是 JARVIS 要去的地方——**从"叫得动的执行者"变成"不用叫也懂你的管家"**。

## 定位与边界

### JARVIS 是什么

- **个人电脑的原生 AI 管家**：常驻操作系统，能看、能听、能说、能动手
- **多模态交互入口**：文字、语音、视觉，用户选最自然的方式
- **自主代理层**：不只是工具的集合，是能自己规划、执行、验证的 Agent
- **开放生态**：通过 MCP / Plugin / Skill 接入无限工具能力

### JARVIS 不是什么

- ❌ 不是云端 SaaS——数据和控制权在用户手里，跑在本地
- ❌ 不是聊天机器人——核心是"行动"不是"对话"，对话只是交互方式
- ❌ 不是编程工具——不只为写代码服务，为整个数字生活服务
- ❌ 不是万能的——它有边界，知道自己不能做什么，会说不

## 目标蓝图：真管家的六个维度

### 维度一：记忆——管家越用越懂你

> 没有记忆的助手每次都是陌生人，有记忆的管家才值得托付

- **情景记忆（Episodic）**：记住"昨天我帮你整理了哪份文档""上周你让我盯的那个 issue"
- **偏好记忆（Semantic）**：记住"您习惯文件按项目归类""您不喜欢早上 10 点前被打扰"
- **工作模式**：学习用户的作息、常用应用、文件组织习惯，主动适配
- **关系网络**：记住常用联系人、协作对象、项目干系人

**技术方向**：向量化 episodic store + 结构化 semantic store + 跨会话持久化，LLM 自动判断"这句话值得记吗"。

### 维度二：主动——不用叫也打理

> 管家和助手的区别：助手等你吩咐，管家自己看着办

- **监控→决策→执行闭环**：CPU 异常→判断→自动处理（不只是提醒）
- **事件驱动响应**：邮件到达、日程临近、文件变动→主动汇报或处理
- **信息流聚合**：RSS/邮件/日历/GitHub 多源信息→LLM 筛选→主动早报
- **情境化主动**：根据时间/地点/当前任务决定该不该打扰

**技术方向**：daemon 从"定时器"升级为"事件总线 + 规则引擎 + LLM 决策器"。

### 维度三：理解——从盲操到懂应用

> 能点坐标 (500,300) 是手，知道那是"发送"按钮才是脑

- **应用语义层**：每个高频应用一个 adapter（微信读消息、Outlook 读邮件、Excel 操作单元格）
- **UI 自动化**：从 pyautogui 盲坐标升级到 UI Automation API（Windows UIA），按语义元素操控
- **界面理解**：截屏 + 多模态 LLM 反向定位"这个按钮叫什么、点了会怎样"
- **应用状态感知**：知道"您现在在 IDE 里""您正在写邮件"

**技术方向**：`tools/app_integrations/` 应用适配层，优先覆盖微信、Outlook、Excel、浏览器。

### 维度四：维护——管家会打扫卫生

> 真管家不让屋子乱到需要大扫除

- **自动清理**：临时文件、缓存、回收站、下载目录归档
- **健康巡检**：磁盘空间、启动项、后台进程、网络连通性定期检查
- **更新管理**：软件版本追踪、系统更新提醒与执行
- **性能调优**：识别资源占用大户、给出优化建议或自动处理

**技术方向**：`tools/system/maintenance.py` 一组维护工具 + scheduler 定期执行。

### 维度五：跨端——管家无处不在

> 离开电脑，管家跟着你

- **剪贴板同步**：手机复制→电脑可粘贴
- **文件流转**：手机拍照→自动归档到电脑指定目录
- **通知接管**：手机通知→JARVIS 筛选→重要才打扰你
- **会话漫游**：电脑上的对话→手机继续，无缝衔接

**技术方向**：现有 bridge 升级为"设备协同层"，不只是会话同步。

### 维度六：安全——管家要值得托付

> 能动你电脑的 AI，必须是你最信任的

- **权限分级**：已有五层权限模式，持续完善
- **操作审计**：所有自主操作留痕，可回溯、可撤销
- **敏感数据保护**：密码、密钥、隐私文件不进 LLM 上下文
- **行为边界**：AI 知道自己不能做什么（删系统文件、转账、发敏感信息），会说不

## 核心设计原则

### 1. 本地优先，云端可选
数据和控制在用户手里。LLM 调用走云，但**记忆、文件、操作日志全在本地**。用户拥有完全的所有权和隐私。

### 2. 对话是手段，行动是目的
不追求"聊得自然"，追求"办得利落"。能一句话做完的，不用三句话解释。能静默做完的，不用问。

### 3. 主动但不越界
默认"建议而非执行"高风险操作。用得越久，信任等级越高，权限边界越宽——但永远保留"这件事先问我"的红线。

### 4. 越用越懂，而非每次重头开始
每一次交互都在积累对用户的理解。第一天的 JARVIS 和第一百天的 JARVIS 应该是两个不同的存在。

### 5. 开放生态，不造孤岛
通过 MCP / Plugin / Skill 接入一切。JARVIS 不试图内置所有能力，而是成为**调度一切能力的入口**。

### 6. 诚实地有限
JARVIS 不是万能的，它知道自己不能做什么。宁可说"这个我做不到"，也不瞎编。承认局限是信任的基础。

## 演进路线

### Phase 1：给管家装上记忆（✅ 2026.09 交付）

**目标**：从"每次初见"到"记得你" —— **已达成**

- [x] 画像记忆（实际实现：`agent/core/memory/profile_refiner.py` + `profile_store.py`，而非原计划的 `memory/profile.py`）
  - 会话结束后 LLM 异步提炼偏好/习惯/背景（默认 600 秒节流），存 `~/.jarvis/memory/profile.json`
  - 下次会话限额注入系统提示；每日维护，过时记忆自动衰减淡忘
  - 从交互中渐进式学习用户偏好，影响系统提示词生成（个性化 JARVIS 行为）✓
- [x] 长期记忆（实际实现：`MEMORY.md` 文本 + `profile.json` 结构化，而非原计划的向量化 episodic store）
  - 用户级 `~/.jarvis/MEMORY.md` + 项目级 `<workdir>/.jarvis/MEMORY.md`，启动注入系统提示
  - 会话存盘 / 崩溃恢复提示
  - 向量化情景记忆语义检索（"上周你让我盯的那个 issue"）未做——当前画像+文件方式已覆盖主场景，有真实需求再升级
- [x] 记忆查询工具
  - `/memory`（view / add / del / clear / refine / sync）+ 知识图谱 MCP 工具（`get_profile` / `search_entity`）
  - 知识图谱画像桥（`profile_bridge`）：启动经 MCP 拉取结构化画像注入，无需重新聊天

**成功标志**：✅ JARVIS 能在对话中自然引用过去的信息，不需要用户重新交代背景（README 效果展示"贾维斯你对我了解多少"即实测记录：身份/作息/偏好/项目/三层理解）。

### Phase 2：让管家主动起来（🔄 部分交付，当前阶段重点）

**目标**：从"提醒型"到"处理型"

- [x] 主动提醒闭环（2026.09 经 serve 宿主 `ProactiveHub` 交付，原计划的 `daemon/responder.py` 路径未采用）
  - 每日简报 08:30（错过补播窗口 2h 可配）、ScheduleReminder 定时提醒
  - 截止日期分级追踪（提前 7/3/1/0 天 + 逾期每天）、提醒升级（5→10→20 分钟，说"知道了"确认）
  - 待机 TTS 播报（"先生，提醒您："，对话/语音忙时跳过）、日历集成（Outlook/ICS 可选）
- [ ] 事件驱动 daemon：监控指标→规则引擎→LLM 决策→自动执行/征得同意（`monitor.py` 仍在休眠态，待重新接线）
- [ ] 信息流聚合：RSS/邮件/GitHub/日历多源订阅 → LLM 筛选 → 主动早报
- [ ] 情境化打扰控制：根据当前任务、时间、专注度决定该不该打断

**成功标志**：半达成——"打开就主动汇报"（简报/提醒）已实现；"监控异常自动处理"（处理型闭环）未到。

### Phase 3：让管家懂应用

**目标**：从"盲操键鼠"到"理解应用"

- [ ] 应用适配层 `tools/app_integrations/`
  - 优先：微信（读消息/发消息）、Outlook（读邮件/发邮件）、Excel（读写单元格）
  - 使用 UI Automation API 而非坐标点击
- [ ] 界面语义理解
  - 截屏 + 多模态 LLM 识别"这个控件是什么、点了会怎样"
  - 从"点击 (500,300)"升级到"点击'发送'按钮"
- [ ] 应用状态感知
  - 知道用户当前在哪个应用、在做什么

**成功标志**：用户说"把老板刚发的邮件摘要给我"，JARVIS 真的能去 Outlook 里读出来。

### Phase 4：让管家会打理

**目标**：从"只动不维护"到"主动保养"

- [ ] 系统维护工具集 `tools/system/maintenance.py`
  - 清理、归档、健康检查、更新管理
- [ ] 定期自动巡检
  - scheduler 驱动，LLM 生成"体检报告"
- [ ] 跨端协同升级
  - bridge 从会话同步升级为设备协同（剪贴板/文件/通知）

**成功标志**：用户不再需要手动"打扫电脑"，JARVIS 自动保持系统整洁。

## 成功标准

不是 KPI，是"什么时候我觉得它真的成了我的管家"：

1. **一周没主动开过 JARVIS 窗口**——因为它该做的都做了，我只在被服务时感知到它
2. **换一台电脑装上 JARVIS，导入记忆，它立刻"认识"我**——记忆可迁移
3. **它能说"先生，这件事上次您是这么处理的，要照旧吗"**——有连续性
4. **朋友看到我用电脑的方式，问"你这管家怎么弄的"**——体感到差异

## 非目标（明确不做什么）

- ❌ **不做云端托管版**：JARVIS 是个人的，数据在本地。云端只用来调 LLM。
- ❌ **不做手机 App**：JARVIS 扎根桌面操作系统，手机是协同端不是主端。
- ❌ **不做企业版/多用户**：它是"一个人的管家"，不是 SaaS。
- ❌ **不追求全自主**：永远保留人在回路，高风险操作必须确认。
- ❌ **不替代专业工具**：不自己做编辑器/浏览器/邮件客户端，而是操控已有的。
- ❌ **不支持所有 OS**：先做好 Windows，再考虑 macOS，Linux 不是优先级。
