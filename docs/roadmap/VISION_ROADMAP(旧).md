## ① 感知层 — 看到并理解屏幕上的一切

### 现状

| 能做到 | 做不到 |
|--------|--------|
| 全屏/区域截图 | 实时持续观察 |
| 多模态模型描述截图内容 | 对 UI 元素的精确识别和定位 |
| 窗口列表/激活 | 理解窗口内的具体内容 |
| 摄像头拍照 | 屏幕变化检测（弹窗、通知、加载完成） |

### 缺什么

| 能力 | 说明 | 为什么重要 |
|------|------|-----------|
| **实时屏幕理解** | 不用你说"看看屏幕"，它随时知道你在干什么 | 主动层的基础，没有它就谈不上主动 |
| **UI 元素识别** | 看到按钮/输入框/菜单/列表项，不是一堆像素 | 语义操控的前提——知道那儿有个"确定按钮"才能点它 |
| **OCR 文字提取** | 读取任何窗口里的文字（IDE、PPT、微信、PDF） | 很多程序的信息无法通过 API 获取，OCR 是兜底方案 |
| **应用状态感知** | 知道当前活跃窗口是什么、里面发生了什么操作 | 判断用户意图的关键输入 |
| **屏幕变化检测** | 注意到弹窗、错误提示、进度条完成等关键事件 | 主动干预的触发器 |
| **系统通知拦截** | 获取 Windows Toast / macOS 通知内容 | 低电量、邮件、日程、Slack 消息——都是重要上下文 |
| **音频环境感知** | 麦克风检测环境音量/会议状态 | 判断用户是否在开会/通话中，决定是否打扰 |

### 实现方案

**屏幕理解管线（低频 + 高频双通道）**：

```
低频通道（每 2~5 秒）：
  全屏截图 → 多模态模型（VLM）→ "用户在写代码，IDE=VSCode，文件=main.py"

高频通道（每 0.5 秒）：
  屏幕变化检测 → 变化区域 OCR（PaddleOCR）→ 提取新出现的文字 → 匹配事件规则
```

**技术栈**：

| 技术 | 用途 | 依赖 |
|------|------|------|
| VLM（Qwen-VL / Claude Vision） | 低频全屏理解，语义描述 | 已有 |
| PaddleOCR | 屏幕上所有文字的实时提取 | `pip install paddleocr`（已有） |
| OmniParser（微软） | UI 元素检测——按钮、输入框、图标 | 需新集成 |
| UIAutomation | Windows UI 元素树获取 | `pip install uiautomation`（已有 pywinauto） |
| watchdog | 文件系统变更监听 | `pip install watchdog` |
| Windows Toast API | 系统通知拦截 | 需新集成 |

**核心设计原则**：不需要全屏全帧分析。设计一个**注意力聚焦机制**——只在关键区域（活跃窗口、弹窗、右下角通知区域）保持高频关注，其他地方低频扫描。

## ② 操控层 — 操作任何程序，不只是浏览器

### 现状

| 能做到 | 做不到 |
|--------|--------|
| 浏览器自动化（Playwright，导航/点击/输入/截图） | Excel/Word/PPT 的内容级操作 |
| 鼠标点击/移动/滚轮（坐标级） | 对 UI 元素的**语义操作**（"点确定按钮"而非"点 (540, 320)"） |
| 键盘输入/组合键 | 文件对话框导航、右键菜单操作 |
| 窗口切换/关闭/移动 | 拖拽文件、应用间数据传递 |
| 剪贴板文本输入 | 非标准控件（WPF/UWP 自绘控件）的交互 |

### 缺什么

| 能力 | 说明 | 为什么重要 |
|------|------|-----------|
| **Accessibility API 语义操控** | 直接操作 UI 元素树（Button/TextBox/Menu），不依赖坐标 | 对任何标准 Win/mac 应用通用，精度 100%，不受分辨率/缩放影响 |
| **应用专精：Office 套件** | Excel/Word/PPT 的内容级读写、格式操作、图表生成 | 打工人最常用的工具，需要理解并生成内容 |
| **应用专精：文件管理器** | 文件浏览/选择/拖拽/压缩/解压 | 日常高频操作 |
| **应用专精：终端** | 附加到已有的终端会话，读写其内容 | 开发者的核心工作环境 |
| **多应用协作编排** | "把网页数据复制到 Excel，做图表，贴到 PPT" | 跨应用流程是实际工作的常态 |
| **自适应等待与重试** | 操作结果不确定——弹窗出来了吗？加载完了吗？ | UI 操作的本质不确定性，需要观察反馈并适应 |
| **键盘快捷键知识库** | 每个常用软件的快捷键映射 | 快捷键比鼠标快 10 倍，是高效操控的关键 |
| **剪贴板智能管理** | 多步复制粘贴、格式保持、内容暂存 | 跨应用数据传递的枢纽 |

### 实现方案

**三层操控体系**：

```
Layer 1 ▸ 语义操控（首选）
  UIA / Accessibility API → "点击确定按钮"
  → 找到 Button[name="确定"] → 调用 Invoke()
  精度 100%，不受窗口位置/分辨率影响

Layer 2 ▸ 坐标操控（降级，Layer 1 不可用时）
  截图 → VLM 定位元素坐标 → 鼠标移动到 (x, y) → 点击
  精度取决于 VLM，约 90%

Layer 3 ▸ 键盘操控（精确快速）
  快捷键序列 → Ctrl+S, Alt+Tab, Tab Tab Enter
  无视觉依赖，100% 可靠
```

**关键实现**：

```python
# 不是在屏幕上猜坐标
# 而是直接找到 UI 元素并操作

import uiautomation

window = uiautomation.WindowControl(Name="设置")
button = window.ButtonControl(Name="确定")
button.Click()

# Office 不走 GUI 模拟，直接操作文件格式
# Excel:  openpyxl → 读/写/格式化/图表
# Word:   python-docx → 读/写/样式/表格
# PPT:    python-pptx → 读/写/布局/动画
```

**Agent 工具的封装思路**：

| 工具 | 说明 |
|------|------|
| `WindowGetTree` | 获取窗口的 UI 元素树（JSON） |
| `ElementFind` | 按 name/type/text 查找元素 |
| `ElementClick` | 语义点击（不依赖坐标） |
| `ElementType` | 向元素输入文本 |
| `ElementGetText` | 获取元素的文本内容 |
| `ElementScroll` | 滚动列表/页面 |
| `ExcelRead/Write/Chart` | Excel 内容级操作 |
| `WordRead/Write` | Word 内容级操作 |
| `PPTRead/Write` | PPT 内容级操作 |
| `ClipboardGet/Set` | 剪贴板管理 |

### 操控层工具拓展更详细的方案

#### UIAutomation 深度集成

**Windows UIAutomation** 是操控层最关键的突破点。它是 Windows 内置的无障碍框架，几乎所有标准应用都暴露了 UI 元素树。

```python
# 示例：不用坐标，用语义找到并点击"保存"按钮
window = uiautomation.WindowControl(searchDepth=1, ClassName="Notepad")
save_button = window.ButtonControl(Name="保存")
save_button.Click()

# 示例：读取 VS Code 编辑器内容
editor = uiautomation.Control(AutomationId="editor")
text = editor.GetTextPattern().DocumentRange.GetText()
```

**封装思路**：

1. **元素搜索策略**：`Name` > `AutomationId` > `ClassName` > `ControlType`，逐级降级
2. **等待机制**：`等待元素出现（超时 5s）→ 等待元素可用（超时 3s）→ 操作 → 等待结果确认`
3. **中文适配**：中文软件的按钮名/菜单名直接用中文搜索
4. **自定义控件**：WPF/UWP/Electron 自绘控件，降级到坐标操控

#### Office 套件内容级操控

**不走 GUI 模拟，直接操作文件格式**：

| 应用 | Python 库 | 能力 |
|------|----------|------|
| Excel | `openpyxl` | 读写单元格、公式、图表、数据透视表、条件格式 |
| Excel (xlsx 超大文件) | `polars` / `pandas` | 数据分析、筛选、聚合 |
| Word | `python-docx` | 读写段落、表格、样式、图片、页眉页脚 |
| PowerPoint | `python-pptx` | 读写幻灯片、文本框、图表、形状、动画 |
| PDF | `PyPDF2` / `pdfplumber` | 读取、合并、拆分、提取表格 |
| Outlook | `win32com` | 读取/发送邮件、管理日历、操作联系人 |

## ③ 主动层 — 不叫就不动，不配叫助手

### 现状

| 能做到 | 做不到 |
|--------|--------|
| 资源告警（CPU>85%/内存>90%/磁盘<10%） | 理解用户行为意图 |
| 定时提醒（一次性/每天/每周） | 主动发现用户遇到困难 |
| 节假日通知 | 在合适的时机说合适的话 |
| | 追踪长期任务进度 |
| | 预防错误（危险命令/错误操作） |

### 缺什么

| 能力 | 场景示例 |
|------|---------|
| **意图推测** | 你在 VSCode 里打开一个文件反复修改 20 分钟没保存 → "先生，需要帮忙吗？" |
| **错误预防** | 你敲了 `rm -rf /usr/...` → "先生，这会删系统目录，确认吗？" |
| **时机感知** | 连续工作 2 小时 → "该起来喝杯水了" |
| **任务追踪** | 3 天前你说要做 X，现在看起来你忘了 → "上周二您说要给这个函数加异常处理" |
| **环境感知** | 弹出低电量通知 → "电脑快没电了，要保存工作吗？" |
| **礼貌的沉默** | 全屏看视频 → 不打扰；发呆 → 可以搭话 |
| **会议感知** | 检测到你在 Zoom/Teams 通话 → 静音模式 |
| **文档校对** | 你在写文档/邮件时主动发现错别字或不妥的表达 |
| **网络安全** | 你正在访问一个可疑的钓鱼网站 → "先生，这个页面看起来有问题" |

### 实现方案

#### A. 输入侧 — 持续但不打扰的观察

守护进程后台常驻，维持一个**环境状态快照**，持续刷新：

```
环境状态快照（每 0.5~5 秒按需刷新）：
├── 屏幕变化检测   → 变化区域列表
├── 活跃窗口追踪   → 当前应用 + 标题栏文字
├── 键盘/鼠标活跃度 → cps / 鼠标移动频率
├── 系统通知拦截   → Windows Toast 内容
├── 音频环境       → 麦克风信号判断是否在通话
└── 文件变更监听   → watchdog 监听工作目录
```

#### B. 大脑侧 — 干预判断引擎

一个轻量级**决策循环**（不依赖于大 LLM），持续评估 3 个问题：

```
1. 用户有遇到困难吗？
   - 检测信号：同一文件反复修改 N 次 / 错误弹窗 / 长时间卡在同一页面
   - 判断方式：规则引擎 + 小模型（BERT 分类）

2. 有什么重要信息用户不知道吗？
   - 检测信号：系统告警 / 日程到点 / 任务超时 / 异常事件
   - 判断方式：事件驱动 + 优先级队列

3. 现在是说话的时机吗？
   - 检测信号：全屏应用 / 通话中 / 正在打字 / 鼠标高频移动
   - 判断方式：启发式规则（键盘 cps > 3 持续 5s = 正在打字）
```

```python
# 干预决策循环（伪代码）
# 运行在守护进程的后台线程中

class InterventionEngine:
    def __init__(self):
        self.screen_watcher = ScreenChangeDetector()    # 屏幕变化检测
        self.window_tracker = ActiveWindowTracker()     # 活跃窗口追踪
        self.activity_monitor = UserActivityMonitor()   # 键盘/鼠标活跃度
        self.notification_hook = SystemNotificationHook() # 系统通知拦截
        self.file_watcher = FileChangeWatcher()         # 文件变更监听
        self.task_tracker = TaskTracker()               # 任务追踪
        self.attention_model = AttentionModel()         # 干预时机模型

    async def run(self):
        while True:
            state = await self.observe()           # 感知环境
            context = self.assemble(state)         # 拼合上下文
            intent = self.infer_intent(state)      # 推断用户意图
            risks = self.assess_risks(context)     # 评估风险/机会
            worth_it, level = self.should_speak(risks, intent)  # 值得打扰吗？

            if worth_it:
                await self.deliver(level, risks)   # 分层递进提醒

            await asyncio.sleep(self.adaptive_interval(state))
            # 忙时少观察（5s），闲时多观察（1s）
```

#### C. 输出侧 — 分层递进的干预方式

```
Layer 1 ▸ 托盘图标变色/闪烁
  "有信息，但不急"
  场景：日程提醒、常规通知

Layer 2 ▸ 右下角 Toast 通知
  "先生，已经下午 3 点了"
  场景：定时提醒、状态小结

Layer 3 ▸ 语音插入（短句，自然打断）
  "先生，您在第 42 行有个未处理的异常"
  场景：工作纠错、危险警告

Layer 4 ▸ 弹出对话框（强干预）
  确认后才关闭
  场景：高危操作拦截、关键决策
```

#### D. 具体场景的干预规则

```
┌────────────────────┬──────────────────────┬──────────────┐
│ 检测到的事件        │ 干预内容              │ 干预层级      │
├────────────────────┼──────────────────────┼──────────────┤
│ 同一文件反复修改 >15min│ "需要帮忙看看吗？"    │ Toast / 语音  │
│ 错误弹窗出现        │ 截图 + 分析 + 建议     │ 语音          │
│ 危险终端命令        │ 警告 + 确认           │ 强干预弹窗    │
│ 连续工作 >2 小时    │ "该起来喝水了"         │ Toast         │
│ 低电量 <15%         │ "电脑快没电了"         │ 语音          │
│ 进入全屏应用        │ 自动切换到静音模式     │ 无提示        │
│ 检测到 Zoom/Teams   │ 静音模式              │ 无提示        │
│ 浏览器访问钓鱼网站  │ "先生，页面可疑"       │ 强干预弹窗    │
│ 文档中出现明显错别字│ "考虑改为 XXX"         │ Toast         │
│ 忘了之前说的任务    │ "您在上周三提到..."    │ Toast / 语音  │
└────────────────────┴──────────────────────┴──────────────┘
```

## ④ 人格层 — 像人，不像客服

### 现状

| 能做到 | 做不到 |
|--------|--------|
| 静态系统提示定义人格 | 从交互中自动学习 |
| "先生"称呼 + 英式管家口吻 | 根据用户情绪调整说话风格 |
| 一次性自我介绍 | 跨会话的连续感和关系演化 |

### 缺什么

| 能力 | 说明 | 为什么重要 |
|------|------|-----------|
| **自动记忆提取** | 对话后自动提取"值得记住的事"，存为结构化记忆 | 人格层的根基——没有记忆，其他都是空中楼阁 |
| **情绪感知** | 从语气/用词/语速判断你是赶工/摸鱼/烦躁/开心 | 决定回应的方式和时机 |
| **风格适应** | 工作时简洁专业，闲聊时幽默放松 | 一种风格无法适应所有场景 |
| **长期关系演化** | 第 1 天和第 100 天的了解完全不同 | 这才是"陪伴"的本质 |
| **跨会话连续感** | "上次我们说到..."——不是每次都从零开始 | 打断后回来，它知道刚才的话题 |
| **主动分享** | 不只是回答问题，会分享趣事和观察 | "先生，今天是你用 Jarvis 第 100 天" |
| **犯错与道歉** | 操作失败时自然承认，不是冷冰冰的报错 | 人都会犯错，助手也是 |
| **有观点** | 问它"你觉得这个方案怎么样"，它能给出有立场的意见 | 不是"两种方案各有优劣"的废话 |

### 实现方案

#### A. 自动记忆提取系统

每次对话结束后，用一次轻量 LLM 调用提取"值得记住的事"，存入结构化数据库：

```
输入：本轮对话记录
输出：结构化记忆卡

类型 = fact（事实）/ preference（偏好）/ task（任务）/ relationship（关系）/ milestone（里程碑）

示例：
"我叫张三，住在北京"    → {type: fact, key: user.name, value: "张三"}
"我不喜欢 React"         → {type: preference, key: tech.react, value: "dislike"}
"下周五要交报告"          → {type: task, key: deadline.report, date: "2026-07-24"}
"最近在减肥"              → {type: fact, key: user.current_goal, value: "减肥", expires: "30d"}
"我老婆叫李梅"            → {type: relationship, key: spouse, value: "李梅"}
"今天是我用 Jarvis 第 1 天" → {type: milestone, key: first_day, date: "2026-07-12"}
```

**存储方案**：**SQLite**（不是 Markdown 文件），支持：
- 增删改查（用户可修改/删除记忆）
- TTL 过期（减肥目标这种临时记忆 30 天后自动降权）
- 模糊搜索（对话中检索相关记忆）
- 置信度标记（"我猜你不喜欢 React" vs "你明确说过不喜欢 React"）

**记忆注入**：每次 LLM 调用的系统提示中加入 Top-K 最相关的记忆：

```
当前相关记忆：
- 你叫张三，住在北京
- 你不喜欢 React 框架
- 你老婆叫李梅
- 你最近在减肥（1 周前开始）
- 下周五要交项目报告
```

#### B. 情绪感知模型

三通道融合判断：

```
通道 1：文本情绪分析
  短句 + 重复词 → 不耐烦 → 助手闭嘴，简洁
  长句 + 问号 → 探索 → 助手详细回答
  感叹号多 → 兴奋/激动 → 助手可以更活泼

通道 2：语音特征（STT 时可用）
  语速快 + 音量大 → 紧张/焦虑
  语速慢 + 音调低 → 疲惫/沮丧
  语速正常 + 平稳 → 正常

通道 3：行为模式
  连续打字 30 分钟 → 专注 → 不打扰
  来回切换窗口 → 烦躁/找东西 → 可问"需要帮忙吗"
  鼠标无目的移动 → 发呆/放松 → 可主动搭话
```

**情绪状态机**：

```
用户状态      →  助手模式
─────────────────────────────
专注工作      →  静默（除非紧急事件）
遇到困难      →  简洁建议，不多废话
闲聊时间      →  幽默放松，可主动延伸话题
赶 deadline   →  只回答，不闲聊，说完闭嘴
烦躁/焦虑     →  安抚语气，简短确认，不追问
兴奋/开心     →  可以更活泼，一起高兴
```

## 操控层工具拓展（补充）

> 此部分为操控层工具的具体扩展方案。

### UIAutomation 深度集成

**Windows UIAutomation** 是操控层最关键的突破点。它是 Windows 内置的无障碍框架，几乎所有标准应用都暴露了 UI 元素树。

```python
# 示例：不用坐标，用语义找到并点击"保存"按钮
window = uiautomation.WindowControl(searchDepth=1, ClassName="Notepad")
save_button = window.ButtonControl(Name="保存")
save_button.Click()

# 示例：读取 VS Code 编辑器内容
editor = uiautomation.Control(AutomationId="editor")
text = editor.GetTextPattern().DocumentRange.GetText()
```

**封装思路**：

1. **元素搜索策略**：`Name` > `AutomationId` > `ClassName` > `ControlType`，逐级降级
2. **等待机制**：`等待元素出现（超时 5s）→ 等待元素可用（超时 3s）→ 操作 → 等待结果确认`
3. **中文适配**：中文软件的按钮名/菜单名直接用中文搜索
4. **自定义控件**：WPF/UWP/Electron 自绘控件，降级到坐标操控

### Office 套件内容级操控

**不走 GUI 模拟，直接操作文件格式**：

| 应用 | Python 库 | 能力 |
|------|----------|------|
| Excel | `openpyxl` | 读写单元格、公式、图表、数据透视表、条件格式 |
| Excel (xlsx 超大文件) | `polars` / `pandas` | 数据分析、筛选、聚合 |
| Word | `python-docx` | 读写段落、表格、样式、图片、页眉页脚 |
| PowerPoint | `python-pptx` | 读写幻灯片、文本框、图表、形状、动画 |

# Excel 工具
class ExcelRead(BaseTool):
    """读取 Excel 文件的内容。返回指定 Sheet 的数据（前 N 行）"""

    args = {
        "file_path": "路径",
        "sheet": "Sheet 名",
        "chart_type": "bar/line/pie/scatter",
        "data_range": "数据范围",

    }
